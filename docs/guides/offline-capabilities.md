# ReadMD 能力包与内置依赖

更新：2026-10-11。本文描述 V0.0.5 开发实现；主程序尚未正式发布。本次已发布的是独立能力包，不会替换现有软件。

## 使用时安装

打开 PDF 编辑、选择学术 PDF 排版或执行图片 OCR 时，如果对应引擎缺失，当前功能直接显示安装窗口。窗口列出用途、下载量、安装后大小、版本和许可证。点击“安装并继续”后，ReadMD 从自己的能力仓库下载、验证完整包及每个文件，并实际运行引擎探测；成功后继续刚才的操作，无需前往插件面板重新寻找入口。

编辑预览菜单中的真实分页也复用同一入口。缺少 Typst 时直接安装并回到页面；若页面栅格不可用，会继续提示安装对应渲染引擎。Windows 已实测取消、真实在线下载安装、页面编辑及保存重启；其他平台和全部缺包组合仍分别验收。

下载支持进度、取消和失败重试。网络不可用时，可以在同一窗口导入 `.readmd-pack`，安装后继续。用户取消不改变当前文件；切换文件期间的过期导出不能覆盖新文档。安装开始提交后等待其实际结果，不能把已经提交的安装误报为取消。

插件面板仍提供已安装状态、离线导入、修复和卸载。通用导入会识别包类型；某个功能的安装窗口只接受该功能的包，避免装错。引擎和模型集中存入当前 ReadMD 配置目录，不进入文档目录。安装、打开与预览不会创建 `readmd-assets/`。

## 当前可用包

引擎目前仅 Windows x64 已准备并实测；字体是通用资源包。其他平台没有对应引擎锁定包时明确提示不可用，不能拿 Windows 引擎包试装；通用字体包也不能代替其他平台原生验收。

| 能力包 | 用途 | 下载 | 安装后 | 版本 |
| --- | --- | ---: | ---: | --- |
| PDFium | PDF 页面对象渲染、文字/图片/批注和页面操作 | 17.3 MiB | 13.0 MiB | 7881 |
| Typst | 真实分页学术 PDF、双栏、矢量公式和科研图表 | 29.9 MiB | 50.1 MiB | 0.15.1 |
| OCR | 本地印刷文字识别，包含简中、繁中、英文模型 | 9.4 MiB | 12.7 MiB | 5.5.3-r1 |
| 中文出版字体 | PDF 的常规/粗体、黑体/宋体风格字形；私有字体，不安装到系统 | 38.1 MiB | 48.5 MiB | 2026.10.10 |

小型 STIX Two Math 数学字体随 Rust 核心提供，约 1.45 MiB，不要求用户电脑已有 Cambria Math 或 Office。中文字体缺失时，真实分页入口直接提示安装；导出预览提供当前操作内的安装按钮，保存 PDF 前同样检查。取消、损坏或卸载不能覆盖已有文件，字体状态改变后不能复用不匹配的旧页面缓存。

Typst 关闭系统字体扫描，使用自己的随附字体及已验证的 ReadMD 字体；原生 PDF 嵌入实际使用的字形子集。Office 平台字体在 PDF 中以公开随包字体替代并提示，DOCX 仍保留原请求的字体名称。中文字体包不等于所有 Unicode 字符、所有 UI 语言或手写字体都已覆盖；任意缺字的精确定位和完整替代目录仍在第三批验收中。

扫描 PDF 识别还需要 PDFium；遇到缺失时同样在原操作内提示安装。OCR 不依赖 Office、Windows OCR 语言包、Python 或系统安装的 Tesseract。它不等于手写识别或所有语言的准确率保证。

下载位置：[tool-ReadMD 能力包发布](https://github.com/Natsummerance/tool-ReadMD/releases/tag/packs-2026-10-10)。最终大小和摘要以随软件提供的 `assets/capabilities/catalog.json` 为准；目录及逐文件锁在主程序版本中固定，不随远端描述静默变化。

## 安装软件时预选

Windows 安装程序增加组件页：核心必装；OCR 推荐预选但可取消；PDFium、Typst 和中文出版字体可选。每项显示下载量、安装后空间和功能说明。所选组件调用同一安装服务，不运行外部包脚本。下载失败保留基础软件，之后可在功能入口重试或导入离线包。

这是联网预装入口；基础安装包不内嵌四个大型能力包。离线部署需要同时带上对应 `.readmd-pack`。安装器已经以真实程序及资源编译验证，未在用户当前安装目录执行覆盖安装；实际安装向导及完整升级/卸载仍须最终发布验收。

## 核心与重型依赖边界

必要的阅读、编辑、保存、格式编解码及启动运行库属于软件本体，不要求用户配置 PATH、安装 Office 或手动寻找环境。平台界面宿主也是启动前提，最终安装包须负责完整离线交付，不能把启动失败推给用户安装浏览器或系统开发包；这部分尚在平台交付验收中。

重型能力按功能进入点安装，插件面板只是管理入口。后续 TeX、媒体及其他引擎沿用同一目录、体积说明、安装继续、离线导入、实际探测、修复和卸载契约。没有审查及实测的资源保持待准备，不能仅因电脑 PATH 上碰巧存在某个工具就宣称能力已独立交付。

| 类别 | 当前行为 | 尚未完成 |
| --- | --- | --- |
| Markdown、基础 Word/EPUB/PDF、文献和常见图片解码 | Rust 内核直接处理，不需要安装 Office、WPS、Python 或 Node | 完整格式和跨应用往返矩阵继续验收 |
| 桌面 Vega/Vega-Lite 科研图 | 软件内置脚本及 CSP 安全解释器，导出使用源码绑定快照 | 无界面的 MCP Vega 渲染仍需去除系统 Node 依赖 |
| Windows 小型 VC 运行库 | 两个 DLL 随核心打包，共 228,728 字节；主进程和子进程实际从软件目录加载 | 其他平台原生包及完整无预装环境验收 |
| PDF 原位编辑、学术排版、OCR | 上述独立管理包，真实探测后才报就绪 | 完整升级/回退矩阵、非 Windows 引擎包及其他文字体系字体 |
| 语音与传统 TeX | TeX 正式导出、预览及 MCP 共用受管理资源租约和 Windows OS 隔离编译；不再搜索宿主 PATH | FFmpeg/whisper.cpp；TeX 对应源码、许可证及公开能力包仍未完成，不能将本地 QA 包当成正式交付；非 Windows TeX 隔离尚未验收 |
| 代码块运行环境 | 仍有 Node、Python、R、Go、Rust、C/C++ 的宿主解释器／编译器查找；打开文档不会自动执行代码 | 必须另交付受管理的语言运行包、依赖说明和当前操作内安装；现有宿主路径不能计入“软件自带”验收 |
| 其他宿主组件 | 当前仍有平台要求 | Windows WebView2、Linux GTK/WebKit、PlantUML Java 和其他文字体系字体交付待解决 |

WPS、Word、LibreOffice 等用于检查输出的兼容性；某台测试机无法启动 Word，是互操作验收缺口，不是 ReadMD 生成 DOCX 必须依赖 Word。不可把所有宿主依赖都已消除作为当前宣传。

Word 预览同样不依赖 Office 或 TeX，也不会继承 PDF 页上次选用的外部引擎。有 Typst 时自动改善共享投影，安装变化会刷新预览缓存；界面保留实际引擎说明，不能据此宣称 Word 原生分页一致。分栏、页码、脚注等能力见[共享出版版式](publication-layout.md)。

## 维护与离线构建

- 主程序中的能力目录决定可信仓库、平台、版本、长度及 SHA-256，随后逐文件校验并执行最小真实操作；不接受任意下载地址或执行安装脚本。
- 下载复用应用代理策略，失败只报告本地化错误，不记录含凭据地址。完全阻断 GitHub 时使用离线包，不保证任何网络都能联网下载。
- OCR 从锁定的 Tesseract/Leptonica 源码离线静态构建；模型、许可证、构建工具输入单独锁定。Typst/PDFium 的来源、第三方声明和摘要保留在包中。
- `tools/stage-windows-runtime.mjs` 离线检查并复制核心 DLL；`tools/prepare-windows-runtime.mjs` 从本地锁定官方归档提取，绝不执行全局运行库安装器。
- `tools/sync-capability-installer.mjs --check` 检查安装器显示尺寸与目录一致。发布流程离线构建并打包本体运行库；准备新上游输入与构建是分开的明确步骤。
- 以后准备新版本，使用 `tools/prepare-capability-catalog.mjs PDF_PACK TYPST_PACK OCR_PACK FONTS_PACK --release NEW_TAG` 生成目录；它会先核对完整包、原始或 gzip 载荷及逐文件锁。`tools/publish-capability-packs.mjs --packs STAGING_DIRECTORY` 默认只离线检查，不读取凭据、不访问网络；显式添加 `--publish` 才更新自有能力仓库。已发布同名包的长度/摘要不同就拒绝，须新版本和新 tag。工具与配方均保存在代码仓库，维护不依赖临时缓存。
- 新增平台或引擎时先增加资源锁、许可证及最小真实探测，准备对应包并验收，最后才加入可安装目录。不存在的包不能显示为就绪。

本轮引擎证据与剩余工作见 [实施记录](../reviews/readmd-v005-capability-delivery-2026-10-10.md)，数学与中文字体的独立交付见 [字体记录](../reviews/readmd-v005-batch3-fonts-2026-10-10.md)。

中文字体的上游输入、固定字重准备及离线装配分别见 `tools/publication-font-inputs.lock.json`、`tools/fonts/prepare_static.py` 和 `tools/build-publication-fonts.mjs`。准备工具不随应用提供，普通应用构建与能力包装配只读取已锁定的字体字节，不依赖 Python/fontTools。

## 便携 TeX 准备与隔离验证

固定输入为官方 TinyTeX v2026.10 Windows x64 归档，247,389,422 字节，摘要见 `tools/tex-runtime-inputs.lock.json`。`node tools/prepare-tex-inputs.mjs` 默认只离线核对；维护者明确加 `--download` 才准备网络输入。`node tools/unpack-tex-inputs.mjs` 完全离线解包或重新审计已有运行库，核对归档、每个文件和提取边界，不覆盖未知目录。普通应用构建、安装及运行不调用这些 Node 维护工具。

准备输入不是可安装产品包。当前归档包含 21,454 个文件、536,953,774 字节及 322 条数据库记录（其中 320 个组件），未包含完整中文出版资源和各组件对应源码；许可证、源码义务及新的大包流式安装仍需审查。它没有加入能力目录、没有发布到工具仓库，也没有取代用户安装。

`node tools/audit-tex-inputs.mjs` 离线读取固定归档、审计清单和上游组件数据库，生成各组件许可证、依赖及源包摘要分类，并检查中文宏包缺口。分类报告始终明确不是分发批准，不以许可证名称或源包摘要代替对应源码和条款审查。

Windows 的新便携编译入口使用 AppContainer、明确文件句柄继承、无网络能力和受限 Job。运行库只读、任务目录单独授权，不为解决旧引擎路径问题给私人上级目录放开权限。每任务的非盘符设备别名提供短执行路径，最后一个工作进程释放后撤销；实际资源仍使用管理目录。XeLaTeX 输出 XDV，再由 Rust 显式启动同样受限的 PDF 驱动，不通过系统命令壳启动。两个引擎共用输出、时间及取消检查。

TeX Live 2026 的 `openin_any` 已无读取限制效果，不能当作沙箱。新入口用真实目录外读取失败检查 OS 边界；正式预览、导出和 MCP 已移除系统 TeX 查找，统一进入受管理编译服务。能力包尚未完成分发审查，当前正式目录仍提示待准备。早期隔离证据、失败尝试与余项见[便携 TeX 隔离记录](../reviews/readmd-v005-batch3-tex-sandbox-2026-10-10.md)。

大型能力包的 v2 流式读取现已接入同一安装服务。原生离线导入不把整个包读成 JSON/base64；浏览器在同一窗口按最多 4 MiB 分块传输，显示进度并允许取消，完成校验和真实探测后才提交。已用 141 MB 的锁定测试包在 Windows 功能入口验证安装、错误重试、实际 PDF、退出及重启；这不是已发布的 TeX 包或最大容量认证。通用旧 JSON 单请求导入保留 128 MiB 上限。固定 v1 资源可以在逐文件身份完全不变的前提下重编码为 v2，自有仓库当前分发仍为原有四包。维护命令、信任边界与剩余工作见[流式能力包合同](../design/capability-pack-v2-spec.md)及[分块记录](../reviews/readmd-v005-batch3-chunk-upload-2026-10-10.md)。未审查的 TeX 仍不可安装。

上传取消和过期后不安装；传输中真正退出程序，下一次启动会清理已识别且无人使用的未完成上传文件，保留用户额外文件。需要继续时重新选择离线包。校验失败保留原窗口及重试入口，不把错误清理误报成“用户取消”。这些规则只管理集中暂存，不改动当前文档或原有安装。

引擎正在使用且字节有效时，功能入口继续正常操作，由各引擎执行实际并发限制；不会误报未安装并要求重复下载。正在使用的资源若已损坏，会提示忙碌，等待任务结束后再修复。PDF 会话和实际排版／识别任务均保护其资源，修复／卸载不能移除在用文件；卸载遇到已知文件被锁定时会回滚已移动文件，未知用户文件保留。对应真实 Windows 流程见[安装接线记录](../reviews/readmd-v005-batch3-stream-install-2026-10-10.md)。

## 中文 TeX 的维护输入

`tools/tex-publication-inputs.lock.json` 固定基础归档之外的完整 CTeX 依赖闭包：43 个包，运行归档共 85,932,952 字节。`node tools/prepare-tex-publication-inputs.mjs --runtime-only` 默认离线逐包核对；显式 `--download` 才获取输入，完整版本另准备匹配的宏包源码与文档。数据库修订、容器长度、SHA-512 和声明文件集都锁定，不能拿上游新文件替换旧版本。

`python tools/compose-tex-publication.py` 是独立维护准备工具，离线验证基础文件与新增包、严格解包并生成相对文件数据库，不执行 `tlmgr`、宏包钩子或系统 TeX。它不随软件交付、不接入普通构建或安装器；ReadMD 运行没有新增 Python 依赖。结果位于集中准备缓存，34,822 文件、736,565,687 字节；基础文件用硬链接复用，逻辑长度不等于新增实际磁盘占用。已有结果只能审计，不能静默覆盖。

ReadMD 生成的中文 TeX 使用 `fontset=fandol`，避免 CTeX 根据 Windows/macOS 自动选择系统字体。pdfLaTeX 的 T1 字体使用已包含矢量轮廓的 Latin Modern，禁用临时生成位图字体的依赖；报告和书籍按章、节映射标题。手写或导入模板仍可声明自己的字体，缺字和字体不可用必须报错。便携编译输出通过 Rust 补入标准 Adobe CID 字体缺少的 Unicode 映射，便于独立阅读器、复制与文本提取，不改变字形或页面绘制指令。

中文运行输入与最终可安装包分别验收：对应二进制源码、部分历史宏包材料和分发审查尚未完成。流式协议已将文件数预算调整到 40,000，8 MiB 清单、4 GiB 展开及逐文件校验上限保持不变；完整大包另外验证。TeX 仍未加入正式下载目录。生产接线现已统一，但完整安装、并发、修复卸载及其他平台仍按各自实际证据验收。

完整 34,822 文件输入已从 373,309,453 字节的流式归档重新提取，经过真实取消清理和隔离中文书籍输出，旧资源保留。此为开发容量证据，不是用户可安装 TeX 包；当前下载目录仍只包含上述四项已审查资源。详细结果见[容量验证](../reviews/readmd-v005-batch3-tex-stream-capacity-2026-10-10.md)。

## 受管理 TeX 的开发验收

`node ui-tests/prepare-managed-tex-fixture.mjs` 仅复用已固定的本地输入，建立独立 QA 资源目录、应用锁和流式包，不联网、不运行引擎、不修改正式资源。测试包明确保留 `redistributionApproved=false`、`qaOnly=true` 和未发布状态；仅用于检查真实安装链路，不能交给用户或加入下载目录。公开目录及输入审查状态不得为使测试通过而更改。

将维护者明确指定的离线构建路径设为 `READMD_BIN`，将生成的 QA 目录设为 `READMD_TEX_QA_FIXTURE`，运行 `node ui-tests/managed-tex-native.cjs`。脚本使用隔离配置、合成资料、正式 CSP 和只含 System32 的子进程 PATH，检查完整安装、两个编译引擎、预览／导出、实际 MCP、保存重开、卸载及旧预览失效。报告中的正式能力包验收始终为否；发现失败必须保存原始记录。

`managed_latex_probe` 开发示例另外检查资源租约、两任务并发、忙碌拒绝、取消、等待就绪探测、损坏资源及目录外读取。它与桌面共用 Rust 编译服务，不通过系统 TeX 或模拟结果代替执行。完整运行库校验也计入任务取消与期限，不能只限制实际排版阶段。

该故障示例先执行一次真实状态／就绪探测，再测试工作任务；此设置与功能进入点一致，但不代表冷态校验符合性能预算。冷态全树校验仍曾超过任务预算，正式 TeX 包尚未发布；需要精简运行闭包并另行验收。生成的 XeLaTeX 使用随包 Unicode Math 与 Latin Modern Math，避免 DSL 的希腊字母落入传统字体而失败；pdfLaTeX 保留 ASCII 路径，不能据此声称任意 Unicode 公式都由 pdfLaTeX 支持。

## 升级时保留可信历史清单


工具只登记明确提供的维护者输入，不从用户资源目录自动发现或授权清单。结果是应用自带的 `capabilities/recovery-locks.json` 与 `capabilities/history/<fingerprint>.lock.json`；后者保留原始文件，不能重排字段。Rust 启用了 `serde_json/preserve_order`，历史指纹为保持字段顺序的紧凑 JSON 的 SHA-256，既不是原始文件字节摘要，也不是排序后的 JSON 摘要。
