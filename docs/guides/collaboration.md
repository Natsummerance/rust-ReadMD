# 协作与本地保存

在已打开的 Markdown 中进入现有分享面板，展开协作并开始会话。主持者继续使用桌面编辑器；参加者通过邀请链接使用协作网页。按角色邀请编辑者、审阅者或阅读者；评论、建议、附件和成员管理在协作网页中提供，桌面分享面板中的“评论与建议”也能查看和处理共享审阅。服务端执行权限检查。

同步与保存是两个动作。修改同步到会话后，桌面页面仍可能有未保存标记；Ctrl+S 才原子保存到本地文件。网页来宾不能任意读写主持者的文件。个人撤销只撤销自己的编辑，其他人的修改继续保留。

断线时，本地增量进入当前会话的 IndexedDB 日志，重连后合并；服务端持久化后才确认增量。请保留浏览器及应用资料目录，清除此目录会删除尚未上传的离线增量。应用重启会恢复未关闭页面和原有启用的协作绑定；全部页面关闭后仍进入主页。局域网端口优先复用，若端口被占用或网络地址改变，需要重新分发分享链接。

建议所涉及的内容被他人修改后，直接接受会停止并打开“对照并合并”。核对原先审阅内容、当前共享内容与合并后的替换内容；若删除或移动章节使原范围失去位置，先在编辑器选中新的目标范围，再点“使用编辑器选区”。桌面中可先关闭分享面板，进入编辑并选中目标文字，再返回原合并草稿。多处建议分别指定范围，最后应用合并内容。刷新对照会保留已输入的替换文字，并重新核对当前范围；不能把旧选区沿用到新的正文。

合并草稿与最近一次确认的共享审阅历史单独保存在本机 IndexedDB，既不加入正文同步队列，也不因文本同步确认而删除。断网或重开页面后可继续修改草稿，联网刷新对照后再提交。提交时必须先同步现有编辑；服务端重新检查编辑权限、待审状态、完整正文修订、持久变更计数和 UTF-16 范围。正文被编辑后又撤销，即使文字相同，旧的手动合并对照也必须刷新；日志压缩与服务重启不会重置此计数。过期、降权或存储失败会保留原建议与合并草稿。成功决定及其正文增量在同一 SQLite 事务中提交，历史保留原提案、处理人、实际合并事务及逆向片段。本地文件仍需明确保存。

已接受的共享文字修改，在正文仍处于该决定刚提交后的修订和变更计数时，编辑者或主持者可在该条审阅中点击“撤销”。这是对共享决定的明确操作，不占用个人撤销快捷键。服务端只使用该决定保存的逆向片段；后续有任何正文增量，包括修改后撤销到相同文字，都会拒绝旧决定的撤销，避免覆盖他人修改。缺少可信逆向片段或计数的旧记录、评论和无实际文字变化的决定不提供此操作。

撤销将正文增量与独立的历史回执原子提交，原提案、原接受决定和原状态保持不变；决定历史另显示撤销人和时间。响应丢失后，同一成员用原修订和计数重试只会取得同一回执，不会再次应用逆向片段；重试仍重新检查当前权限。撤销结果会同步给其他成员，本地文件仍需明确保存。当前不支持重新应用该决定或跨后续编辑自动重定位撤销范围。

明确丢弃一个桌面页面时，断开该页面的绑定并标记其未发送的增量不可恢复发布；不会撤销已经同步到会话的内容，也不会关闭来宾会话。再次开始同一会话时，以已确认的会话状态为基础。结束整个会话则要求当前增量已同步。

重启时若发现磁盘原稿被外部修改，或恢复稿与本地协作日志不一致，停止自动绑定并保留两份内容供审阅。协作失败或存储失败不能静默覆盖文件。输入法正在组合文字时延迟应用远端修改；真实物理输入法和数位设备仍需单独验收。

Windows 原生证据见验收账本：双向编辑、个人撤销/重做、明确保存、会话传输中断、组合事件保护、后台标签页隔离、真实进程重启、来宾未发送增量恢复、远端光标、丢弃隔离及外部修改保护共 11 项。该证据不代表 50 个原生客户端、八小时运行或全平台认证。自托管部署、运行中备份和恢复方式见[设计文档](../design/readmd-experience-and-capabilities.md#自托管备份与升级)。

独立 HTTP 压力入口为 `ui-tests/collaboration-http-stress.cjs`，通过 `READMD_COLLAB_BIN` 指定离线构建的 `readmd-collaboration`。它启动隔离服务和 3／10／50 个独立 Yjs 文档，检查并发编辑、重复投递、个人撤销、阅读者拒写、撤销权限及重启恢复；还先发送依赖后续增量，跨过 128 次日志压缩阈值并重启，再补回前置增量，核对没有丢失。所有资料和凭证均为临时合成数据。报告中的同步耗时只代表当次负载，不是空闲机器基准，也不替代 50 个原生窗口或八小时测试。
