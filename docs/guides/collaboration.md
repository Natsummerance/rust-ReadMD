# 协作与本地保存

在已打开的 Markdown 中进入现有分享面板，展开协作并开始会话。主持者继续使用桌面编辑器；参加者通过邀请链接使用协作网页。按角色邀请编辑者、审阅者或阅读者；评论、建议、附件和成员管理在协作网页中提供。服务端执行权限检查。

同步与保存是两个动作。修改同步到会话后，桌面页面仍可能有未保存标记；Ctrl+S 才原子保存到本地文件。网页来宾不能任意读写主持者的文件。个人撤销只撤销自己的编辑，其他人的修改继续保留。

断线时，本地增量进入当前会话的 IndexedDB 日志，重连后合并；服务端持久化后才确认增量。请保留浏览器及应用资料目录，清除此目录会删除尚未上传的离线增量。应用重启会恢复未关闭页面和原有启用的协作绑定；全部页面关闭后仍进入主页。局域网端口优先复用，若端口被占用或网络地址改变，需要重新分发分享链接。

明确丢弃一个桌面页面时，断开该页面的绑定并标记其未发送的增量不可恢复发布；不会撤销已经同步到会话的内容，也不会关闭来宾会话。再次开始同一会话时，以已确认的会话状态为基础。结束整个会话则要求当前增量已同步。

重启时若发现磁盘原稿被外部修改，或恢复稿与本地协作日志不一致，停止自动绑定并保留两份内容供审阅。协作失败或存储失败不能静默覆盖文件。输入法正在组合文字时延迟应用远端修改；真实物理输入法和数位设备仍需单独验收。

Windows 原生证据见验收账本：双向编辑、个人撤销/重做、明确保存、会话传输中断、组合事件保护、后台标签页隔离、真实进程重启、来宾未发送增量恢复、远端光标、丢弃隔离及外部修改保护共 11 项。该证据不代表 50 个原生客户端、八小时运行或全平台认证。自托管部署、运行中备份和恢复方式见[设计文档](../design/readmd-experience-and-capabilities.md#自托管备份与升级)。

独立 HTTP 压力入口为 `ui-tests/collaboration-http-stress.cjs`，通过 `READMD_COLLAB_BIN` 指定离线构建的 `readmd-collaboration`。它启动隔离服务和 3／10／50 个独立 Yjs 文档，检查并发编辑、重复投递、个人撤销、阅读者拒写、撤销权限及重启恢复；还先发送依赖后续增量，跨过 128 次日志压缩阈值并重启，再补回前置增量，核对没有丢失。所有资料和凭证均为临时合成数据。报告中的同步耗时只代表当次负载，不是空闲机器基准，也不替代 50 个原生窗口或八小时测试。
