# OpenAPI 文档生成与更新

在目标 Markdown 文档中打开命令面板，运行“从 OpenAPI 生成文档”，选择 JSON、YAML 或 YML。查看操作增加、修改、删除和前后差异，接受后进入编辑草稿。取消不创建文件、不标记正文修改；接受是一次可撤销编辑，保存才写磁盘。也可从主页生成新稿。

再次选择同一个来源会更新原来的生成区，而不是不断追加。生成区外可自由编写研究笔记、示例与解释；生成区内部若有手工修改，更新会停止，避免丢失这些内容。先将笔记移到区域外，或通过历史恢复生成区，再重新生成。隐藏注释保存来源身份和摘要，普通文档不会自动附加这些注释。

审阅期间修改正文、API 主文件或实际引用的本地依赖，会使旧提案失效。重新生成后再接受。外部修改磁盘文件仍由普通保存的修订检查保护，API 生成不绕过保存规则。

VS Code 使用 `ReadMD: Generate API documentation` 命令。扩展调用同一 Rust 内核，打开原生差异页后接受或取消；接受为一次原生撤销操作，保存前磁盘不变。需信任当前工作区并配置可用 ReadMD 内核。MCP `readmd_openapi_document` 提供相同只读生成与事务接口。

支持 OpenAPI 3.0/3.1、路径与操作、参数继承、请求体、响应、安全要求、内部引用、组件数据及 3.1 Webhook 内容。输出源映射使用 JSON Pointer 和 UTF-16 文本范围。主规范所在目录及子目录中的 JSON、YAML、YML 文件可通过相对路径与 JSON Pointer 引用；解析不会联网，路径越界、链接逃逸、循环和缺失会报告诊断，保留未解析内容。示例和扩展字段不会触发文件读取。

目前不是完整 OpenAPI 验证器，也不保证全部扩展字段投影；包含独立 `$id`、锚点和动态引用等资源作用域的复杂模式保留并给出诊断，不按普通相对文件路径猜测。源码最多 8 MiB、2,048 个操作；本地依赖、深度、节点数和展开内容均有预算，YAML 还有事件与别名预算。达到并发预算会返回繁忙，允许稍后重新操作。源文件不会执行脚本或自动请求其中的服务器。

Windows 桌面与真实 VS Code Extension Host 曾验证单文件流程；跨文件依赖仍须分别取得桌面和 Extension Host 的原生验收证据。其他平台和全部语言人工审校仍待验收。
