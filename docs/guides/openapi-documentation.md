# OpenAPI 文档生成与更新

在目标 Markdown 文档中打开命令面板，运行“从 OpenAPI 生成文档”，选择 JSON、YAML 或 YML。查看操作增加、修改、删除和前后差异，接受后进入编辑草稿。取消不创建文件、不标记正文修改；接受是一次可撤销编辑，保存才写磁盘。也可从主页生成新稿。

再次选择同一个来源会更新原来的生成区，而不是不断追加。生成区外可自由编写研究笔记、示例与解释；生成区内部若有手工修改，更新会停止，避免丢失这些内容。先将笔记移到区域外，或通过历史恢复生成区，再重新生成。隐藏注释保存来源身份和摘要，普通文档不会自动附加这些注释。

审阅期间修改正文或 API 文件，会使旧提案失效。重新生成后再接受。外部修改磁盘文件仍由普通保存的修订检查保护，API 生成不绕过保存规则。

VS Code 使用 `ReadMD: Generate API documentation` 命令。扩展调用同一 Rust 内核，打开原生差异页后接受或取消；接受为一次原生撤销操作，保存前磁盘不变。需信任当前工作区并配置可用 ReadMD 内核。MCP `readmd_openapi_document` 提供相同只读生成与事务接口。

支持 OpenAPI 3.0/3.1、路径与操作、参数继承、请求体、响应、安全要求、内部引用、组件数据及 3.1 Webhook 内容。输出源映射使用 JSON Pointer 和 UTF-16 文本范围。外部引用不会自动联网获取；循环、缺失和外部引用会报告诊断，保留原始内容。

目前不是完整 OpenAPI 验证器，也不保证全部扩展字段投影或跨文件引用解析。源码最多 8 MiB、2,048 个操作，YAML 有深度、事件、别名及展开预算；达到并发预算会返回繁忙，允许稍后重新操作。源文件不会执行脚本或自动请求其中的服务器。

Windows 桌面已验证审阅、取消、接受、撤销、保存重开、重复生成、同名不同来源及修订冲突。真实 VS Code Extension Host 已验证取消、接受、一次撤销、显式保存、幂等和冲突拒绝。其他平台和全部语言人工审校仍待验收。
