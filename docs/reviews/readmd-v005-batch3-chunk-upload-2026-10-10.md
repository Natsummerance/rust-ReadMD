# 第三批：大型能力包的浏览器分块导入

本增量继续实现“核心依赖随本体，重型引擎在使用时安装”，补齐浏览器传输至统一安装事务的链路。没有新增工作台、依赖包或常驻按钮，没有发布主程序或改变已发布的四个资源包。第三批及 V0.0.5 的完整范围仍保留。

## 用户行为与实现

功能内已有的离线导入窗口现在显示分块进度并支持取消。浏览器只读当前块，先计算 SHA-256，再发送不超过 4 MiB 的请求；原生文件选择仍直接从文件流安装。新格式最大传输预算为 2 GiB，实际包还必须满足软件固定目录的长度、摘要和资源锁。通用旧 JSON 导入保留 128 MiB 兼容接口；已知引擎的功能入口对两种格式均可使用分块。

Rust 上传会话绑定配置身份、引擎、调用标识及私有令牌。offset、块长和摘要不符合时拒绝写入；完全相同的重复块只返回确认，不重复追加。重复开始返回原会话，重复结束返回原安装任务。状态查询不包含令牌，令牌不进入本次证据或日志。

同一配置至多四个活跃上传安装任务，总传输预留不超过 2 GiB；预留在解包和探测期间继续计入，直到终态。HTTP 接收层在分配或读取超额正文前拒绝大于 4 MiB 的分块。收到完整文件不等于安装成功：只有统一校验、真实引擎探测及原子提交完成后才报就绪。

取消与提交沿用同一边界，已确认的取消不能随后提交。故障清理不会把真正的校验错误改成用户取消，错误仍在原窗口内显示并可重试。网络传输只对可识别的网络／响应解码故障做至多三次有界尝试；重试使用同一请求标识或相同块，不能重复修改资源。提交确认不明确时查询同一任务的实际结果。

未提交的字节存于配置目录 `capabilities/transfers/`，不写文档目录。15 分钟无活动的上传会话过期。活跃阶段以文件锁持有目录；实际进程退出后，下次启动只清理有明确标记且无活跃持有者的已知上传文件，保留未知用户文件原位置，不递归删除。重启不自动安装未完成的包；用户需要重新选择离线文件。macOS／Linux 文件锁分支尚无原生证据。

## 验证范围

最终来源摘要及证据见[本增量索引](../evidence/capability-upgrade/2026-10-10/batch3-chunk-upload-manifest.json)。测试使用正式 CSP、真实 Windows 宿主、System32-only PATH、隔离配置与合成文档。修正后的六条完整流程一次全部通过；先前失败／中止的开发尝试不计入通过数，也没有删去失败记录。

- 大包六流程通过：真实 HTTP 校验／幂等／容量保护；限速条件下实际按钮取消；合法 gzip 数据但整包摘要失配的错误反馈和重试；功能内安装继续及真实 PDF；重复结束与再导入；实际进程退出后重启清理并再次导出。
- 该流程发出 112 次分块请求；明确发送的协议探测块最大 4 MiB，服务端同样在读超额正文前拒绝。限速条件下从取消操作至界面退出记录为 96 ms，这不是所有负载或平台的性能认证。
- 当前程序的原四包 10 条 Windows 原生回归再次通过，包含修复、在用保护、真实 junction 和重启。两组流程分别记录，不把协议探测次数当功能数量。
- 最新完整 Rust 内核 **2068 通过、0 失败、3 项既有忽略**。安装／传输专项 **22 项**为其子集，不重复相加。维护工具 **11 通过、0 失败／跳过**。
- 离线锁定构建、boot 一致性、资源、接线、无应用 Python、安装器尺寸一致及语法检查通过。没有新增可见文案，复用现有 i18n 键，不据此宣称 46 语言完整语义审校。
- 真实 PDF 经独立 Poppler 渲染后检查：标题、正文、分式、希腊字符和表格清晰，无重叠裁切。1024×680 的安装进度和本地化错误卡片已视觉检查；短功能材料不能代替论文／科研表格或宣传材料验收。

容量材料保留已审查 Typst 引擎原字节，增加 112 MiB 固定合成数据，形成 **141,000,444 字节**、展开 **169,958,981 字节**的锁定 v2 包。容量用目录仅存在于隔离测试资产中，没有修改生产目录或发布到 GitHub；它不是 TeX 包、许可证批准或 2 GiB 极限认证。准备器为 `ui-tests/prepare-capability-chunk-fixture.mjs`。

原生脚本为 `ui-tests/capability-chunk-native.cjs`，验证真实 HTTP 校验、功能内导入／取消／错误重试、实际 PDF、重复结束、进程退出和重启清理。Playwright 将所有 CDP 浏览器标记为远程并拒绝传送大于 50 MiB 的文件；测试先确认自己启动的同机进程与本地真实文件，再通过其 in-process QA bridge 修正这一自动化传输标志，继续使用原文件选择器的 `setFiles` 本地路径流程。不修改应用、CSP 或校验规则，不合成 Blob、不拦截安装或导出响应。升级测试工具后若桥接接口改变，脚本明确失败。

此前尝试未计作通过：测试资产用目录 junction 指向外部，被正式静态文件边界拒绝，导致样式与翻译未加载；改为实际目录及只读使用的文件硬链接，保留生产安全检查。其后发现 Playwright 大文件传送限制，独立 CDP 文件选择会话在 WebView2 下未取得完整结果，改用上述同机真实文件选择流程。取消测试明确模拟 1 MiB/s 的上传条件，为真实 UI 操作留出窗口，不依赖恰好能在本机高速传输中抢在提交前点击。失败报告与中止尝试保留在缓存分类中，修正后的完整流程须全部重新走通。

等待工具还暴露了正式 CSP 下的 `unsafe-eval` 拒绝：最新捕获该错误时原生进程未退出，不能将此前的调试连接关闭都归因于应用崩溃。测试改为 Node 侧读取真实状态文字并轮询，不放宽 CSP。调试器正文缓存也被限制，不在调试事件中保留整批二进制上传数据；请求上限取明确发送的协议探测字节及服务端接收检查，不用调试器缓存推断产品内存峰值。完整内存压力仍须独立实测。

重现时先将 `READMD_CHUNK_TYPST_RUNTIME` 指向已审查的本地 Typst 解包目录（包含 `bin/`、`LICENSE`、`NOTICE`），运行准备器；将其输出的 `fixture.json` 完整路径设置为 `READMD_CHUNK_FIXTURE`，将当前离线构建程序设置为 `READMD_BIN`，再运行原生脚本。准备器会重新核对源文件固定摘要，未设置输入时直接失败，不在线寻找或安装工具。
