# ReadMD 安装版生产场景复查（2026-10-06）

本轮以 Windows 11 上的真实安装载荷、系统 WebView2、用户已保存的 AI 连接和真实资料的隔离副本进行检查。源码审计、界面回归、原生流程和压力负载分别记录；一次通过不代表所有外部服务、网络、文件内容和其他操作系统均已穷尽。

## 为什么以前没有查出来

1. **运行对象不一致**：之前大量测试从仓库资产目录启动，不能发现安装目录权限、打包漏项以及 Windows MSIX 文件虚拟化造成的路径差异。实际安装环境出现过入口 HTML 可读，但 CSS/启动脚本被静态路径检查误拒为 403。
2. **真实配置没有进入测试**：UI 回归默认使用空的隔离 AI 配置，部分联网分支用响应夹具检查交互。它们没有验证用户已保存连接的地址、凭据解析和上游的实际模型响应。反代的局域网地址在切换网络后失效；模型目录有条目也不等于每个上游模型仍可生成。
3. **成功判据偏浅**：只验证状态码或面板存在，无法识别空模型目录、损坏 Office 文档被解码成原始 ZIP 文本、“已取消”但仍继续 OCR、导出 HTML 静态正文为空等问题。
4. **负载与交互组合不足**：小文档和独立控件测试没有覆盖数百页扫描件、稀疏超宽表格、同文件并发写入、滑块拖动与旧请求返回相交等情况。
5. **覆盖声明不够明确**：条件跳过、浏览器桥模拟和源码接线检查不能计作原生成功操作；i18n 键集合一致也不能计作已翻译。

责任在验收设计：以前的检查范围不足以支撑“生产环境所有功能都能使用”的结论。本轮把这些失败分别加入可复用的检查，而不是仅修一次现象。

## 验收层级与未穷尽条件

- **原生**：实际 Win32/WebView2 进程，无伪造桌面桥；自绘顶栏、窗口缩放、物理拖动、托盘、重复启动、文件交接、退出恢复、隔离网页授权/取消/关闭真实执行。
- **真实 API/磁盘**：安装载荷内核、实际上游和系统引擎；导出/转换/保存检查磁盘内容，不只检查成功标志。
- **界面回归**：安装资产上的浏览器操作；个别外部服务使用响应夹具时只验证交互和失败反馈。
- **源码/条件**：外部账号、网络、系统权限、可选解释器、其他设备/平台等分支仍明确依赖条件，不能写成已在这台机器穷尽。

Windows 默认应用状态和已登记的打开命令被检查；受 Windows 用户选择保护的默认应用确认不被静默改写。联网更新元数据本机已读取，代理/超时/镜像失败分支由内核测试覆盖；没有实际切换所有公网、代理、断网、企业防火墙环境。macOS/Linux 原生交互由其平台另行验收。OCR/语音准确率、上游模型可用性和复杂文件的版式还需要内容质量抽样；本轮的文本量与回读检查不能证明每个字识别正确。

外语补译使用机器辅助，校验键、占位符、英文回退和动态交互，未声称 42 种语言全部经过母语者逐句审校。公开 UI 文案单独处理，不上传用户资料。原生物理拖动测试必须独占鼠标；本轮有一次窗口拖动和一次桌宠短距拖动初跑失败，顺序复测通过，具体原因未稳定复现。保留初跑记录，不把未确定原因的现象写成已修复的产品缺陷。原生测试的默认工作区收紧到自己的资料目录，避免启动夹具时顺带索引整个用户临时目录；CDP 就绪检测也增加重试，避免端口文件已生成但服务尚未监听时误判失败。

## 复用本轮检查

最终本机检查：Rust 1862 项、xtask 12 项、Node 45 项通过；另显式运行随包桌宠安装和真实 HTTPS 两项条件测试。完整桌面 UI 306 项通过，1 项移动触控条件跳过；另外完成最终内核上的图谱/保存/语言 25 项、9 项移动尺寸检查和 8 组外语全弹窗检查。21 组最终原生/真实资料场景通过，0 页面异常、0 资源失败，原件哈希未变。两次物理测试初跑失败和测试隔离/就绪检测的修正已在上文记录。脱敏计数、场景指标及完整桌面用例状态见[结果数据](readmd-production-audit-2026-10-06-results.json)。

所有检查需要现有 Node/Playwright 与已编译程序，不安装新依赖。Rust 使用 `cargo test --offline --locked --manifest-path rust/Cargo.toml -p readmd-kernel -p xtask`；前端修改后执行 `cargo run --offline --locked --manifest-path rust/Cargo.toml -p xtask -- bundle-boot`，再运行 `tools/check-i18n.mjs`、`check-styles.mjs`、`check-wiring.mjs`、`check-assets.mjs`、`check-no-python.mjs` 和 `privacy-scan.mjs`。Node 工具测试及编辑布局、全部语言切换回归已接入仓库 CI。

- `ui-tests/installed-native-audit.cjs`：指定 `READMD_BIN`、`READMD_ASSETS_DIR`、`READMD_PRODUCTION_DATA`、`READMD_PRODUCTION_CORPUS`、`READMD_PRODUCTION_REPORT`。资料清单包含 `{source, copy, sha256, suffix, bytes}`；`copy` 必须位于隔离目录。AI 检查另需 `READMD_PRODUCTION_AI_CONFIG` 和 `READMD_PRODUCTION_AI_MODEL`，配置文件仅含本机安全凭据引用，不能提交。
- `ui-tests/production-stress.cjs`：使用独立临时资料和配置执行读写、冲突、批量转换压力；报告区分内核工作集与整个软件内存。
- `ui-tests/window-native-smoke.cjs`、`native-web-test.cjs`：指定实际 `READMD_BIN` 和 `READMD_ASSETS_DIR`，使用系统 WebView2 和真实 CSP；窗口测试独占鼠标。
- `packages/readmd-pet-rust/scripts/smoke-windows.ps1`：传入随包的 `-Executable` 和 `-RendererRoot`；分别验证精灵图、`-Character live2d-haru -Renderer live2d`、`-Character bongocat`。
- Playwright 完整桌面回归：`--project=desktop --workers=1 --retries=0`；设 `READMD_PET_RENDERER_BUILD` 为随包 renderer 路径、`READMD_VERIFY_NATIVE_PET=1`，避免因没有桌宠载荷而跳过。移动触控检查使用 `--project=mobile`。
- `tools/i18n-complete.mjs`：可选的公开文案补译工具，使用已配置的本机 ReadMD 连接和明确的模型、输出文件、调用预算；先审阅输出，再交给 `tools/i18n-add.mjs`，不读取 API 密钥。
