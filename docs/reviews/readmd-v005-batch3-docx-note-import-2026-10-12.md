# 第三批增量：Word 脚注与尾注导入

2026-10-12。状态：本增量 Windows 验证通过。本次处理实际内容丢失及保存链路，不改变完整 B3-51–57 合同，也不宣布第三批完成或正式发布。

## 用户能走通的流程

打开或拖入 DOCX → 提取为 Markdown → 在已有编辑器校订脚注／尾注 → 显式保存 → 重启重开 → 重新导出 Word。重复引用共用同一定义；脚注与尾注的相同 Word ID 不冲突。段落、引用、列表起始编号、表格、代码、链接、图片和 Office 公式复用现有正文转换能力。

图片预览仅暂存；另存为成功后才进入共享 `readmd-assets/`，不提前生成输入目录旁的 MD 或资源文件。注释中的旧公式属性在明确保存时迁移为可读 DSL，保留脚注容器；代码示例继续作为代码。

注释及其图片、链接依据所属部件的关系解析，支持非默认路径和命名空间别名。缺少定义、重复 ID、缺失资源、外部注释部件、损坏 XML、非法字符引用及不合规嵌套都明确失败。字段与已接受移动的内容保留，删除／移出内容不导入；无法映射的引用不能静默丢弃。结构错误不再进入可能丢失注释的旧转换回退。

## 实现与边界

`convert/docx_notes.rs` 负责有界命名空间解析、部件关系、身份及引用完整性；正文和注释共用结构转换器。`math_migration.rs` 与 `math_dsl.rs` 使用同样的脚注容器规则，保存、渲染与导出共享模型。无新增依赖；内置 Word 转换及输出不依赖本机 Office。

本增量不宣称所有 DOCX 无损：混合脚注／尾注的原始编号、任意节及全部版式属性继续按完整出版合同验收；导出遵循用户选定的当前注释预设。ReadMD 自身往返不能代替 Word／WPS／LibreOffice 的实际应用认证，Windows 文件对话框成功也不能代替其他系统原生验证。
