# V0.0.6 macOS 关闭故障紧急修复

Finder 在会话恢复尚未完成时交付新文件，旧实现立即进入 `loadFile` 并改变文档加载 epoch。恢复程序因此正确拒绝把残缺的页面集合写回磁盘，但当前窗口此后一直没有会话写入资格，关闭标签和真正退出均被持久化屏障拒绝。不能通过删除屏障或强行获取最新 CAS 版本来绕过这一状态。

新文件现在等待权威会话恢复完成，再使用既有队列依次打开。恢复过程自身的初始文件具有内部标记，避免与排队的 Finder 文件相互等待。保持原有鉴权、CSP、修订、恢复和重命名保护，没有改变保存或审阅的含义。

## 故障与通过证据

新增确定性回归先在旧实现失败。真实 LaunchServices／Cocoa WKWebView 中，延迟原始会话 GET 回应后打开文件，同样在 `finder_open_waited_for_authoritative_restore` 首败；测试只延迟真实回应，没有替换内容、鉴权或持久化服务。

修复后同一原生场景完成三次独立进程、26 项检查：旧页面与新文件并存、真实标签按钮关闭、取消保留正文、“不保存”返回原始预览、丢弃内容可从真实历史读取、丢弃后关闭最后标签、保存后重开、重启恢复及空会话回主页。磁盘预期为独立固定的中文／emoji／BOM／CRLF 字节。后两次启动使用正式 index，没有延迟脚本。

完整 Node 回归 1776 项：1773 通过、0 失败、3 跳过。已有并发写入冲突、丢失回执、持久化失败、重命名恢复和待审正文保护继续通过；新增多个启动文件及初始文件与外部文件交错的回归。boot 由仓库 xtask 在 `--locked --offline` 下重新生成并检查。

## 分发边界

本次只更换 V0.0.6 的 Mac ZIP／DMG，原发布标签和其他平台保留。Rust 内核源码没有改变，沿用原 V0.0.6 已发布的 ARM64／x86_64 内核及桌宠载荷，打包时重新签名，并逐个核对新 boot。安装包的最终摘要、真实冷启动及发布回执另行绑定，不沿用旧包结果。

Mac 仍是用户选择的免费 ad-hoc 签名，未取得 Apple 公证。Apple Silicon 原生和 Intel 包在 Rosetta 下的执行分别记录，Rosetta 不等于 Intel 硬件验收。本轮没有加载模型，没有变更 75 条完整合同的认证状态，也不将其他 V0.0.7 待办混入紧急修复。

已经处于旧故障状态的进程需要重启才能加载修复。日常配置、恢复记录和用户原件应在本机替换前保护；不得为了安装而丢弃尚未持久化的正文。
