## 首次失败与修正依据

1. 注释原生关系类型、JSON 数值测试和表后结构空段的早期失败均保留；真实源分节、普通代码标签及字号模型兼容问题在共享链路修复后重测。没有新增忽略、跳过或自动重试取得生产通过。
2. candidate-27 的设置材料把非数值标识放进 ISBN 校验字段，先被正确拒绝。夹具改用独立 catalog_id，并继续验证相邻数字字符串及注释不被转换。
3. candidate-28 的首次设置检查把合法 Markdown 实体 III&#46;4 当作错误。独立 oracle 改用既有 marked 的真实顶级语义块与一次 HTML5 实体解码，严格拒绝代码、注释、重复／错误对象和双重实体；没有放宽原生 DOCX 字段、缓存或目标断言。
4. candidate-29 的“30pt”材料只改 FootnoteText 样式，作者文字仍直接指定 10pt，构成同段混合字号。原包保留为精确拒绝负例，另构造每个实际文字 run 都为 30pt 的正例，导入前、再输出后独立逐一核对；没有放宽产品的未知行内字号保护，也不重新签名来掩盖生成引用的显示变更。
5. candidate-30 的真实重开链发现产品问题：第一次导入已把带题注的两列表格简化成列表，留下无对象的 label／ref，第二次输出出现无效题注与缺失引用。保留完整失败包、保存字节、请求响应和原生检查；以实际节点关联保留表格，增加默认 form_tables=true 往返、边界及普通表单反例。首次导入 oracle 同时核查真实表格内容，不能再以宏文本存在冒充成功。
