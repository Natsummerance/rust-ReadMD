日期：2026-10-08。按 [五批执行 Spec](../design/v005-five-batch-spec.md) 完成第二批 B2-01–B2-09 的限定增量，已进入 V0.0.5 工作版本。没有发布安装包，也没有制作宣传片。公共保存、全部 OMML 和生产场景仍按原账本继续验收，不能把本批结果当成这些大范围要求全部完成。

## 实际行为

| 操作 | 结果 |
| --- | --- |
| 编辑第二处重复公式，输入尚未完成的表达式，再切页 | 集中保存原公式的精确范围、正文修订与槽位输入；回来恢复第二处，第一处及磁盘正文不变。DSL 与已有 LaTeX 共用此链路。 |
| 无效公式输入后 Ctrl+S | 保存当前已应用正文，独立保留未应用公式；现有状态位置提示草稿仍保留。没有把无效输入写进正文，也没有创建旁文件。 |
| 正常退出，或已确认持久化后异常终止测试进程，再启动 | 原生 WebView2 重新载入集中记录，恢复对应公式与输入；不依赖浏览器内存。异常终止只承诺已确认写入的输入，不承诺尚在防抖队列中的最后输入。 |
| 修正恢复的公式并离开 | 有效输入形成一次正文事务，可一次撤销/重做；成功应用后清除对应草稿。保存后重启可从集中版本历史找回保存前正文，内存撤销栈不作为跨重启恢复依据。 |
| Esc 或公式取消 | 只放弃当前公式草稿；写入与删除串行，不会被迟到写入复活。 |
| 原文已被外部修改 | 摘要、UTF-16 范围或原公式不匹配时禁止自动套用；“恢复与版本历史”可打开包含原源码与未应用输入的可读恢复副本，不显示内部 JSON/XML。 |
| 恢复写入失败或达到配额 | 明确反馈，失败时阻止会丢失当前输入的导航；保留已确认记录，不因普通历史过期而清除未应用草稿。 |

## 实现边界

Rust 的 `document_history.rs` 复用既有压缩与原子写入，增加内部 `math_draft` 类型、载荷校验和同槽更新。每条上限 512 KiB、每文档最多 32 条，受既有集中总额约束；未应用公式不参加普通历史的 30 天和每文档 10 条淘汰。更新先落新记录再替换旧记录，普通正文保存的草稿清除不会删除公式草稿。记录仅保存公式及必要状态，不复制整个正文。

`formula-inline.js` 负责精确定位、独立草稿、恢复、串行写入/删除和最后输入校验；`document-history.js` 通过真实 Rust 服务保存并提供可读恢复入口。编辑预览、标签切换、主页、文件打开与会话恢复在离开前等待必要写入。没有新增依赖或常驻面板。

修复了回归发现的实际问题：旧的无效输入 Promise 已拒绝时，用户立即修正并点击正文仍被旧错误阻止应用。现在等待旧请求结束后重新校验最新输入。原生测试脚本还修正了 Node 进程被信号终止后 `exitCode` 为空的判断；这是测试进程状态判断问题，与应用数据恢复分开记录。

新增存储配额说明经 `i18n-add.mjs` 同步 46 种明确翻译。键值、占位符及结构检查通过，不把它写成全部 46 语言已经完成原生语义审校。
