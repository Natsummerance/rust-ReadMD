# 第三批：可信历史恢复与真实 OCR 路径修复

接续[旧客户端隔离](readmd-v005-batch3-namespace-2026-10-11.md)，属于 B3-52 的限定增量。没有发布、提交或替换用户安装，全部实测使用自有隔离资料。

## 实际修复

应用升级改变清单时，旧安装记录不能只按新清单解释。Rust 现在从应用自带的有界历史索引选择受信清单，再执行原有完整移除、替换和暂存校验；运行目录中的清单或记录不能自行授予恢复权限。不同历史版本发生回滚冲突时保留双方原件，当前目标的未完成事务仍禁止使用。没有待恢复记录时不额外读取历史索引。

新增离线维护工具显式登记可信旧应用清单，现已随应用保留四个正式能力包的原始清单。指纹保留 JSON 字段顺序：内核启用了 `serde_json/preserve_order`，不能按键排序。登记工具保留原文件、检查整数/Unicode/重复键及数字型键顺序；不能精确表达的材料拒绝登记，不改写为另一个身份。没有改变包下载摘要、版本、许可或正式目录中的四包审批。

实际 OCR 安装暴露了此前纯单元测试未覆盖的问题：规范化模型路径使用 Windows 扩展长度路径前缀，Tesseract 拼接 `/文件名` 后无法打开模型。独立真实引擎对照证明普通路径成功、规范化路径失败。Rust 改为在模型目录内相对读取，以显式只读句柄接收有界解码后的 PNM；临时与缓存根仍在任务目录，创建期工作组和资源租约继续生效。没有系统 OCR、模型整套复制或新的 DOS 映射。

## 失败、边界与下一步

首次历史探针恢复成功，但后续安装因 QA 资产缺少新包的下载摘要被正确拒绝；补齐隔离目录后通过，生产校验没有放宽。首次真实 OCR 安装失败保留；独立诊断定位后修复 Rust，再重新完整回归及原生识别。维护工具首次错误假设键排序；真实 Rust 对照揭示后按原顺序修正，另补数字型键和旧 PDFium 无 review 字段的保留测试。历史 v1 校验投影不写回原清单，也不授予新包分发批准。

曾将工作目录回归扩到超过 Windows 当前目录长度限制，实际启动返回系统错误 267。原始失败日志保留；后续测试只认证普通长度的 Unicode 目录，**超长当前目录仍待修复**，没有将其改成跳过或声称通过。

历史恢复目前覆盖一组真实字体编码升级，不能代表所有历史版本、全部引擎或断电恢复。标准 PDF14 Helvetica 仍用于 Rust PDF 的数字页脚及公式间空白，明确未嵌入；不能宣称全部字体嵌入。Typst/OCR 完整拥有者崩溃、三引擎桌面/MCP 全传输、AppContainer 配置/映射回收、展开磁盘/磁盘满、TeX 正式材料及冷态性能、全 OMML、完整出版属性、实际 Word/EPUB 应用、长期与非 Windows 原生继续待验，第三批仍进行中。
