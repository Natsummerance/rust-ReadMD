# ReadMD 首轮 Mac 原生验证

日期：2026-10-29。正式版本保持 V0.0.5；未发布、未推送。源码起点为正确仓库的迁移分支与指定提交。迁移 ZIP 及解密后 1764 个文件在 Mac 独立校验通过；恢复资料和私人配置留在源码仓库之外的用户工作区内。

## 已确认事实与修复

本机实际检测为 arm64、Apple M5 Ultra、macOS 27.2（26B123）。从正确仓库取得 V0.0.5 的 `ReadMD-macos-arm64.zip`，61,784,110 字节，SHA-256 为 `fd4f4a27f648add3f2ad6a49f32aa1ac17f1dee79f4cddbfa6c1cb26cbe0670d`，与 GitHub 发布元数据一致。

该原包的 Info.plist、arm64 架构、执行权限和系统动态库路径检查通过；app 只有链接器 ad-hoc 签名，Info.plist 未绑定、资源未封装，严格验证和 Gatekeeper 均返回 `code has no resources but signature indicates they must be present`。这是本机复现的公开包缺陷，与原反馈一致；没有用户当时那份安装文件，不宣称排除了其全部故障原因。

修复完整 app 的由内到外签名、宠物程序先签名再生成清单、正式发布的凭据/公证/装订门禁及清理。开发脚本改为明确锁定离线构建、读取真实版本、匹配架构的最低系统版本，拒绝复用旧 app 目录。原图标和品牌资源未修改。

启动探针的旧兜底条件存在将完整空白页记作就绪的风险，现等待真实前端和原生桥。Mac 环境诊断也不再通过 X11 环境变量推断本机无显示器，或仅因选中后端就报告原生就绪。

全库回归还暴露并修复两处 Unix 错误分类：目录占用锁文件名明确归为无效锁对象；导出资源中的符号链接/非目录路径明确归为不安全路径。拒绝、原件保留和禁止跟随链接的规则没有放宽。

## 真实通过范围

- 最终开发 ZIP 解压副本通过 `codesign --verify --deep --strict`；应用产物隐私扫描通过。开发签名仍被 Gatekeeper 拒绝，符合尚无正式签名、公证的边界。
- 同一签名后二进制、生产 boot、正式 CSP 和严格令牌模式，在真实 Cocoa WKWebView 的五个独立进程中通过 43 项检查。测试直接调用生产 UI 函数与实际模态框，未使用浏览器或鉴权/选择器替身。
- 中文路径打开、未修改编辑保持干净、无副本、撤销重做、保存、关页重开、新进程会话恢复、空会话主页均通过。独立文件核对确认 BOM、CRLF、中文和 emoji 字节精确。
- 实际渲染中编辑区有非零布局，初始源码无需滚动即可看到；真实保存冲突框在当前原生窗口内完整可见。这不是 4K、全部窗口尺寸或人工视觉审美验收。
- 独立进程外改后，真实冲突框取消不会覆盖外部版本，当前手改保留；取消退出后仍保持脏正文，并取得草稿持久回执。最后用受控宿主退出清理，未冒称真实断电或完整异常恢复矩阵。
- Mac 选定资料夹后的组重命名明确说明平台限制，源路径、引用和文件字节不变，界面屏障解除。独立只读数据库查询确认没有组事务或路径预留。Mac 组提交仍未实现，不计为跨平台重命名完成。

首次 Rust 全库结果为 4197/4/7。两项分类错误已修复；宠物路径断言还依赖默认资料目录的末级名称，调整本地隔离测试目录后通过，没有改该断言。SVG 工作者缺失单独保留。首次 Node 全套的独立 EPUB 检查默认启动 `python.exe`，改为按宿主选取测试解释器后通过；这是独立测试工具，不是产品 Python 依赖。

原生驱动的早期失败另行保留：生成脚本的转义错误、将 CRLF 返回值误当 LF、把仅元数据响应当正文、未处理保存冲突模态框。这些是测试驱动的错误，不能登记为产品修复。系统 SQLite 的只读检查失败也保留，最终以 Node 自带 SQLite 的只读连接完成独立数据库核对，没有改写被测数据库。

完整原始日志、合成输入、首败和脚本保存在用户工作区的本地证据目录；含实际目录的原始日志不进 Git。精确二进制、boot、源文件和日志摘要见[机器可核对记录](readmd-macos-native-2026-10-29.json)。早期候选的结果没有归给最终候选。
