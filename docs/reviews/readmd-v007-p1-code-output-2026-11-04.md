## 结果与保存

代码运行前向同一 Rust 审阅服务获取固定目标：文档身份、generation、审阅修订、内容修订、节点标识和 UTF-16 源范围。结果提交时重新核对全部字段，只修改被选围栏紧邻的完整输出块。相同调用重试只报告原回执，不重复插入；篡改目标、另一文档、改后再撤销、损坏标记及不明相邻内容均保持拒绝。

结果采用既有编辑事务与持久历史，一次撤销只撤销这次结果，保留独立待审原文和用户正文。原目标在当前编辑器时才进入现有自动保存流程；切页后完成的原目标只得到持久草稿。运行、结果插入、磁盘保存分别核对，保存失败不能显示整个动作已成功。

预览代码卡片归属于一个文档。同样的 Markdown 切到另一页时，编辑器挂载入口失效旧渲染和文本缓存，并清理旧组件；阅读节点复用也重新绑定监听。退出确认期间暂停生成结果写入，取消退出后释放；确认退出等待执行停止。持久关闭回执获确认后，移除页面前同步取消其代码任务，保护已关闭页面。

长文目标的源行只定位一次，避免为每个围栏反复扫描全部前文；2000 段含 emoji 的重复输入保留了 UTF-16 范围断言。受保护的 `preview.js`、编辑器、设置、样式和工具栏精确字节基线均未改动，也未修改既有摘要消除失败。

## 首败与边界

- 初次真实浏览器暴露了跨页复用旧代码卡片所有者，随后受字节保护的预览文件限制促使修复移至既有挂载入口；该入口先后暴露并修复了清组件而保留文本缓存导致的空白。首次失败和后续 7 组通过分别保留。
- 最初退出测试在恢复后的脏页切换时停留于正常保存确认。测试先显式保存，再用独立输入验证确认退出，未伪造确认或加大等待期限。
- [首次远端运行](https://github.com/Natsummerance/rust-ReadMD/actions/runs/41695054513)为 7/8 通过。失败页面仍能重做，记录显示只有 undo 请求；本机按 Linux 键位复现了测试发送的小写 `z` 与 Shift 组合。改为物理 `KeyZ`，并增加实际 Rust redo 请求及 Ctrl+Y 检查，再完整重跑通过。按键输入依据 [Playwright 官方规则](https://playwright.dev/docs/api/class-keyboard#keyboard-press)，产品快捷键未因此重写。
- 完整嵌套容器、生成输出内围栏的来源处理、批量运行顺序/预算、受管运行环境、任务检查点与未知副作用仍待完成。后续新增的内核正常退出修复另有首次失败及新二进制，需独立跨平台验收；MCP EOF、Unix 宿主强杀和崩溃仍分列。
- 当前版本号、日常应用、V0.0.6 发行资产及 75 条总账未改；未加载用户本机的其他模型。
