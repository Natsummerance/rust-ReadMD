# V0.0.5 全模块体验深化复核

日期：2026-10-07。V0.0.5 仍为本地候选。原有 21 个模块、104 条功能流程全部保留，逐项入口、前端、后端、操作和验证条件见[体验矩阵](readmd-v005-experience-matrix-2026-10-07.md)和其 JSON 证据；原始完整清单见[功能盘点](readmd-ui-function-inventory-2026-10-02.md)。

本轮统一采用八项检查标准：可用条件与禁用反馈、正常操作闭环、慢响应和并发、取消与重试、原件与冲突保护、撤销恢复和空间、键盘/输入法/语言/布局、批量和性能边界。清单没有因实现困难而删除。属于其它模块的回归通过，不等于该模块每一种输入和异常都已实机测试。

## 本轮实际改变的体验

| 位置 | 原先风险 | 现在的行为 |
| --- | --- | --- |
| 批量转换 | `running` 行被错误计为完成；重复来源重复执行 | 只统计最终结果；规范化 Windows 路径，ZIP 提取后也去重；已完成行不会被迟到进度覆盖 |
| 批量任务网络 | 请求堆积、断线后丢失任务归属 | 串行轮询、请求超时、逐步退避；保留原任务并显示重新连接；关闭与重开不接受旧响应 |
| 批量取消 | 未确认取消就显示已经取消 | 等待服务确认；失败恢复按钮并允许重试；未知任务提示核对输出，缺失结果不再冒充成功 |
| 转换结果 | 鼠标可点但键盘无法直接打开 | 只有实际产出文件的结果可聚焦，Enter/空格打开；覆盖策略在启动时固定 |
| 文件自动刷新 | 相同修改时间漏检；迟到请求覆盖新草稿或切换后的标签 | 对比内容版本；元数据和正文读回后再次核对当前文档与编辑状态；后台刷新安静完成 |
| 导出 | 双击清空回执；取消/网络错误后缺乏恢复；选择位置期间任务尚未注册 | 重复请求保持现有任务；选择位置前注册任务；明确区分用户取消、选择器失效和请求失败；取消在提交前阻止写盘 |
| 导出预设与回执 | 等待期间改设置导致记住错误预设；打开结果失败未处理 | 保存点击当时的预设；记忆失败仅提示，不否定已生成的文件；打开/定位失败可见且可以重试 |
| PDF 预览 | 快速翻页并发，错误后丢失当前页 | 单次翻页请求；两侧按钮共同等待；失败保留原页、显示原因并可重试；关闭或切格式中止旧请求 |
| 插件 | 重复刷新与安装轮询堆积；开关保存后旧列表把状态改回 | 合并刷新；串行安装进度与退避；关闭中止；开关操作丢弃保存前的旧列表；保留正确空状态 |
| 原生文件选择 | 宿主故障被当成安静取消 | 六种文件/目录/Skill/桌宠插件入口共享失败反馈；真实用户取消保持安静 |
| AI 协议 | 反代忽略流式参数返回 JSON，被当成空补全；Responses 真实文本形状未完整支持；传统 completions 的标准文本被忽略；Anthropic 地址重复拼接版本号 | 按同一响应的 Content-Type 解析，不额外请求模型；兼容 JSON 文本块、SSE 字符串增量及标准/旧版 completion 文本；限制响应体大小；保留代理前缀而避免 `/v1/v1/messages` |
| 验收清单 | 代码移动后按旧行号误报；只见路由名无法证明有处理函数 | 按控件与函数身份检查；路由注册和实际处理函数同时存在；历史退出入口明确标记用户要求移除 |

界面没有新增常驻面板。信息出现在原有任务行、按钮或错误位置。七个新增状态文案通过 `i18n-add.mjs` 写入，46 个字典键齐全；英、简中、繁中、日文提供对应文案，其余语言使用英文回退，不能据此宣称全部语言均已人工翻译。

## 为什么先前没发现

旧用例偏重点击后立即返回的成功响应，掩盖了进行中状态、断线恢复、慢请求与取消确认的差异；有些测试替代了原生选择桥接，因此宿主出错时返回 `null` 的含义没有被验证。AI 用例集中于 SSE，遗漏了“请求流式、服务返回 JSON”以及 Responses HTTP 文本结构。清单的固定行号也容易在正常重构后失效。

还有一类根因是“移植一致”被当成“真实可用”：旧 Python 对照测试把重复版本路径以及忽略标准 completion 文本写成了预期。现已纠正实际路由和文本读取，保留底层兼容辅助函数的历史测试，并用八个真实 HTTP 场景覆盖四协议 × JSON/SSE，分别核对聊天、补全、路径和单次请求；不将修正这些错误解释成回归。

本轮加入可人工推进的真实 HTTP 流测试、慢响应/旧响应/断线故障用例、真实原生桥接和磁盘回读。首次失败没有被覆盖：`.cache/v005-depth` 保留首次桌面运行、JSON 兼容失败、MCP 空补全和后续成功日志。首次全量发现插件空状态被新的状态清空逻辑覆盖，已修复；流测试的固定等待窗口在负载下不稳定，改为由测试端明确推进真实流，不放宽最终业务断言。

## 增量视频与复用

`showcase/updates/v0.0.5/experience-depth` 保存新的原生 4K 批量工作台演示、海报、字幕、事件时间和隐私扫描记录。展示真实 32 文件转换、去重及键盘打开结构完整的哲学阅读材料。不会录入操作系统窗口、私人文件路径或编号叠层。旧宣传片保留，制作目录继续被 Git 忽略。

清单生成命令：

```powershell
node tools/report-experience-depth.mjs --date=2026-10-07 --desktop=.cache/v005-depth/desktop-final-results.json --native=.cache/v005-depth/native-transport-final-report.json --stress=.cache/v005-depth/stress-transport-final-report.json --final=.cache/v005-depth/final-verification.json
```

原生与压力脚本分别为 `ui-tests/experience-depth-native.cjs` 和 `ui-tests/production-stress.cjs`，都要求明确指定独立数据目录和报告位置。新增功能继续按同一标准验收，不通过不纳入素材。

完成编码与隐私检查的录制原始帧已逐文件清理。删除本轮四个隔离 WebView 缓存（约 79.22 MiB）的命令被自动审批拒绝，原因仅为 `blocked by policy`；未执行删除、未改用其它方式重试。证据、材料、最终视频和这四个缓存均保留，之前被拒绝的缓存目标也没有触碰。不能宣称所有本地缓存已清理。
