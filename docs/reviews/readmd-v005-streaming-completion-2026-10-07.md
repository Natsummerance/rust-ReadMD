# V0.0.5：流式补全、模型策略与速度复核

## 研究结论与边界

没有吸收市面上所有 Markdown 工具的全部优点。产品、官方资料、所读模块、自己的 Rust 实现与缺口分别列在[研究对照](readmd-v005-learning-and-autocomplete-2026-10-07.md)。最初 28 个产品、4 个组件是功能对照；本次进一步研究 Obsidian、Typora、VS Code Markdown、MarkText、Joplin、Zettlr、SiYuan，以及补全项目 Continue、Tabby。没有声称运行过全部上游产品，闭源核心也没有被阅读或复刻。

本轮具体参照 [Continue 的独立补全模型与上下文配置](https://docs.continue.dev/customize/deep-dives/autocomplete)、[CompletionProvider](https://github.com/continuedev/continue/blob/main/core/autocomplete/CompletionProvider.ts)，以及 [Tabby 的防抖实现](https://github.com/TabbyML/tabby/blob/main/clients/tabby-agent/src/codeCompletion/debouncer.ts)。学习的是缓存、防抖、取消、流处理和模型职责分离；未复制 GPL/AGPL 实现。自己的实现继续使用 Rust 内核、既有提供方适配和 CodeMirror，不引入新依赖。

## 产品行为

AI 设置的已有“高级参数”增加一个补全模型下拉项，默认折叠，提供自动优先速度、跟随对话、固定独立模型。自动选模限定在当前保存连接内，不换账号或凭据。固定模型失败会返回失败，不暗中换模型。VS Code 可通过 readmd.aiAutocompleteModel 单独指定，留空沿用共享策略。

桌面直接读取上游增量，以 SSE 传递清理后的灰字快照。若网关一次返回大段文本，仅对已经收到的文字做约 120 ms 内的逐步呈现；不捏造未收到的内容或首字时间。字素分段避免切坏 emoji，系统“减弱动态”与缓存命中时立即显示。Tab 只接受眼前可见文字、停止后续补全；一次撤销恢复原稿。断流、失败、Esc、失焦、输入法组词和上下文变更清除旧候选。未接受的候选不进入草稿、字数、预览或文件。

顺带修复：模型目录为空或暂时漏掉已选模型时，保存其它 AI 设置会清空对话模型。现在保留已选模型，刷新目录也不擅自切换它。

## 自己的 Rust 实现

| 层 | 实现与作用 |
| --- | --- |
| ai_completion.rs / App Runtime | Unicode 上下文、候选清理、短句提前结束、FIM、并发上限 2、内存缓存与模型观测。已成功候选优先，再按实测时延排序；未验证名称只作冷启动猜测。失败冷却 300 秒。 |
| ai.rs | 独立策略字段白名单保存；空目录时最多约 2 秒预算的模型发现，短期缓存，避免每次输入都取目录。 |
| ai_providers.rs | 复用 HTTP Agent 和现有 OpenAI/Responses/Anthropic 适配；补全候选自动新模型采用 8 秒传输预算，固定/当前模型采用 20 秒。 |
| server.rs | 同一 POST /api/ai/complete：桌面 Accept: text/event-stream，MCP JSON；候选缓存 32 项/60 秒；自动最多两个模型尝试，失败清除临时内容；不执行文件写入。 |
| ai-inline.js | 动态 180–650 ms 防抖、附近 3000/750 字上下文、24 项/60 秒内存缓存、真实流式灰字和可撤销接受。 |
| VS Code | 原生 InlineCompletionItem、250 ms 防抖、缓存立即返回、工作区信任与版本检查。宿主原生接口返回完整候选，不能把它描述成桌面相同的逐段绘制。 |

同模型优化包括连接池、较小上下文、128 token 生成预算、完整短句提前结束、流式显示、防抖和缓存。它们降低本地与传输开销，无法保证供应商排队或推理时间变短。客户端请求期限 35 秒；Rust 在流事件安全点检查取消与工作期限，阻塞读取仍受传输超时限制，不能承诺立即终止第三方生成。

## 当前反代实测

使用本机保存的 Antigravity 配置和合成中英文研究文字，日常配置散列前后一致。人工审阅了返回文字：能延续论证语气，没有伪造引文、重复后文或泄露推理标签。这只是小样本检查，不是模型质量保证。

| 模式 | 中文 | 英文 | 说明 |
| --- | --- | --- | --- |
| 原实现、当前 Gemini | 13.056 秒 | 12.808 秒 | 等完整回答，前次基线复用 |
| 自动、Sonnet | 首段 3.447 秒；完成 3.942 秒 | 首段 2.624 秒；完成 3.183 秒 | 分别 9、6 个真实 SSE 候选帧 |
| 同一 Gemini、新实现 | 首段 14.356 秒；完成 14.357 秒 | 首段 10.151 秒；完成 10.224 秒 | 反代分别只给 1、2 个候选帧；中文没有变快 |
| 固定 Sonnet、相同上下文 | 0.120 秒 | 0.118 秒 | 缓存命中，不能当作模型推理速度 |

固定 Sonnet 的前次独立真实请求首段约 2.845 / 2.785 秒、完成 3.496 / 3.603 秒。两次初版自动策略暴露旧别名不可用、成功模型又被未验证别名挤掉的问题，失败报告保留。最终改为观测成功优先，六个候选模式案例和缓存复用均通过。以上均为本机有限轮次，不承诺稳定达到同样耗时。

随后对离线构建的 release 二进制再做真实请求：自动选模中文首段 3.444 秒、完成 4.141 秒；英文首段 3.796 秒、完成 3.999 秒；缓存复用 0.051 秒。两组均为真实 SSE，日常配置没有变化。上述表格为调试构建的完整模式对照，不能和 release 复测混为一次测量。

Rust 全量：1888 个库测试、116 个主程序测试、12 个 xtask 测试通过，3 个明确忽略；最新调试与 release 均离线构建成功。前端补全 11 项通过，包含真实 HTTP SSE、部分接受、断流、组词取消、保存模型保护、三语言和两种紧凑窗口。VS Code 50 项通过。46 语言/2062 键同步通过；新增文案的简中、繁中、英文、日文人工撰写，其它语言采用英文回退，不能宣传为完整翻译。

四语言官网沿用原布局和动效，只更新既有介绍、元数据及演示视频；四语言 × 明暗八项播放检查通过，手机无横向溢出，53 个 canonical 页面与 feed/sitemap 验证通过。
