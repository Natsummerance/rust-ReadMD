# 第三批增量：PDF 公式交换文字与实际出版检查

本增量修复上一轮独立检查发现的真实问题，不改变第三批完整范围及各项未完成状态。轻量文字层由 Rust 内置 PDF 写出器实现，不新增 Office、系统字体、Python 或 Node 运行依赖。PDF 编辑继续使用按需安装的既有离线 PDFium 包。

## 原因与实现

原公式为矢量路径，虽然包在 `ActualText` 中，但没有文字对象。独立 MuPDF 检查读出了正文，却读不出数学字符。PDFium 的文字处理也围绕实际文字对象处理标记内容；不能仅检查 PDF 中存在 `/ActualText` 就宣称公式可复制。[PDFium 官方实现](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/core/fpdftext/cpdf_textpage.cpp)

新的文字层使用文件内自带、完全不绘制的 Type3 字形程序；每个字形有有效范围及 Unicode 映射。`ActualText` 支持的阅读器使用明确的交换文本，忽略它的生产转换器仍能通过 `ToUnicode` 恢复字符。按 255 字符分组，CMap 分批写入，不截断补充平面字符，也不需要安装额外字体。文字范围与公式位置、宽高对应，控制字符在单行交换文本中规范为空格，完全不可见的 Office 占位公式不建立复制目标。

行内公式与前后正文现在按原文顺序输出，避免把整行公式文字提前到正文之前；原图片占位也采用同一条顺序和宽度链路。可见公式仍使用原矢量路径，不以栅格图替代。

PDF 上下文复用现有选择区，交换文字只读。Rust 服务按当前修订记住对象身份，修改后清除缓存；未渲染页面按需检查。旧离线工作进程提供的专用字体身份也会被识别，防止正式包尚未更新时绕过保护。新工作进程额外拒绝独立编辑／删除不可见文字层。文本替换和删除均由服务端检查，不能靠隐藏按钮代替权限。

复制出的明确分式、根式、矩阵等 LaTeX 命令可完整粘回 DSL 草稿，转换为结构编辑。中途插入、引号字符串和原有 LaTeX 草稿保持原语义；未识别命令保留来源并禁止应用。继续使用草稿身份和渲染代次校验，正文只在确认后形成事务。

## 视觉复查发现的相关修复

实际 PDF 页码偏到纸张右边。装饰文字的输入已经是锚点，原实现又在一个整页宽框内对齐了一次；居中页码和右对齐页眉因此被再次偏移。现在只对锚点对齐一次，并用实际文字边界验证。

全局按钮样式覆盖了 HTML `hidden`，使 PDF 上下文的“替换图片”等无关动作仍然显示。PDF 面板现在明确执行隐藏状态，只读对象不显示无效修改、删除、字体或溢出设置。页面对象命中区使用真实内容几何，避免普通按钮的最小宽度使右边缘对象制造横向滚动；常驻命令控件仍保留 44px 区域。

修正隐藏状态后，原生回归暴露了此前被 CSS 错误掩盖的问题：文字溢出等后端拒绝发生时，加载流程已清空选区并隐藏页面，错误返回却没有恢复。现在失败后恢复原页面、原选区及用户尚未提交的文字、字体与溢出选项；错误仍显示，用户可直接修正。原生检查实际触发溢出拒绝，确认草稿保留、页面可见、修正成功，再走取消关闭与保存关闭。

## 验收边界与剩余项

普通 PDF 回归发现旧脚本在新的安装提示前等待用户，不能把这种暂停记成后端挂死。脚本改为安装实际 PDFium 包，并继续验证从功能入口安装字体。PDF 字体替换原来读取 Windows 的 Arial、SimHei 和 KaiTi 文件，现已改为校验后的 ReadMD 私有字体包，替换操作及重放期间持有资源租约。界面只提供明确的 ReadMD 字体名；旧恢复记录的三个名称映射为兼容别名，不再读取系统字体目录。

保留原字体的编辑不安装额外字体；明确选择替换字体时，在 PDF 上下文内提示用途、下载与安装体积、许可证。取消不修改正文或文件；安装后仅在原选择、页面与修订仍有效时继续，用户已经转到其他对象则丢弃旧动作。缺包时直接调用后端同样拒绝修改，不以按钮检查代替服务端保护。

本增量验证内置 Rust PDF 的 LaTeX 交换投影，不声称 PDF 带有完整 OMML 可编辑属性，也不声称 PDF/UA 认证。Typst／TeX 公式交换文字、所有字体完全嵌入、全 OMML 视觉语义、完整出版属性、原生 Word 往返及其他平台保持未验收。

现有普通西文 Base14 字体与本轮自带的不可见字形程序、内嵌中文／数学字体子集分别记录。原生截图属于 QA 证据，不作为沉浸式 4K 宣传材料。本次不发布版本，不替换用户已安装软件。

- 最终前端公式回归：**18 通过、0 失败／跳过／重试**，56.3 秒。含模拟故障的单元用例不计入生产验收。
- 正式 CSP、独立配置和合成材料的 Windows 原生公式流程：**8 条通过**。使用原分发 PDFium 与字体包，软件子进程 PATH 仅有 System32。
- 普通 PDF 原生流程：**10 条通过**。包括真实文字、图片与表单编辑，撤销／重做，保存重开，进程重启恢复，外部修改冲突，字节级历史恢复，溢出后原位纠错，以及取消关闭／保存关闭。当前工作进程与原分发包的用途分别记录。
- 缺字体包时后端拒绝修改；PDF 中选择替换字体后，原位提示体积，取消不改磁盘；实际从自有 `tool-ReadMD` 仓库下载字体包，校验、安装后自动继续原选区修改。字体下载约 **38.1 MiB**、安装约 **48.5 MiB**，不依赖宿主 Arial／SimHei 文件。此为本网络成功证据，不能替代完整网络矩阵。
- 独立 MuPDF 与真实 PDFium 检查 **3 份输出、38 页**：公式文字、希腊及补充平面字符、非零选择范围、真实搜索、1000 条公式逐条提取、每页矢量画面与文字层移除前后像素一致。相对旧样本，仅主动修正的页脚发生变化，正文及公式像素不变。
- 人工复查完整研究样本、纯公式页、36 页压力联系表及第 1／19／36 页；最终渲染文件与已查看版本逐文件摘要一致。另实际查看最终两种紧凑窗口截图及溢出草稿恢复截图。
- 资源、接线、46 语言／2580 键、无运行时 Python、前端包一致性与 diff 检查通过；语言键检查不等于语义审校完成。Python／MuPDF 只用于独立 QA，不是软件运行依赖。

最终源码、产物摘要、测试范围及开发失败见[不可变证据清单](../evidence/capability-upgrade/2026-10-10/batch3-pdf-math-text-manifest.json)，共 9 份记录，关联 R013、R028、R034、R059、R075，全部为局部证据。75 项账本仍为 16 待处理、59 进行中，未把任何大项提前标记验收完成。
