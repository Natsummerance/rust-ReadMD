# V0.0.6 第三批：单文件重命名增量

状态：**限定流程已实现并用隔离 Windows 进程复测，V6-31 和第三批整体继续进行中。** 测试使用合成文件、独立资料目录和离线构建，没有修改用户文档或保存私人连接配置。

## 交付范围

- 已打开且正文已保存的 Markdown／文本可在同一目录改名；保留磁盘字节、同一个持久审阅身份、待审原文及审阅历史。新路径取得保存授权，旧路径授权不能创建旧文件。
- 重命名采用身份及内容校验、受限 no-replace 移动和持久审阅意图；无法确定结果时保留待恢复状态，不自动覆盖或回滚不认识的文件。未启动操作通过持久终止记录阻断迟到重试。
- 已保存状态和会话写入需要明确确认；编辑中、待恢复和改名中阻止相关操作。会话写入采用单调版本与有界幂等回执，旧页面和旧进程不能覆盖已确认的新版本；启动恢复、重命名前后和关闭标签分别有持久化屏障。回执必须匹配本次调用、确切正文、版本及递增代数；确认丢失后重放遇到冲突时继续保留意图与编辑限制，不猜测文件未移动。恢复存储未确认前不向自动保存暴露重命名意图。迟到的刷新及 AI 审阅结果不能将标签重新指向旧路径。新打开的文件使用独立恢复键，旧会话保留旧键，以免重新创建旧名后覆盖另一文档草稿。
- 标签关闭屏障期间收到的打开和转换请求按顺序等待；连续关闭、新请求加入排队和已打开文件的嵌套刷新分别有受控回归，避免丢弃请求或自等待。
- 长时间的转换、批处理和 OCR 发布绑定预先观察的目标并在提交前复核；上传、图片格式和导出目标限制避免利用后缀写入其他 Markdown 文档。这些保护均不声称约束外部进程的最后瞬间竞争。
- 审阅数据库升级到 schema 4；不识别新 schema 的旧内核应拒绝打开，不能将旧内核与新内核混用来处理同一份资料。

## 尚未完成与风险

1. 同资料目录的旧会话迟到覆盖曾在[首次失败](../../.cache/capability-upgrade/v006-rename-session-race/first-failure-20261027/report.json)和[带待审修改的复现](../../.cache/capability-upgrade/v006-rename-session-race/first-failure-pending-20261027/report.json)中真实出现；新协议已通过上表中的真实进程复测。其边界是单一共享会话发生冲突时旧页面停止写入：各窗口的所有标签不保证同时包含在同一原生会话中。若程序绕过界面直接修改状态、关闭确认后另一实例又推进版本，受控前端测试仅证明当前标签、正文、恢复草稿及本地镜像保留，不能保证全局会话包含该窗口所有标签。真实桌面多窗口、故障注入和迁移仍需分别验收；旧内核或外部恢复配置不参加新协议。
2. 无强文件身份的文件系统可能打开文档却无法获得普通保存授权，资料目录不支持保护锁时也可能阻断读写；需设计可解释的兼容路径并分别在实际文件系统验证。单次重命名有 32 MiB 原始内容上限，审阅正文上限为 4 MiB；硬链接、重解析目录和仅大小写变更当前受限。
3. 资料目录锁只协调使用相同资料目录且遵守协议的新版 ReadMD。外部程序、旧版本和其他资料目录不会参与；现有目标的最后复验与替换之间不存在系统级原子比较交换。大资源复制期间锁持有时间仍需性能测量。
4. 多文件引用更新与回滚、全部转换／OCR／导出入口的完整竞争矩阵、真实 Windows 桌面桥、VS Code Extension Host、macOS／Linux／国产 Linux 原生证据及完整故障注入仍待完成。Windows 和 headless 结果不能替代这些验收。
