## 首次失败及修复

- 第一轮基线测试把文本 DrawItem 分组合并数量当作稳定语义；实际位移会让普通文字与代码拆组。改为逐字形来源、字体、横向 advance 和真实 PDF 原点验证，保留几何要求。
- 一次完整库编译暴露未限定 `json!` 宏，改为 `serde_json::json!`；中途另一次编译为纳入最终安全修复而主动取消，均不计验收。
- 随后的完整库为 2963 通过、2 失败、3 既有忽略。真实 TeX 回归是基线验证误伤没有该字段的旧容错样式，修复为显式声明时才执行相应严格校验，并新增防回归。另一失败是新 PDF 材料把链接子节点写到错误字段，改用真实 Markdown 解析生成输入，链接文字与命中区要求没有放宽。
- XML namespace/QName 注入、资源预算放在扩张之后和逐属性整树克隆风险已在源码审查中修复，并纳入自动测试。不能把仅保留原始扩展称为实现扩展语义。
- 原生 EPUB 前四次失败属于 QA：未展开完整预设列表、把源书名误认作固定目录标题、误按 Esc 关闭导出面板、在模态面板背后点主题按钮。改为可见控件操作与精确源标题／链接断言，原始文件和几何要求不变；第五次同旧 boot 通过，Reader 修复打包后再用最终 boot 完整通过。
- 基线首轮 PDF 检查器的弃用 `fitz` import 把警告写到 JSON 输出，改用现有 `pymupdf` 模块名。第二轮抓到**真实冷排版缺陷**：先包装普通文字偏移，再由 MathJax 把公式放进偏移祖先；热态修改正常，重启后公式被带动。现在 typeset 完成后只重建当前源码授权的文字包装，保留数学节点身份；新增 6 项回归和原生 `shiftedAncestor=false` 检查，几何阈值未放宽。
- Math 首轮在已成功把 β 改成 γ 后等待超时，是 QA 错把新可读源码要求为带 JSON 引号的字符串；修为精确 γ 值加“Edit symbol γ”无障碍标签，后续正文、扩展 XML 和恢复断言不变。

原始失败与成功日志分别保留，不覆盖或合并为“首次全通过”。
