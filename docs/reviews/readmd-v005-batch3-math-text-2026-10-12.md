# 第三批 MVP：连续公式字符的就地编辑

2026-10-12。沿用用户要求的第三批 MVP 优先级，补齐原始 Office 公式单个运行中连续字符的精确操作，不继续扩展完整 OMML 兼容范围。原 [MVP 合同](../design/v005-batch3-mvp-spec.md)和既有冻结证据保持不变；本记录单独绑定新构建及前端。

## 用户可见行为

在正文预览点击一个字符，现有就地输入框直接选中该字符；也可以进入公式后用鼠标或键盘选择字符。重复字母分别有身份，修改第二条公式不会替换第一条。数学增补字符和带组合音标的字符作为一个输入单元。支持替换成多个字符、撤销／重做、明确应用及取消。

保留同一个 Office 运行的字体、颜色、显式关闭属性及 XML 注释。局部输入保存在公式草稿中，应用前不改正文；应用后形成一次正文编辑，保存及重启仍可读。无效 XML 字符不能应用，草稿可恢复、改正或取消，不破坏磁盘正文。

本轮还修复快速取消后再次点击无反应的问题：浏览器可能将这次点击识别为双击，旧处理器取消了单击，而 Rust 渲染器没有对应的双击动作。DSL 公式现在在两种点击速度下都使用同一个就地编辑器；既有 LaTeX 双击源码面板继续使用自己的处理器。

## 实现与边界

Rust 渲染器给每个字符区域附加原始运行身份及 UTF-16 范围；不改变实际字形、间距和输出绘制指令。前端依据 [ECMA-402 的 Intl.Segmenter](https://tc39.es/ecma402/#sec-segmenter-objects)合并字素簇。字形轮廓内部的空白也通过源区域坐标命中，不要求点击实际墨迹。

共享数学服务新增 `replace_text_range`，校验基础修订、目标文本节点、UTF-16 边界与大小。仅重写最小可表达的 DSL 子树，并检查完整 XML 语义。源码范围不是字形顺序，重复字符不是全文字符串匹配。前一字符长度变化时，尚未刷新的点击目标随同一文本节点的长度差校正；前一操作已改写整个运行时拒绝猜测旧字符目标。

本轮字符功能针对标准单 `m:t` 的运行。非标准多文本节点运行保留整体运行编辑，不猜测第一个文本节点；任意嵌套、复杂文字整形、所有字体及完整 Office／UnicodeMath／MathML 认证仍未完成。后端 UTF-16 范围接口复用通用服务，本次不以 API 通过宣称完整 MCP／VS Code 界面矩阵已验收。
