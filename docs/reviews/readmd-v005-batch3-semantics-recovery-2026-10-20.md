## 保留的失败与修正

1. candidate-14 真实 stdio 证明显式函数没有生成 `func`，行／单元格对齐覆盖被忽略且没有诊断；旧任务库的真实流程证明未知叶子可能在原 WAL 删除后成为无法继续恢复的残留。这些是已修复的产品缺口。
2. 新 MathML 定向首轮有一项测试错误地把 display 输出当成直接 `oMath`，忽略外层 `oMathPara`。保留 34 通过／1 失败的日志，修正测试定位后原列属性、间距和编辑断言均保留。
3. 任务 verify-01 的前五个中断场景通过，第六个场景在建立哨兵前被 QA 的普通路径／`\\?\` 路径比较误拒。统一路径命名空间，补接受／逃逸反例后，用新目录执行 verify-02，10 个场景全部通过。没有覆盖首轮文件。
4. stdio-01 的 25 个语义检查和实际 DOCX 通过，随后 QA 错把 EPUB 发给不接受该格式的通用导出工具。修正为现有 `readmd_export_epub`、移除非法字段，并在发送前用真实 `tools/list` schema 校验。stdio-02 三格式全部完成。
5. 粘贴行为测试先在旧入口真实失败：4 项中 3 失败；补入口后 4 项通过。首次产品无 Python 检查也保留；只为独立 PDF 检查器增加明确、窄范围的 QA 白名单，产品未增加 Python 依赖。

这些失败表明，只检查解析器或单测数量不足以发现 UI 入口遗漏与工具契约不一致。本轮把生产处理函数、真实 stdio、真实文件、进程终止和独立读回接在一起；仍不能由这些有限范围的测试推出所有场景永远无错。

## 保留边界与下一步

- 不从普通的 `sin x` 猜测函数，也不把此次显式函数支持称为完整 UTN28。任意复杂宏、全部脚本语法及 Word 歧义仍有剩余。
- 冲突的逐单元格列对齐、跨格、复杂多脚标与 Content MathML 不冒充等价可编辑。空／不规则行保留已有导入形状，本轮未认证其三向重解析。未知或无法表示的输入保留原文、明确失败或诊断。
- 退役见证要求同卷硬链接；不支持的文件系统保守失败。未知文件不会因前缀相似而删除。本轮不是断电、远程卷、真实磁盘满或八小时认证。
- 安装空间检查是准入，不是操作系统硬预留；同卷其他 profile 或其他程序仍可能占用空间，写入失败继续依赖事务回滚。没有用注入的空间不足检查冒充真实低空间卷测试。
- Word／WPS／LibreOffice 的实际编辑重存、独立阅读器完整操作、VS Code Extension Host、非 Windows 原生和完整国际化语义审校没有新证据，不标完成；这些证据缺口不阻止本机可交付功能继续实施。

下一步继续补齐可实现的出版细节：P05／P08 的按章编号与重启、P06 的长注与重启策略、P07 的引用回流保护；每条先固定格式能力与往返合同，再实现和测真实文件。D04／D05 的 TeX 对应材料与正式分发仍独立跟踪，D06 的 OS 冷缓存条件明确前不认证。随后按既定第四批路径实施持久 AI 审阅闭环。完整第三批及发布保持未完成，具体范围见[47 项表](readmd-v005-batch3-remaining-audit-2026-10-15.md)及[总清单](../design/v005-remaining-work.md)。
