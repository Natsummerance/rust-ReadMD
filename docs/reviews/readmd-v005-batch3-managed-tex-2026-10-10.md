# 第三批增量：受管理 TeX 与当前功能内安装

日期：2026-10-10。对应 R029、R030、R075，状态仍为进行中。此增量不等于第三批完成、主程序发布或 TeX 能力包分发批准。

## 用户可感知的变化

- 正式 XeLaTeX／pdfLaTeX 预览、导出及 MCP 使用同一 Rust 受管理服务，移除宿主 PATH 查找。Word 和基础 PDF 继续使用自己的内置路径。
- 缺少字体、Typst 或 TeX 时，导出面板显示正常大小的状态卡片及“安装并继续”。提示不再放进微缩纸张，也不被放大预览遮罩挡住。
- 安装窗口说明用途、下载量、安装空间及许可证；取消保留原文与导出选择。安装完成后继续原预览，失败不得覆盖先前的 PDF。
- 真实就绪检查必须编译最小文档；存在路由、目录或引擎文件都不能替代可用性证明。正式目录当前仍只有 PDFium、Typst、OCR 和中文字体四包。

## 内核与生命周期

资源在同一安装锁内登记临时租约，然后释放安装锁进行完整校验。校验通过后才返回可使用的资源；失败自动释放租约和并发名额。这样允许两个工作任务校验，不把整份大运行库串行化；同时修复／卸载仍拒绝移除校验中或使用中的资源。此处的租约当前只在一个进程内生效，跨进程属于明确余项。

每次校验仍检查所有文件的元信息和全部字节摘要。超过 256 个文件的包最多四路并行访问，每路首次使用前及结束前核验祖先目录；不建立跨请求的“已验证即可永远信任”缓存。首次错误停止其他校验，调用返回前收回全部线程；调用者的取消上下文显式传入线程。取消与期限覆盖等待安装锁、资源校验、隔离工作进程和 PDF 驱动。

Windows 对同一文件只打开一次，使用不跟随最终重解析点的句柄检查类型与长度，再从该句柄计算摘要；读取期间拒绝并发写入和重命名。避免路径查询与第二次打开的重复访问，也减少“查询一个对象却读取另一个对象”的竞态。此项 Windows 句柄保护不作为其他平台原生证据。

Windows 流式解包在新建的空暂存目录上预设只读沙箱资源权限，随后文件继承。避免首次编译时再递归修改数万个文件的权限；不向私人上级目录授权。XeTeX 到 PDF 的驱动仍由 Rust 显式启动，并共用取消和期限。

v2 大包在解压前检查可信目录记录，归档完整摘要在流式读取后继续核验。卸载保留未知用户文件时，资源身份也必须失效，旧预览不能冒充仍可编译的当前引擎。

## 测试记录

最终功能增量证据已收口，宽范围需求仍为进行中。没有正式 TeX 分发批准；本地测试使用明确标记的未发布 QA 资源目录，不修改正式下载目录。

- 最终离线锁定 Rust 库：2,095 通过、0 失败、3 项既有忽略，140.61s。
- 相关前端回归：16 通过、0 跳过／重试；包含真实缺包 API、鼠标点击及 44px 安装目标。
- Windows 正式 CSP：11 条真实流程通过，包含 34,822 文件安装、两个引擎、实际 stdio MCP、预览／导出字节一致、保存重开和卸载失效。最终安装及探测 221,694ms；开始等待中文预览后 33,648ms。布局检查使用 WebView 的 1024×680、1160×820 CSS 视口，不能扩大为完整系统 DPI 矩阵。
- 实际就绪探测及进程故障检查：9 项通过。两个真实工作进程启动后，第三请求的拒绝耗时 0ms；取消至两进程退出 31ms；损坏资源、目录外输入及保留未知文件均验证。预先执行了真正的就绪探测，明确不认证冷态性能或跨进程租约。
- 三份实际 PDF 共三页由 PyMuPDF 独立检查并全部目检：字体嵌入、无栅格图像、中文／CSL 和 Unicode `σ` 文字保留；两种界面视口截图同时目检。
- 资源、接线、无 Python 运行依赖、46 语言 2,582 键集合检查通过；键集合不代替全语言语义审校。

不可变证据索引为 `docs/evidence/capability-upgrade/2026-10-10/batch3-managed-tex-manifest.json`，记录源码、二进制、原始日志及失败尝试摘要。没有发布主程序或替换当前安装。

完整双任务复测曾在 110 秒内无法进入编译阶段，记录为失败，不能用忙碌拒绝或取消快速返回代替成功。阶段日志定位到资源校验，尚未进入沙箱。单独 33,110,528 字节文件的摘要一致，读取 30/46ms；默认开发哈希 923ms，启用 SHA-2 的开发优化后 31ms。完整复测仍暴露小文件串行访问开销，因此增加有界并行，后续原生结果另行记录。这些耗时是当前机器和这两次构建的观察，不代表正式版本性能承诺。

一次完整原生安装已通过 34,822 文件校验、两引擎实际探测和提交，导入及探测用时 175,915ms；随后中文预览发现 `σ` 被送入传统 TeX 数学字体的实际错误。生成器已改用非 pdfTeX 分支的 Unicode Math 及随包 Latin Modern Math；同一真实材料的后续诊断请求成功输出中文、分式、表格和 CSL 引用。但该过程中另有冷态任务超时，不计为无故障验收：一次直接阶段追踪的校验为 108,666ms，几乎耗尽 120 秒总预算。不能以热态成功抹掉冷态失败。

固定 256 文件读取得到首次读取 2,005ms、紧接着读取 56/52ms；因后两组访问同一文件集，这只能证明明显的冷／热差异，不能作为两个查询接口的独立性能对照。Windows 后续实现使用单次句柄信息查询取所需属性和长度；完整 Rust、原生及性能结论仍按最终证据分别记录。

## 先前为什么没有发现

先前的小资源包不足以暴露 34,822 文件校验、全局锁和 Windows 权限传播的组合开销。此前部分界面回归只验证缺包按钮存在，没有真正用鼠标点击，因而遗漏了预览遮罩和微缩区域的交互阻挡。宿主碰巧安装 TeX 也会掩盖受管理服务未接通的问题；仅含 ASCII 公式的 TeX 样本又遗漏了 DSL Unicode 符号与传统数学字体的不兼容。本增量分别补充真实大包、实际点击、受限 PATH、Unicode 数学、工作进程退出以及实际 MCP 传输，保留失败尝试，不将它们计为通过。

## 缓存分类

- 固定维护输入及源码审查材料：保留用于补齐审查和重建，未审查输入不用于正式分发。
- 原始与 QA 流式包：集中在本任务缓存，区分公开批准与 QA；文件头不同的 QA 包不替代正式包。
- 运行库：大量基础文件通过硬链接复用，逻辑长度不等于新增实际磁盘用量。
- 隔离原生报告、独立检查及失败日志：保留；成功卸载后的测试配置可在最终收口时按清单整理。
- 异常退出遗留暂存：集中标记，待最终清理；不对用户书籍、安装目录或历史缓存执行批量删除。
- 离线构建产物：第三批仍进行中，继续复用；不为本增量清空共享构建缓存。
