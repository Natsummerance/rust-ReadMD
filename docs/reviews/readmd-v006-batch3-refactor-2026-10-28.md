# V0.0.6 第三批：多文件重命名引用更新与失败回滚

本轮限定交付是 **Windows 受支持资料夹内的 Markdown 重命名事务**，承接此前单文件改名、保存授权和持久审阅迁移。第三批整体继续进行中；没有发布、推送或修改用户实际文档。完整规格见[安全协议](../design/v006-batch3-rename-refactor-safety-spec.md)，可复算摘要和最终门禁见[证据摘要](readmd-v006-batch3-refactor-evidence-2026-10-28.json)。

## 用户流程和实现

1. 明确打开资料夹，再重命名已保存的 `.md`／`.markdown`／`.mdown`。软件扫描该资料夹的受支持文档，展示逐文件、逐链接差异；没有明确资料夹授权时继续使用单文件协议。TXT 不进入链接改写。
2. 取消预览不产生修改；确认前重新取得计划与审阅状态。任一参与文档正在编辑、有未保存内容、仍有 AI 任务写入或处于待恢复状态时，拒绝提交并保留正文。
3. Rust 在保存锁与资料目录进程锁内复核扫描清单，为全部原件取得 Windows 句柄租约，预演审阅映射和空间预算，再记录持久意图、保留原件并逐个发布暂存结果。全组审阅及路径在一次 SQLite 事务中确认。
4. 正常成功后，标签、正文、文件侧栏、同一审阅身份和新路径保存授权一起更新；会话 CAS 确认成功才解除屏障。引用文件可立即编辑、撤销／重做、保存、关闭并重开。
5. 中途失败或进程退出后，新拥有者按记录的文件身份、字节与受支持元数据恢复。能安全恢复的文件先回滚；第三方占位不覆盖，不认识的对象不删除。未解决部分保持 `recovery_pending`，相关写入继续受阻。

链接改写保留相对路径写法、空格／Unicode／百分号编码、查询串、锚点、标题与原换行，覆盖内联、图片、引用式定义、明确的 wiki 链接及自引用。代码、外部 URL、普通正文不替换。不能安全定位的相关 HTML、歧义 wiki 或文件别名作为诊断阻止提交，不猜测目标。

审阅库由 schema 4 升为 5，保存全组意图、全路径预留和幂等回执。原文、文档 ID、检查点与不相交历史保留；与链接改写相交且不能可靠映射的待审修改或历史在提交前拒绝。旧内核不能和新内核混用同一资料目录。磁盘原始字节修订与规范化审阅修订分别核对，避免 CRLF／BOM 被误判成另一份正文。

## 真实验证与受控验证分开记录

- **真实 Windows 文件系统及进程：** 真实文件句柄、同目录暂存、无覆盖移动、UTF-16 BOM／CRLF、文件锁、元数据不兼容拒绝、第三方占位保留、审阅库与重启恢复。父测试还启动真正子进程，在文件发布中以退出码 77 结束、不给析构机会，再由新拥有者恢复；这是进程中断证据，不等同于硬件断电认证。
- **受控故障：** 在内部单元测试的每个文件发布步骤后返回错误，核对所有原始字节、备份与审阅状态；运行时 API 不提供故障注入开关。预算耗尽使用受控额度，不冒称真实磁盘写满。
- **实际服务：** 最终二进制运行六个 HTTP 检查，覆盖只读预览、新引用导致计划过期、全部引用和自引用更新、精确编码、幂等／异参拒绝、旧进程旧路径保存拒绝、新路径编辑保存、重启审阅恢复及持久终止后的迟到请求拒绝。
- **实际前端：** 正式 CSP、严格令牌模式与 headless Edge 下通过五个完整流程；使用真实生产 boot 和 `apiFetch`，没有 fetch 鉴权替身。仅系统目录选择与原生桥采用合成 shim，不冒充 Windows 原生窗口验收。确认框在 1160×820 和 1024×680 检查边界、滚动、44px 操作及焦点，另检查文件侧栏立即改名。
- **公共回归：** 最终 Rust 库全套 4,286 通过、0 失败、7 项既有忽略；113 个前端与工具文件共 1,653 通过、0 失败、0 跳过。命令、二进制／boot／源码摘要及原始日志位置在证据摘要中登记；原始证据放在本机忽略目录。语言键结构检查通过不等同于 46 种语言全部完成母语审校。

最终浏览器报告保留一个后台 `/api/update/check` 的 403：最小原生 shim 未提供 `check_update`，触发旧的未带鉴权 fetch 后备分支；实际原生桥源码使用本次已修复的 `bridgeHeaders`。这不是更新功能通过证据，也不删除该失败；本轮全部重命名和目录请求成功，页面 JavaScript 错误为零。截图仅存本机忽略目录，含合成文件的实际工作区路径，不作为匿名宣传资产。

最终候选二进制 SHA-256 为 `cf09d1ec466f67df692ff8b9fe4ddbfdf6679b4b25cd6e161879ce41c9c61e52`，boot 为 `8bf3b28ca9dfcd4c220a0864c80600c3edcbefd7e99b11faa25f4a2376cfd8bd`。所有构建复用共享目录、`--locked --offline` 和 `CARGO_INCREMENTAL=0`，没有增加依赖或代理独立 target。

## 首败与修复

原候选真实复现“源文件已改名、两个引用仍为旧链接”，原报告保留。后续首次原生测试暴露 NTFS 名称隧道继承创建时间，导致原件正确但强身份复核失败；修复仅在持有句柄的文件 ID 和字节完全匹配时校正该时间，再做完整核对，不放宽文件身份条件。

严格模式浏览器首败还暴露 CSP 禁止的旧内联令牌引导失效。现在前端与原生桥都从安全 meta 读取实例令牌；显式 LAN 值仍优先，CSP 不放宽。新增接口与旧敏感接口的尾斜杠别名一并要求 app token，缺失或错误令牌在磁盘副作用前拒绝。首次 bootstrap 4/6 结果仅在工具记录，不伪造原始落盘日志。

首次全套 Node 中两项既有样式保护测试将 AI 样式结尾误当作永久文件结尾。修复方式是只剥离本次有明确边界且所有选择器均为 `.document-refactor-*` 的新样式块，原有受保护字节摘要保持不变。首次 HTTP 的恢复响应 envelope 断言、首次浏览器的最小改动片段断言与诊断用鉴权 shim 均明确区分，旧失败及中间报告不删除；仅最终无鉴权 shim 的流程作为本轮前端通过证据。

## 边界、隐私与下一步

- 受支持范围为本轮明确扫描的 Markdown 文件、同目录同扩展名改名与普通受支持 NTFS 状态。硬链接、重解析／大小写别名、额外数据流或不能安全保持的权限／属性明确拒绝；不声称完整 SACL、所有文件系统或所有文档语法兼容。
- 多文件发布不是文件系统级原子事务；其他应用可能观察到中间状态。最终清单复核后，外部程序仍可能在非参与文件新添引用；不能把 ReadMD 参与者屏障说成所有外部程序的全目录锁。
- 未登记身份的断电残留、NTFS 时间校正中断和外部占位可能要求人工恢复。保留原件与阻止误写优先，不靠删除第三方对象强行完成回滚。真实断电、实际磁盘满、完整权限矩阵、原生多窗口及非 Windows 等价批量租约尚待验收。
- 本轮使用合成文档和隔离资料目录，不复制私人配置、不调用真实 AI，也不生成宣传素材。凭据检查只记录结果和摘要；既有录屏资产与其中历史隐私问题保持独立待办，没有随本次推送。
- 下一步继续 V6-31 的真实桌面及其他格式边界，并推进 V6-32 可视表格、V6-34 原排版导入／损失报告、V6-35 PDF 表单／扫描和 V6-36 受管媒体；协作审阅、其他平台和长期压力保留原待办。本次不宣布第三批整体完成。

| 私有配置及目录链接 | 未复制、未随清单读取内容 | 分类遍历跳过私有目录与链接，不能把链接指向的资料作为可清理缓存。 |

历史分类有两项遍历错误，上述合计不作为精确物理占用值；同一资源的硬链接也可能重复计入逻辑大小。后续清理应先区分可重建的测试副本与仅有的离线材料，不能因为目录名含 cache 就整体删除。
