# 第三批：同配置跨进程传输预算

接续[持久化事务验证](readmd-v005-batch3-durable-transactions-2026-10-11.md)，属于 B3-52 的独立增量，未发布或替换用户安装。

## 实现与边界

此前上传最多四项和总声明长度限制只查看当前进程内的任务表；多个桌面、MCP 或安装器进程可以各自取得这份预算。现在 Rust 公共协调层使用固定 OS 名额，所有遵守 `transfer-v1` 的进程共享同一配置的预算。

- 最多四项活动传输；压缩输入按 64MiB 向上取整，总预留最多 2GiB。因此可能略早于精确长度上限拒绝，绝不向下取整超额。
- 分块上传在建立目录/正文前占用，直到实际安装线程释放最后一个上传状态；重复开始不重复占用，重复分块不重复写入。
- 下载、文件导入、直接上传和安装器 CLI 使用同一服务；下载的预算覆盖联网、验证、解包、探测和提交，而非下载结束便归还。
- 分配锁只覆盖短暂的名额分配，不覆盖联网、校验或安装。失败归还已经取得的部分名额，取消通过原有任务状态释放；拥有者终止由 OS 回收不继承的句柄。
- 固定空锁不删除、不截断；非空、重解析或异常路径拒绝且保留。引擎执行、无关配置的预算分别独立。

这是活动压缩输入预算，不是所有展开引擎、未知文件、恢复原件或历史缓存的磁盘总配额。旧客户端尚未采用此协议，隔离与版本迁移仍是独立待办，不能据此声称旧版本混用安全。

## 验证状态

新增六项回归覆盖数量/字节预留、向上取整、部分失败、异常锁、实际 OS 拥有者崩溃/句柄不继承、各入口拒绝、重复开始及取消。能力相关专项 **68 项通过、0 失败**；最终完整内核库 **2,142 通过、0 失败、3 项既有忽略，142.52 秒**。最终锁定离线构建通过，未添加依赖。

独立原生工具 `capability_transfer_process_probe` 的 **5 项流程通过**：两个实际拥有者各声明 1GiB，超额开始/下载/导入拒绝；退出一个只释放自己的预算；随后实际导入正式字体包、导出 PDF、重开服务；四个拥有者占满数量时各入口拒绝；实际分块重复、取消及再次开始通过。API 忙碌拒绝实测 8–42ms，拥有者取消退出均 21ms。2GiB 场景测试声明预算，不传输 2GiB 数据；不模拟包安装或 PDF 输出，不等于桌面/MCP 传输认证。

`capability-transfer-cli.cjs` 的 **3 项流程通过**：两个 API 拥有者占满预算后，实际 `--install-capability typst` 命令返回 `capability_install_busy`，无下载/安装产物；两拥有者正常取消清理。CLI 从启动到拒绝 1,760ms，包含应用启动，不计为 API ≤200ms 的证据；取消退出 11／15ms。均为单次观察，不是 P95 或长时压力统计。

同一最终主程序正式 CSP 字体/出版 **6 项回归通过**，覆盖缺包取消、实际离线选包安装继续、两个真实 PDF 引擎、损坏修复和重启；中文字体、矢量公式和实际分页截图已独立检查、目检。

首次额外 PDF 检查错误地要求所有字体资源都提供可提取字体文件，实际先遇到标准 PDF14 页码字体，另有 Type3 数学 Unicode 交换层；原失败诊断保留。后续按真实结构核对：中文正文嵌入静态 TrueType 字形，数学层具有字形程序和 Unicode 映射，公式有真实矢量路径、无整页栅格替代；未嵌入的 Helvetica 仅用于数字页码并单独报告。没有把这份通用 PDF 记为“全部字体嵌入”或完整学术输出通过。

原始失败及最终源码、构建、工具、正式包身份分别归档，见[传输预算证据](../evidence/capability-upgrade/2026-10-11/batch3-transfer-budget-manifest.json)。最终 148 个工作区 Rust 文件摘要为 `7d0b3ce4685b3e5ef11ee2e85a055bc7e7c3d401b30003f97f211330a427561e`；完整库仅覆盖内核，不宣称 xtask 或全工作区完整测试通过。较早 143 文件快照仅含内核，原生诊断文字随后脱敏；最终快照和构建使用脱敏后的工具。

无新增依赖、UI 或译文；构建锁定离线，沿用同一 target 并关闭增量编译。前一事务阶段的 TeX 7 项与 OCR 8 项等证据保持其原构建身份，不挪作本次新二进制的测试结果。
