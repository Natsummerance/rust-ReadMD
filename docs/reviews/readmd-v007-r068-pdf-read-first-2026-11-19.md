# V0.0.7 R068：PDF 原版阅读入口

本轮完成 R068 的 PDF 产品子流程。普通打开、原生/浏览器拖放、直接 `loadFile` 调用先进入既有 PDFium 工作区的原版阅读模式；初始文件分流由 `assets/app.js` 调用同一 `openDocumentPath`。外部 Office 文档原排版、统一外部文档会话和完整 R068 验收仍需继续。

阅读模式保留页面渲染、翻页和安全链接导航，隐藏对象编辑控件并在动作边界拒绝编辑、撤销、重做和保存。只有明确选择“编辑原 PDF”才显示原位编辑；既有“编辑 PDF”功能入口仍可直接进入编辑模式。当前文件名出现在工作区标题，编辑和提取按钮独立换行，不挤入原有翻页工具栏。

“提取 Markdown”先通过当前 PDF 的保存/放弃/取消和后端关闭事务，再读取最后保存的源文件。取消或保存失败不调用转换；提取结果等待虚拟文档切换后才返回成功。PDF 打开失败、能力不可用或安装取消均不自动转入 OCR/Markdown。密码重试保留阅读模式，切换另一个 PDF 不沿用前一文档密码。

PDF 打开请求顺序执行，切换前关闭自己的旧会话。能力准备、打开或提取未完成时，应用关闭保护返回未就绪，避免提前退出。底层 Markdown 编辑器保留并同步现有草稿；PDF 阅读不伪装成文本标签写入 Markdown 会话，已有 PDF 修改和恢复草稿仍使用原有独立保存/关闭协议。当前仍是单个 PDF 工作区，不宣称具备跨重启的 PDF 阅读标签恢复。

新增六个词条已追加至全部 46 种语言，保留原文件现有内容及其他任务新增词条。键集、非空和新增整句未复制英文的检查通过；这不等于 46 语种均由母语使用者完成语言验收。

验证使用 `tools/test/v007-pdf-read-first.test.cjs` 的合成 API/DOM 控制器检查，以及既有 PDF 图像选择、延迟删页确认和能力面板调度回归。覆盖原版路由、不可用无转换、保存失败/取消、顺序打开、关闭保护、密码隔离及提取完成边界；同时执行 JavaScript 语法和 `tools/check-i18n.mjs`。这些检查不冒充真实 PDFium 或原生平台验收，本轮未启动 Office、加载模型、安装用户资源或发布软件。
