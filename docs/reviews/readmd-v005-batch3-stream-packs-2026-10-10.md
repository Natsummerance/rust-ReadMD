# 第三批：大型能力包的流式基础

本增量继续落实“核心依赖随软件、重型引擎按需交付”，没有新增常驻 UI。完成了二进制 v2 包的离线维护装配、Rust 有界暂存解包及真实排版引擎的格式互通验证。正式安装服务、功能入口和安装器目前仍使用既有四个 v1 包；v2 尚未上架，第三批和 V0.0.5 尚未完成或发布。

## 为什么调整

已有 PDFium、Typst、OCR、字体包能够在当前功能内提示用途、体积、许可证并安装继续；同一目录用于安装器预选和插件管理。完整 TeX 展开超过 500 MiB、两万文件，不能套用 64 文件的小包清单，也不应把整个归档变成 base64／JSON 常驻内存。

新格式只允许可信应用清单中的固定文件。按顺序处理单成员 gzip，64 KiB 缓冲核对未压缩长度、CRC 与 SHA-256；文件数、展开总量、单文件和清单均有限制。绝对路径、上级跳转、大小写重名、Windows 保留名、父文件冲突、重解析目录、压缩尾部及拼接成员均拒绝。

解包返回本次新建的集中暂存目录，不返回“已安装”。旧安装未被修改；失败或取消只释放当前暂存。统一能力服务还需持有资源租约、实际探测、原子切换及回滚，不能把格式基础当成生产安装完成。

维护工具采用两遍流式压缩：第一遍核对原始文件并锁定压缩长度，第二遍再次核对并写包。只离线操作，不执行引擎或包脚本；输出独占提交，拒绝覆盖已有归档。显式 `--write-lock` 是维护者准备步骤，不是分发批准。格式、命令与剩余验收见[实施合同](../design/capability-pack-v2-spec.md)。

## 实际验证

证据、源码摘要及探测程序身份见[索引](../evidence/capability-upgrade/2026-10-10/batch3-stream-packs-manifest.json)。

- 完整 Rust 内核：**2054 通过、0 失败、3 项既有忽略**。新增五条检查覆盖 97 文件和碎片输入、危险路径与冲突、截断／损坏／尾部／重复成员、预算和解压超额、取消暂存释放。不是 4 GiB 容量或八小时压力认证。
- Node 维护工具：**4 通过、0 失败／跳过**，检查同锁复现、未准备的压缩锁、输入摘要不符、旧输出保留和路径保护。测试仅使用新建的合成目录，结束后清理该目录。
- Windows 原生：使用应用已有固定锁中的真实 Typst 0.15.1 原始三文件，重新装为 v2，**23,523,775 字节下载、52,518,469 字节展开**。Rust 校验并暂存，随后用相同字节的引擎实际生成可搜索 PDF；系统字体禁用，包暂存释放成功。
- PDF 样张经独立 Poppler 栅格化并视觉检查，文字及公式可读，无裁切。它是短测试材料，不是宣传演示、复杂学术样张或中文出版验收。

这一真实包证明维护工具与 Rust 的格式互通，不证明整套 TeX、浏览器大包上传、原生安装向导或 macOS/Linux 工作流已经通过。没有把新测试包发布到工具仓库，没有改变现有资源包或用户安装。
