# 第三批增量：公式字体选择与电子书字体携带

第三批仍进行中。本次是 Word 主题字体和普通文本运行的明确子集，没有完成全 OMML、完整出版或实际 Word 往返。没有替换已安装软件、提交、推送或发布。

## 实现

- Rust 解析实际 DOCX 的主题／设置关系，按需携带 `drawing.fontScheme` 和 `word.themeFontLang` 可读上下文。八种主题令牌、补充脚本字体及语言选择进入有效副本，原始请求不变；缺失主题或空区域字体保留生产者后备值，不搜索宿主字体。
- 修复同层字体名和主题令牌的优先级：同层主题优先，较高层直接字体仍覆盖较低层主题，结果不依赖前缀或属性排序。
- 普通数学文本按 Word 的 ASCII、High ANSI、东亚及复杂文字槽位选字，处理东亚提示、中文语言、`cs`／`rtl` 显式关闭和 Times New Roman 特例。完整字符集规则及复杂文字整形仍未认证。
- 使用核心 STIX 数学字体及受校验、带租约的私有字体包；Sans／Serif 常规和粗体使用真实字形。斜体目前是合成倾斜，SVG 边界与 PDF 路径共同处理倾斜，不能宣称真正斜体字面已完成。
- MathML 不请求任意宿主字体。EPUB 按实际使用的私有字体／字重携带文件、OPF/CSS 声明及原始许可证；缺字／替代明确报告。本材料用了四字面，电子书约 30.8 MB，字体子集尚未实现。
- 安装／卸载后失效 DSL 及旧元数据缓存，迟到结果不能复活旧缓存。两个新提示键在 46 个语言文件有各自译文，没有英文回填；完整母语语义审校仍待完成。

## 实测及原始失败

最终完整 Rust 内核 2287 通过、0 失败、3 项既有忽略，139.47 秒；严格 CSP Edge 8 通过、零自动重试，50.8 秒。正式 CSP Windows 原生 7 组通过：真实 DOCX／字体安装、语言改变后的实际轮廓、第二处重复公式编辑、一次撤销／重做、保存重开、真实上传协议／缓存事件及宿主重启。同构建回归为主题色原生 6 组、MathML／EPUB 原生 4 组、主题色 stdio MCP 4 组。

实际 EPUB 经独立 EPUBCheck 5.4.0 验证，零致命错误／错误／警告；fontTools 核对四字体族名、400／700 字重、中文映射和锁定摘要。独立 PyMuPDF 检查实际 PDF：1 页、96 份矢量绘制、零栅格，中文及希腊交换文字正确。Poppler 栅格、原生深／浅主题截图已目视检查；Symbol／ArialUnicode 显示字体警告保留，不算全字体认证。

失败没有删除或自动重试掩盖：

- 首轮全库的 MathML 断言仍要求无属性标签；已增加合法字体属性，测试同步验证新输出及内容保留。
- 次轮全库的暂存 Drop 测试误要求 100ms 内完成全部清理。测试按既有“限时清理＋下次受保护访问恢复”合同修正，生产期限没有扩大。
- 两次原生文件选择自动化失败：OS 选择器没有浏览器 CDP filechooser，直接 CDP 设置文件也超时。最终以真实包字节分块构造标准 File，调用真实上传服务、Rust 校验和安装；未模拟后端。**OS 选择器操作仍未认证**，不能用该集成证据替代。
- 独立 PDF 首次错误假设每字对应一份绘制，阈值 100 不合理。改查真实路径边界、零栅格、中文／希腊映射和字体摘要；96 份绘制如实记录，不用数量冒充质量。

全仓库无 Python 检查仍有 10 条历史 QA 依赖违规，未增加或豁免。独立 Python 检查仅在缓存 QA 运行，不加入应用运行时。完整前端、长期压力及全平台工作流没有由本次专项替代。
