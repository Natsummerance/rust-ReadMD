# V0.0.6 第三批：外部文档转换预览与资源事务

## 范围

此切片修复二进制文档直接打开和旧的路径式导入接口的磁盘副作用。它复用现有转换器及资源暂存、显式保存机制，不代表原排版浏览、全部格式转换或批处理已经完成。

## 合同

- `GET /api/file` 提取二进制文档时，正文和图片仅作为内存结果及受管资源返回；不得在源文件旁创建 Markdown、资源文件夹或覆盖同名文件。图片暂存失败不得返回缺图成功。
- 界面把转换结果作为独立、未保存的 Markdown 文档，并携带资源句柄及原文档身份。保存应走现有另存流程；不得把 Markdown 内容写进源二进制文件。
- `POST /api/import/process` 的旧 `paths`/`files` 合同对可转换二进制文件返回待保存内容和资源，而不是写入推测的同名 Markdown；可读文本仍返回其真实路径。响应明确包含 `saved: false`、源路径、建议路径和待保存计数。
- 既有明确执行保存的单文件转换与批处理入口不改变其合同。取消、失败、重复预览及已有同名文件不得改变源目录中的任何字节；暂存资源在受控数据目录按内容复用。

## 验证

先对旧候选记录首败，再用隔离配置启动真实 Windows 内核及正式 CSP 下的无界面浏览器：自建包含正文和图片的 DOCX，保留既有同名 Markdown 哨兵；对两条路径及真实界面分别检查源目录和文件摘要、资源解码、重复调用、非二进制兼容；将暂存内容显式保存为新的 Markdown 并重新打开，验证图片资源与源码一致。无真实 Word 互操作或原排版预览的证据时不得宣称该部分通过。

旧候选分别实测产生源文件旁 `Report.assets` 和改写同名 Markdown；首败报告保留在本机测试目录。新候选通过 6 项检查，包括暂存目录被占用时显示失败、不打开缺图文档。测试生成的 OPC 文档另由独立 DOCX 解析器确认含两段正文和一个内嵌图片；这不是 Microsoft Word 的应用互操作验收。第一次新候选的保存检查误把 URL 百分号编码直接当文件名，保留该测试脚本首败后修正解码；产品代码未为此放宽检查。
