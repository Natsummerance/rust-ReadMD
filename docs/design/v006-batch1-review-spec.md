# V0.0.6 第一批：持久正文审阅

实施日期：2026-10-27。上游规划：`v006-execution-plan-2026-10-26.md` 的 V6-11～V6-17。代码基线为已发布 V0.0.5，不在本批发布或变更正式版本号。

## 操作合同

普通正文的完整出口：AI 分别修改同文 A、B → 用户手改 C → 同意 A → Ctrl+S → 退出／重开 → 撤回 B。A 与 C 保留，B 恢复原文；撤回本身可撤销、重做，已同意的 A 也仍可撤回。

保存与审阅是独立状态：保存当前可见正文不会自动同意待审修改；普通 Markdown 不携带审阅按钮、高亮或数据库内容。原文、候选、决定和补偿操作存入应用数据目录的 `review.sqlite3`，不在文档旁创建副本。打开普通阅读文件不初始化审阅会话；进入编辑或明确使用 AI 审阅后按需创建。重开已有会话时恢复未保存工作内容，并显示底部的上下文审阅入口。

本批约束新增审阅为 4 MiB 正文、单请求至多 4096 处局部修改、单文档至多 4096 个审阅块，存储逻辑预算 64 MiB；4096 不是普通输入或保存的终身次数上限。既有普通大文件阅读／保存上限不变。额度不足拒绝新增操作并保留工作内容、待审原文及已保存文件，不淘汰未审阅依据。

## 内核和边界

| 部件 | 责任 |
| --- | --- |
| `review.rs` | 稳定文档身份；单调 generation；独立 review_revision；UTF-16 编辑、锚点、人工接管、同意／撤回、持久撤销重做、保存检查点 |
| `review_store.rs` | 已锁定 SQLite，事务与 FULL 持久性；schema 迁移；幂等回执；不可变原文共享与容量限制 |
| `review_api.rs` | 当前应用令牌和确切文件授权；实际磁盘摘要／编码／换行；保存意图、资源与公式改写映射；取消提交点 |
| `ai_review.rs` | 原生 `read_document` → `propose_review` 调用；已授权快照与写入范围；OpenAI 兼容、Anthropic、Gemini 协议；参数、轮次与输出预算 |
| `review_transport.rs` | 有界响应读取、请求并发和等待取消；网络线程不持有文档或存储句柄 |
| 前端适配器 | 顺序发送 CM 事务；合并未发送的连续输入；投影 Rust 回执及上下文控件；过期／重叠结果保留双方内容 |
| 选区适配器 | 从解析器位置与 DOM 偏移映射普通正文，重复文本不做字符串重绑定；拒绝不精确投影的直接修改 |

公开接口仅允许 open、resume、read、edit、propose、resolve、undo、redo、discard。保存 prepare／commit／abort、内部路径查找、原文保留集合和回执查询不向前端暴露；`system` 改写来源仅供受信任的保存链使用。MCP 的两项审阅工具调用相同服务，并保留明确的副作用确认合同。

收到同一 call_id 和相同参数时返回原回执；不同参数拒绝。回执不为每个按键复制全文，通过持久反向映射和事件补丁重建历史结果。不可变原文按摘要共享，schema 1 的完整回执兼容读取；较新 schema 拒绝降级改写。

generation、review_revision 和事件序号均单调增长，检查 SQLite i64 上限后递增，不能循环复用。单次修改与审阅块数量的4096上限不能应用到文档终身事件计数，也不能在4096次操作后永久阻止保存、撤回或放弃。

## 保存和故障处理

1. 刷新编辑队列并校验 generation、review_revision 和真实磁盘修订。
2. 用资源物化与数学迁移提供的精确、顺序编辑计算最终内容。禁止用首尾差异形成的巨大替换跨过未改正文。
3. 在 SQLite 保存意图、预期编码字节摘要、目标路径保留和完成所需峰值额度，然后原子写入文件。
4. 实际字节匹配预期后，提交编码意图及保存检查点。按已确认的编码提交，不能因 ASCII 自动探测为 UTF-8 而把成功写入误判为失败。
5. 重开时对账：旧文件表示尚未提交；预期字节表示补交回执；其他文件保留为需要恢复的冲突。文件已提交但数据库提交失败时保留意图，不能误报回滚。

显式放弃只恢复已保存检查点，不撤销保存前的待审记录和兼容决定。丢弃请求期间的新输入保留，关闭流程中止。退出／安装更新再次刷新队列并比较最终页面快照，设置写入期间的新输入不能悄悄被关闭。

通用自动草稿携带其最后已确认审阅水位：document_id、generation、review_revision、revision。重开时，水位精确匹配而正文更新的草稿，以受 CAS 保护的人工事务补交；写入失败保留可见输入及同一请求，允许重试。水位缺失或不同则不能根据“dirty”或时间猜测先后，必须先把通用草稿存成集中恢复点，再选择数据库视图。保留失败时不覆盖、不清理旧草稿，后续手工输入也参与保全。

待审原文、候选、操作历史中的图片引用参与资源保留，包括原目录及另存目标目录的相对引用。保留引用不等于已经搬迁隐藏原图：本批对含未撤回原图相对路径的跨目录另存，明确返回本地化的 `review_asset_relocation_required`，在文件、资源和保存意图提交前停止；原文、旧目标及审阅记录不变。同目录保存、普通文字另存及可见图片的既有物化链路正常使用。完整图像审阅搬迁留在图像资源批次。

## 真实 AI 合同与界面

模型必须先原生读取本会话的未保存正文，再提供独立局部编辑；模型参数不能切换文档或扩大授权范围。前端以 Rust 的实际提交回执更新正文，不解析聊天里的 JSON 当工具调用。选择普通渲染正文时默认限定选区；源码编辑可提供精确 UTF-16 范围。公式、代码、表格及变形投影无法精确映射时保留只读／安全副本流程，不能偷偷改为全文写入授权。

用户选中的动作模板从已有服务端 Skill 注册表加载，调用前冻结指令、必需变量规则和语言摘要，纳入重放身份。缺失、禁用和无效模板在网络请求前失败。以真实源内容和选区校验模板，发送时以原生 read_document 结果指引替代重复全文；模板指导在读取之后进入三种协议，核心工具与授权规则始终优先。正文中的占位符只作为数据，不执行第二次替换。

AI 执行期间的后续手工输入按精确映射重定位；重叠时保留候选、原文和手改并提示比较。取消在持久提交点前生效；网络晚到也不能绕过 generation 与取消检查。完整自主 Harness、64 轮任务、导出快照与接受并导出仍按第二批实施。

人工接管块不能直接用旧 AI 原文覆盖。比较菜单提供显式“保留我的修改”，只同意当前手改，不改正文；原文、候选、接管依据及撤销历史仍保留。选区在后续精确事务中重定位，追问沿用修改后的同一对象；失配或不精确时保持只读选区，不悄悄扩大到全文。

原生 AI 请求只解析已保存连接，禁止凭据跨连接借用、调用参数覆写地址或认证头；无效连接仅返回机器错误码。等待取消可在 40ms 轮询边界结束，底层同步网络线程不持有文档或数据库；最多两条，单请求网络超时 90s。不能把“停止等待和拒绝提交”表述为“所有网络线程两秒内退出”。

控件随正文块出现，支持单块／全部同意或撤回、前后定位、键盘焦点和至少 44px 点击区域；保留单行编辑栏。新增可见文案和机器错误在现有 46 种语言中逐项登记，不使用英文句子回填所有语言。语义翻译的人工审校与全平台原生验收仍属于后续统一验收。
