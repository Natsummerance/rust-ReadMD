## 首个完整流程

输入为隔离工作区内的中文路径 Markdown，含 UTF-8 BOM、CRLF、重复段落和 emoji。原生宿主必须使用生产 boot、CSP、鉴权及保存服务。

预期：打开、进入编辑不创建副本、不标脏；修改可撤销重做；保存保留 BOM、换行和正文；干净页面关闭无需确认；退出后新进程恢复页面；关闭最后一页后，下次启动回主页。打包解压副本从自身 Resources 定位资源，不能靠源码目录兜底。

外改失败流程：编辑后由独立进程写入新的磁盘版本；保存出现真实冲突框。取消后保留当前手改及外部版本；请求退出后取消，编辑器仍保留脏正文。该流程最后的测试清理使用受控退出，不能作为真实断电或带脏内容正常退出的证据。

代码驱动原生集成入口为 `ui-tests/macos-workflow-native.cjs`。它要求显式的预构建二进制、新建证据目录和合成资料，使用仅 debug 构建可启用的 `native-qa` 功能。默认构建不启用它，release 构建排除驱动代码。此驱动不替换鉴权、目录选择器或业务服务；人工视觉、实体键盘与 IME 结果仍独立记录。

所有本轮配置、文档、缓存、临时文件和产物均放在用户指定工作区。原生测试通过写入沙箱拒绝工作区外文件写入；Cocoa home 和应用数据另行指向隔离目录。系统 WebKit 尝试建立默认临时缓存的拒绝日志保留，不为测试放开工作区边界。

## 打包与正式分发

1. 区分 Mach-O 的链接器签名和完整 app 资源封装签名；后者在全部资源就位后生成。
2. 按内到外签名，严格验证可执行文件、嵌套组件和最终 app；不得用批量清 quarantine 或关闭 Gatekeeper 解决。
3. 压缩的宠物运行包在生成其文件摘要清单之前签名，避免签名改动使运行包清单失效。
4. 开发签名明确使用 ad-hoc，验证成功不能声称 Gatekeeper 默认放行。
5. 正式发布分支要求 Developer ID、hardened runtime、时间戳、公证、装订及 Gatekeeper 检查；缺凭据即停止，不降级后发布。
6. 临时证书和公证密钥仅写入专用目录，使用显式 keychain，不替换用户 keychain 搜索列表；结束时清理。
7. 以打包后的字节进行隐私、摘要及解压副本验证。正式 Apple 服务、DMG 和两种 Mac 架构仍分别取得证据。

[Apple 公证说明](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)是正式分发流程的依据。本机尚无可用 Developer ID，相关代码已接入但正式链路未实测。

## 非 Windows 多文件重命名

预览返回 `commit_supported` 和 `commit_block_reason`。这是本构建的平台能力状态，不是对某个文件权限或文件系统的认证。

Windows 保留既有租约、诊断及事务准入。非 Windows 允许授权范围内的只读预览，返回 `commit_supported:false`；前端在预留审阅/AI、创建持久意图和展示确认框之前停止，并显示平台能力说明。直接调用提交仍由后端拒绝。没有自动回退到单文件 rename，也没有将父目录扫描权限附加给单独打开的文件。

新文案进入全部 46 个语言文件，结构检查和英文原生流程已验证；母语语义审校仍待完成，尤其不把 kg 结构存在当成语义认证。

原生等价方案的下一步需要分别证明：租约准入、未参与进程的写入/删除/替换、原件和父目录身份、无覆盖发布、权限/ACL/xattr 保持、持久意图、全组回滚及新进程恢复。不能把协作锁、检查后普通 rename 或名字相同当作这些保证。

本机 SDK 声明了 `F_SETLEASE`；合成文件的非特权准入探针返回 `-1 / EPERM`，没有取得租约。这仅是当前环境的准入结果，不证明所有 Mac 都不可能实现，也不证明放宽权限后就满足事务合同。Apple 的 [XNU 实现](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_descrip.c)可用于继续调查，但不能替代本机对抗进程验证。
