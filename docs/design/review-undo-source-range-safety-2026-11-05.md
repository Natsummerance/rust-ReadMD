# 待审范围与逆交易的撤销安全规格

2026-11-05。状态：已复现两个底层缺陷，修复与完整回归尚未完成。P0 优先于新的列编辑；通过后分别回补 V0.0.6 和开发分支，不发布 V0.0.7。

## 已复现的输入与失败

1. 文档含重复段落、非 BMP 字符及已物化但未接受的 AI 修改。手工替换包围该修改的一整段，再撤销：正文恢复，decision/application/taken_over 恢复为 pending/applied/false，但范围从原 `[198,210)` 错变为整表 `[116,212)`。冻结的 7a6 内核与认证的正式 e7 内核均通过真实 HTTP 复现；e7 第二进程及只读 SQLite 保留同错。原件 BOM/CRLF、资源及原始审阅文本仍在。
2. 原文 `😀ab!`，同一交易删除 UTF-16 `[2,3)`，并删除或替换相邻的 `[3,4)`。前向交易合法，但生成的逆交易含同起点片段，原严格验证器拒绝，无法完成一次撤销。独立 Rust 回归已单选一项实际失败；发布 e7 与开发基底的通用交易模块字节相同。

最小范围回归使用 `前😀\nA orig C\nA orig C\n`，只把第二个 `[15,19)` 的 `orig` 提议为 `next`，再用一个 `[13,22)` 手工替换包围该修改。撤销后必须恢复 `[15,19)`、原修改 ID、原文、候选及全部状态；再重做、撤销、重开和撤回，第一段重复正文始终不变。测试失败为实际起点 13、预期 15，不以错误位置修改预期。

## 必须保留的行为

- Rust 保有文档身份、generation、review revision、事件、幂等回执和待审原文。正文相同不等于修订相同；不通过字符串搜索重新绑定范围。
- 客户端相同起点、重叠或 surrogate 内部范围仍然拒绝。不能为使逆交易通过而放宽普通请求验证。
- 仅合并内核生成、因相邻删除而折叠到同一点的可信逆交易前缀，保持来源顺序；不任意合并或重排未知重叠。通用交易返回的 inverse 必须可再次应用并完成重做。
- 审阅 Action 继续保留逐个前向编辑对应的原始 inverse fragments，用于验证预期文本和恢复来源位置；它们在真正回放前规范化。持久字段、schema、事件身份和已有回执格式不因本修复改变。
- 恢复待审几何必须使用保留的 source offset 和实际补偿输出位置。被大范围替换压缩掉的内部偏移，不能再用 forward 几何和 inverse 几何重放来猜回。
- 连续包围编辑的后继操作及其撤销，可能已恢复正文却留下有损的范围映射。只有坐标、来源字节和插入文本均证明为精确逆对的相邻非空正文映射，才可在本次补偿的计算视图中抵消；持久事件、审阅决定和修订不删改。正文逆交易及缺失的 proposed 锚点复用同一视图，无法证明时继续拒绝。
- 前后端点的左右归属、相邻编辑、先前补偿导致的位移、零长度删除、缺失当前 ID、proposed 状态及 metadata-only 操作分别验证。不能统一强制所有状态的正文等于 replacement。
- 资源历史的投影分支保持原协议；其规划仍实际调用普通补偿，必须做真实资源保存回归。原文恢复载荷变长或来源无法证明时原子拒绝，并保留当前正文、待审原文与恢复依据，不按相同长度或首次字符串匹配猜修复。
- 不自动重写已存在的错误 metadata 或历史投影；未获证的历史保持可诊断，不删除、不冒认已恢复。

## 验收顺序

1. 保留两份实际失败；通用交易测试还需覆盖 BOM/CRLF、非 BMP、相邻删除／替换／边界插入、反复逆交易及普通重叠拒绝。
2. 真实 Service 验证整段、部分重叠、多范围、左右边界、零长度、各审阅状态、重做和新 Service 恢复；不能只单测坐标 helper。
3. 验证旧 Action 的同点 inverse fragments、后续系统 Save、metadata-only 审阅决定、相对图片迁移、历史资源、失败回滚与原件保护。资源消费者使用实际 Runtime writer。
4. 新冻结内核重跑固定 HTTP 原件→待审→包围替换→撤销／重做→显式保存→新进程恢复→撤回；核对完整字段和 SQLite，精确四范围正控不得回归。
5. 两分支分别完成适当的非模型库、前端、Mac 原生及正式包检查，Windows/Linux 加入相同回归。源码／boot／二进制／安装包摘要独立绑定，再替换 V0.0.6 下载和本机安装。

目前单格 50 项 Mac 原生及 OpenAPI 限定通过仍绑定其原生产者，不能作为本修复的新候选成绩。Windows 10060 首败、Keynote 字体漂移仍分别开放；本规格不把它们或 P1/P2 整项改成完成。
