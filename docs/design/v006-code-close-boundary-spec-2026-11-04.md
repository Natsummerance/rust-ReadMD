# V0.0.6 代码结果与关闭决定的安全边界

这是独立热修复，不引入 V0.0.7 的执行器、批量事务或数据库格式。已有关闭修订校验和正式 CSP／鉴权必须保留。

真实首败：用户有未保存正文，运行 `sql cmd output=true`；Rust 已完成 SQL，但结果交付在关闭确认框打开后到达。旧前端立即插入结果，使“不保存”的正文快照失效，第一次点击不能关闭。已使用正式 V0.0.6 二进制及资源、隔离资料验证，原件未保存。

预期：结果固定运行时的页面、输入代次、源位置和修订；等待关闭、退出编辑、切页等生命周期决定结束后，才再次检查。检查与正文修改之间不能再有异步间隙。等待必须在审阅队列外，避免“保存”等待自己的关闭流程。取消关闭且正文未变时可继续正常写入；不保存或保存并关闭后不得晚到改写。改后撤销也算过期。失配只保留控制台结果并提示冲突，不假报保存成功。

验收先覆盖关闭标签／退出编辑的保存、取消、不保存六种决定，再检查切换到相同代码的另一文档、运行中改后撤销、实际保存失败及新进程恢复。成功的普通运行需保存、单次撤销／重做、保留 BOM 和 CRLF；关闭／不保存后重开保持原件。失败路径不得覆盖外部正文。使用实际 Rust HTTP 和文件；延迟只控制真实结果交付。另补 Mac Cocoa 验收，跨平台 headless 证据不替代原生宿主。

旧版批量运行、受管环境和任务恢复仍由 P1 规格推进，本热修复不据此标记整项完成。版本号保持 V0.0.6，公开安装包仅在对应候选真实验证通过后替换。
