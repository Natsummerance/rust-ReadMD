# V7-07：表格导出的受限原生投影

复用 Markdown AST、现有 DOCX／Rust PDF 表格消费者、PPTX 布局与冻结导出快照。先完成可证明的表格内容和边框交付；不把本切片计为全部单元格编辑、合并、扩展属性或外部办公软件往返通过。

## 支持与拒绝

普通矩形 HTML 表格使用已有原生 Table／Inline 模型，首行为 `th`，后续为等宽的 `td` 行。支持相同列对齐、`rowspan/colspan=1`、普通文字、HTML5 实体、强调、代码、链接与换行。文字中的 Markdown 不重新解析；实体只解一次，编码的标签和引号不能制造结构。真实注释中的引用保持无关。保留 GFM 与代码示例原有解析行为。

嵌套表、真正跨格合并、缺格、多表头、不能保留的属性或混合结构，在 DOCX 和 Rust PDF 消费前明确返回 `publication_table_unsupported`。不得丢掉合并后假称成功；原目标、原 Markdown、图片、待审状态和恢复记录保持。HTML／EPUB 的既有 HTML 保留路径不因原生消费者限制被全局禁用。

解析前限制 HTML 片段 2 MiB、标签 4096 字节、每标签 16 属性、深度 64、节点 100000；表格最多 4096 行、32768 单元格。预算扫描定期检查取消，再使用现有 DOM。实体表复用已直接锁定的 pulldown-cmark，不改变 Word／数学 XML 解码器的语义或依赖特性。

PDF 引擎仅接受已有 `rust`、`typst`、`xelatex`、`pdflatex` 及原有默认值。非法枚举在字体、资源冻结和目标写入前拒绝；直接调用 Rust PDF 消费者不能靠其他引擎名称绕过表格检查。

## PPTX 的同模型交付

GFM 继续导出原生可编辑 `a:tbl`。三线表的顶／底边为基础宽度两倍，表头分隔线为基础宽度，其余单元格边明确 `noFill`；网格和商业预设保留各自边框。列对齐与边框颜色／宽度由同一计划供预览和 PPTX 使用，跨页重复表头和底线。

表头颜色／填充／粗体、条带、字号、padding、widthPct 等仍需逐项实现和验证，不能用边框通过覆盖这些缺项。HTML 预览和 OOXML 同源一致只证明该模型，没有证明 PowerPoint、WPS 或 Keynote 的实际像素与往返。

## 独立预期与证据

固定 GFM、普通 HTML、重复表、单位跨度、代码示例与四类拒绝输入；正文使用独立声明的唯一标记和已知表／格数量，不从渲染结果反推预期。真实服务验证保存原件及旧目标、无新失败产物、预览拒绝、快照准备失败后的待审保护和 BOM／CRLF；实际 DOCX 读取 XML，实际 PDF 由独立文本 reader 读取。PPTX 核对可编辑表格、全部边、对齐和续页，冻结预览另行比较。

源码、boot、二进制及 reader 摘要分别记录。Mac 本地、三平台 CI、Cocoa 及外部办公软件结果分列；缺 reader 不得跳过检查后报绿，不调用产品 PDF 导入的 OCR 回退。此前的真实首败与测试准备错误保留并区分。清单只能在各自真实通过后更新，V0.0.7 仍等待全部 P1/P2。
