# V0.0.6 Mac 场景复现与发布门槛

用户追加要求：宣传片使用的全部场景必须能在 Mac 实际复现；先修软件再录制。原 Windows 录像、模拟 UI、headless 成功和平台分支存在均不能代替 Mac 原生验证。本要求优先于此前允许保留旧平台素材的剪辑安排。75 条长期合同仍分别记录，不将本切片扩大为整项验收。

2026-10-31 执行顺序调整：用户要求先修不调用模型的适配，待内存空闲后再测模型服务。普通启动及状态查询不再自动加载 OCR／转写；本阶段不运行 OCR、ASR、AI 推理或权重转换。此前的引擎探测属于暂停前的独立证据，不能替代稍后完整原生消费者验收。全库回归明确过滤唯一直接调用 Vision 的用例，不将其改为既有忽略。

## 场景入口与独立预期

以宣传工程实际引用的场景 ID 和既有功能清单为清单，逐项记录：专用固定输入、入口、真实 Rust 服务、原生宿主、保存结果、重开、取消／失败。新素材必须来自已通过的 Mac 流程，保持全部章节和既有特效。素材规格和软件可用性分别记录。

- 普通阅读、编辑、表格、图表、引用、代码、AI、转换、导出、分享与知识图谱：复用现有业务服务，验证 Cocoa/WKWebView 入口和后端结果；修改原文必须使用现有身份、修订与审阅模型。
- OCR：当前 Mac 默认探测不到可用引擎属于真实移植缺口。接入原生 Vision 的文件字节识别，复用现有布局排序、错误、预算和保存流程；本机已下载的 OCR 资源只读盘点，重型模型按受管资源边界接入。就绪判断执行最小识别，不能只检查框架或文件存在。固定英文／中文图片分别验证文字、布局、原图不变、暂存和明确保存后重开；取消、空图和损坏输入不能创建假成功文档。
- 语音：现有默认转写依赖 Windows System.Speech，Mac 路径需要补齐。本机现有转写权重已经定位，先核对格式、许可和推理实现，再选择可随程序／受管包交付的引擎。原权重只读；转换副本、受管资源和临时 WAV 均在工作区。验证固定录音的独立原始稿、实际时长与偏移、持久结果、重开和取消；不能依赖用户全局 Python 或 PATH 中的 FFmpeg。
- 桌宠：现有 Mac 全局鼠标监听和剪贴板读取存在占位路径，必须实现真实原生行为。复用当前宠物状态、协议、渲染与恢复；验证透明窗口、命中／穿透、拖动、位置记忆、原生剪贴板、陪伴交互、隐藏／唤醒、主程序退出和重开。测试只捕获自有窗口与专用材料。
- 文件选择、导出保存和原生窗口：使用真实 Mac 宿主、系统组件及实际文件；保留数据授权边界和关闭保护。脚本选择固定输入也必须进入同一正式验证／提交路径，不能替换认证或制造成功回执。

## 工程与证据

软件源码不包含宣传资产、私人模型路径、连接地址、偏好或密钥。现有模型、服务和配置只读调查；构建、格式转换、测试、录制和封装输出在工作区内。Rust 先准备锁定依赖，再使用单一共享 target 执行 `--locked --offline`；重型模型和可重建缓存分别计量，不按目录名整树清理。

每个消费者单独绑定源码、boot、二进制和资源摘要；首败保留。原生界面、真实文件结果、受管引擎、原生录制和其他平台分别记账。全部宣传场景通过前，V0.0.6 保持候选状态，不能将尚未实现的 Mac 能力包装为录制限制。
