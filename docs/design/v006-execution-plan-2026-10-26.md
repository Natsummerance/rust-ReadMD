## 版本目标与基线

V0.0.6 的主线是让编辑、AI、保存、导出与恢复共用可靠的内容状态，再把同一能力用于协作、PDF、媒体、图像和出版。默认界面沿用阅读页、单行编辑栏、现有侧栏与上下文工具。

当前正式基线为 V0.0.5，源码提交 `3cbb7a39ad889a2a485105acb4950a6cee995649`。第一批开始前，75条总需求为60条进行中、15条待办、0条整项结案；第一批后62条进行中、13条待办，R063／R065获得限定证据；第二批后63条进行中、12条待办，R064加入限定实测，仍为0条整项认证。批次范围通过不替代原完整合同，也不表示已发布能力全部不可用。保留已通过的有限单元，不从零重做公式、预设、协作或 PDF 工作区。

最新发布收尾记录优先于旧清单中的历史“下一步”：长路径安装、部分数学回退／修订提示、段落装饰阅读投影、Unix 租约及打包隐私阻断已在 V0.0.5 收口。严格 Windows 故障矩阵、旧 Node 超时首败因果、完整数学／排版、外部应用、受控冷态和长期压力仍有待办。不能把旧历史文字直接当作当前产品缺陷列表。

建议把本版本分为五批，每批先交付可独立使用的完整流程。所有旧需求保留在任务池；发版判断依据明确的已验收范围和已知问题，不再等待一个“全部工具优点、所有格式、所有平台均完美”的不可判定终点。下面的进阶项不因进入计划获得完成状态，也不自动移出 V0.0.6；实际版本范围在候选冻结时按证据明确。

## 功能与架构边界

- Rust 是文档、事务、审阅、快照、资源和任务状态的唯一业务所有者。前端、VS Code 和 MCP 调用共享服务，不各自保存一套状态机。
- 复用已锁定的 SQLite、Yrs／Yjs、CodeMirror、PDFium、图像库及现有 exporter／worker；不先拆出大量 crate 或更换编辑器。上游已有代码资产只作参考，未来引入新代码仍需锁定来源与许可。
- 保存、审阅、运行三种状态分开显示。普通 Markdown 不夹带审阅载荷；普通打开和进入编辑不创建副本、资源目录或修改标记。
- 保留 LOGO 回主页、悬停快捷键、底部字数、单行自适应工具栏、无边框 AI 输入、统一勾选框、阅读设置的现有位置与禅／全屏规则。
- 新功能优先进入选区、公式、图片、表格或原有侧栏的上下文；高级参数折叠，不增加八个常驻工作台。

## 依赖和并行组织

主依赖为：当前状态整理 → 第一批审阅／保存 → 第二批快照／任务 → 各场景适配 → 冻结验收。

第一批 schema、错误、范围和回执合同由集成负责人先冻结。其他工作可分为内核、前端、快照、工具协议、文档格式、故障验证等互斥文件任务；公共 server、MCP、保存／退出入口和 Cargo 构建由一个负责人串行整合。每个任务明确写权，不让多个代理同时改同一共享入口。后续若启动子代理，沿用户偏好使用 6.1 Sol max。

每个单元遵循：先列输入／行为／失败／保存结果／独立预期 → 小范围实现 → 定向验证 → 真实完整流程 → 更新限定状态。只在失败、新修改或新的风险需要时扩大回归，不反复生成整套历史证据。

## 缓存和隐私预算

构建继续 `--locked --offline`，Rust 命令在 rust 目录；共享 `CARGO_TARGET_DIR=.cache/community-upgrade/build`，`CARGO_INCREMENTAL=0`。不同时启动多个 Cargo 构建，不为每个代理复制 target。

建议作为本版本新增的执行预算：共享构建缓存 8 GiB 提醒、12 GiB 停止增长并整理；每轮临时证据尽量≤512 MiB，最终证据按需求保留输入摘要、日志、代表产物及必要原始失败，不为每个测试复制整套程序。可用空间不足 8 GiB 时不启动重型构建或压力材料生成。这些是待接入执行脚本的预算，不是已生效的控制器。

清理只针对已确认属于本任务、可重建且无引用的产物。待审原文、恢复记录、未完成任务、原始失败和用户资料不是普通缓存。任何递归清理先核对绝对路径和归属，不绕过自动审批阻断。

模型服务地址、模型名称、连接名、令牌和浏览器数据均视为私有配置；不写入公共文档、测试快照、演示、GitHub 提交或发布资产。真实 AI 验证从现有私有连接运行，只保留脱敏结果与凭据引用，不复制配置。

## 验收和发布判断

本版本至少应打通第一、二批的真实闭环，并修复本次引入或影响已声明能力的数据丢失、越权、错误覆盖、不可恢复和虚假成功问题。第三至五批按实际支持范围逐单元验收；未实现、格式不支持、缺外部环境和性能目标未达分别报告，不能改断言或以重试后的成功覆盖第一次失败。

每项记录五种证据：实现入口、真实操作、保存重开与恢复、失败保护、测试／产物引用。纯函数、模拟故障、真实进程、真实模型、外部应用和原生平台分别归档，不互相替代。真实文件使用隔离副本，磁盘满使用受控小卷，不填用户系统盘。

发布前冻结源、boot、正式包、能力包与观察器；运行完整适用门禁，再用正式安装包验证关键链。新版 schema 要有明确迁移／回退限制，旧程序不得静默改写较新存储。是否发布另按用户指令执行，本文本身不触发发版。
