# V7-11：真实聊天流与请求停止

本项是实施规格，不能据此勾选 P1/P2。首次实际连接中，请求要求流式但 `/api/ai/chat` 返回聚合 JSON；真实多轮审阅和暂停／重启已有独立证据，不能重算为流式聊天通过。使用用户本次指定的已配置远端连接；不加载本机模型，不修改其服务、全局代理或私人配置，不公开连接信息和模型偏好。

## 输入、行为和独立预期

1. 保留原 JSON／MCP 响应；同一鉴权路由仅在 `Accept: text/event-stream` 时提供事件流。请求验证、私有凭据解析、技能与消息整理复用已有服务。正式 CSP、尾斜杠鉴权和真实 token 不变。
2. 有效请求先登记固定 `task_id`，然后发 `start`。每个 `delta` 直接来自提供商返回，不用打字机把聚合结果冒充流。相同请求不能为了 SSE 或补齐 usage 再调用模型一次；提供商返回完整 JSON 时可一次发完，并如实作为回退记账。
3. 上游和下游分别验证结束：上游应有协议结束标记或明确正常结束原因，不能把无标记断流算完成；浏览器必须见到自己的 `done`。错误帧、坏 UTF-8、无效 JSON、错误任务身份、预算和 EOF 均不能清审阅、写正文或保存一条完成的答复。保留已显示的局部文字及可理解的失败状态；usage 最终只计一次。
4. 停止按钮同时取消 HTTP 读取和后端固定任务。关闭连接也要触发停止。取消先于成功提交时不能写聊天成功记录；正常完成在同一数据库事务中保存整轮记录，隐私对话不落原始聊天记录。任务登记竞争只重试取消，不重放原请求。普通聊天不会自动保存文档。清空／切换对话使旧请求失效，旧结果和旧会话保存回执不得覆盖新对话；停止的局部答复保留未完成标记。
5. 取消响应／观察小于 200ms；拥有的 HTTP、转发与读取 worker 在两秒内停止，分项实测。保留最多两个 AI 请求预算；不能靠把阻塞线程放后台、继续占槽 90 秒冒充停止。

## 传输所有权

锁定的 ureq 2.12.1 没有公开的普通 HTTP socket 取消接口。复用其公开 Resolver 接口，为单次请求建立只绑定 loopback 的有界 TCP 转发；HTTP、TLS、证书／主机名校验、Host 和鉴权仍由原 ureq 完成。不解密 TLS，不修改信任根，不用替身服务器完成鉴权。当前构建没有启用 `socks-proxy` 或 `proxy-from-env`，本切片只验证直连 HTTP／HTTPS，不据此声称代理路径兼容；未来若启用代理，须另验 Resolver 的目标地址语义和取消。

所有请求 socket、转发和队列都有独立停止状态；取消只关闭该请求登记的连接。连接尝试至多一秒，每次重试前复核停止；取消后的 DNS 结果不得再启动连接或发送正文。系统 DNS 查询只能在最多两个只读 helper 中等待，系统 resolver 本身不能跨平台强制取消，这一边界保留待验，不能宣称全部 OS DNS worker 已强停。队列满时仍轮询停止，不能阻塞着永久占用请求槽。

## 验证顺序

先用真实 loopback socket 固定“响应头前挂起、SSE 中途停顿、消费者队列满、正常 JSON／SSE、错误／截断”的独立预期；观察对端 EOF、请求槽和 worker 回收。再用正式内核／鉴权验证可逐段观察的内容、取消、持久结果和下一进程。浏览器另验分片 UTF-8、CRLF、最终 usage、失败／取消、过期响应和局部文字保护。

最后使用用户指定的实际远端连接实测流式聊天和取消，并与现有多轮工具、保存重开和暂停等待明确继续的回执分别记账。三平台 CI、Mac Cocoa、长文／多模态、其他供应商与系统 DNS 故障矩阵不能互相代替。测试原始配置仅在工作区私有夹具中，结束后清理本次副本，保留脱敏摘要。
