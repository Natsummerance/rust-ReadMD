# P06-B 后续：题注作者格式的共同消费

**2026-10-23更新：本规格的本轮有限主链已有真实实现及证据，仍有严格互操作和全矩阵未验收。** 以[本轮报告](../reviews/readmd-v005-batch3-caption-section-roundtrip-2026-10-23.md)的具体正例、失败和边界为准；下文原始规格是目标与历史审计，不代表所有条款通过。

状态：待实施、未验收。承接作者行内字号增量，优先于已规划的 P06-C 逐节注释编号。这里记录可实现的欠账，不能将它归为客观不可能，或用当前的明确拒绝代替最终实现。

## 用户结果

导入含自定义字号的原生题注后，阅读、预览和导出均保留题注编号、标题、作者字号及引用目标。默认界面沿用正文与现有格式设置；不加题注专属工作台、配置入口或保真黑盒。

当前 DOCX 已具有真实的 `text.author` 往返。其他消费者仍在提交前准确拒绝该声明；这是一项保护，也是本增量必须解除的实现缺口。普通 `text.size`、无作者格式的题注和空 `text.author: {}` 必须保持既有行为。

## 同一模型与有限范围

复用 `AuthorTextStyle`、`ResolvedTextStyle` 和公共 itemizer。两轴 `size/sizeCs` 独立；省略、显式点数、`base`、`cs/rtl` 的显式关闭不能合并。题注标签与标题共用题注基准，标题内部的行内作者格式优先；`base` 回到题注基准，而非正文默认值。

继续采用精确半点及 4096pt 渲染上限。源和 DOCX 的更大合法值不被夹值。任意复杂文字整形、显式 RTL、数学子节点等尚无等价实现的组合，仍沿各消费者原有准确诊断，不能因补齐普通字号而一并宣称支持。

公共检查不能因为任意一处出现 `text.author` 就放行全部输出。应明确各消费者的已实现属性；空声明无效果，数学、方向和非法参数仍有原有诊断。

## 实际材料及闭环

复用现有冻结、stdio/HTTP 驱动与独立检查器，不新造验收系统。材料至少包含：

- 原生默认 10.5/11/14pt，自定义题注 30pt/10pt，单轴声明、缺少复杂文字轴、显式 false、标题自己的局部覆盖及 `base`。
- 缺少 Caption 样式、不同原生 namespace 别名、native 当前值修改及清除；原件和辅助来源的摘要保持独立。
- 真实 GFM 表格后题注、图片题注、自动 SEQ/REF、重复标题、中文与现有四种复杂文字材料；代码和 HTML 中的相同示例不生效。
- BOM、CRLF、emoji 范围；源事务、逆事务、过期修订及重复请求。

每条正例：实际导入 → 精确修改 → 撤销 → 受修订保护保存 → 正常 EOF → 不同 PID 重开 → 空 options 导出 → 独立检查输出 → 再导入。源码、原件、预设及 Last 不被测试污染。

先保留当前负例与错误详情，在对应正向输出实测通过后逐条替换其能力状态。对于仍不支持的组合，验证 missing-overwrite 与 explicit-overwrite 两条路径，旧文件与目录均不变。不能把 guard 数当作正向排版通过数。
