# V0.0.6 第三批：文件重命名与多文件引用事务

日期：2026-10-28。本文是实施规格，不是通过声明；完成范围以实测报告为准。

## 输入和边界

仅扫描用户明确选择的资料夹；单独打开一个文件不授权扫描其父目录。源文件必须已通过真实文件入口打开，且为已保存的 `.md`、`.markdown` 或 `.mdown`。本切片只做同目录、同扩展名改名；目标不能存在，不接受大小写别名、重解析路径或硬链接。没有选定资料夹时沿用既有单文件协议；TXT 沿用单文件协议，不把纯文本中的括号误作链接。

扫描有文件数、字节数、参与文件数和审阅存储预算上限。跳过私有、隐藏、构建、版本库和资源目录；遍历失败或超出预算不能冒充完整扫描。修改范围包括相对 Markdown 链接、图片链接、引用式定义和可唯一定位的 wiki 链接。代码、外部 URL 和普通正文不替换；无法可靠解释但指向源文件的语法阻止提交并返回定位诊断。

当前明确预算为 4,096 个文档、16,384 个遍历条目、32 层、64 MiB 扫描输入、64 个参与文件和 12 MiB 前后文合计；单参与文件的编码字节及规范化审阅正文分别不超过 4 MiB。文件系统别名审计最多 65,536 次。预算达到上限明确拒绝，不截断后显示完整成功；支持扩展名不代表 MDX、HTML 等其他文档引用也会自动改写。

预览只读，给出源文件、目标文件、每处精确修改和不可变计划摘要。提交重新扫描并比较摘要；任何相关原始字节、强文件身份、扫描成员或审阅修订变化都使旧预览失效。预览不是覆盖文件的凭据。

执行前在保存锁内再次核对全部扫描成员，之后租约保护参与原件；非参与文件被外部进程在最终快照后新增引用仍属于边界，不能承诺跨所有外部程序的全目录原子事务。

## 提交与审阅

锁顺序保持 `SAVE_LOCK → profile OS gate → review SQLite`。Windows 为全部参与原件获取禁止其他写入／删除的句柄租约；全部准入成功后才创建持久意图。其他平台在未实现等价租约前明确拒绝批量提交，不降级为有竞态的路径覆盖。

审阅库升级为 schema 5，增加组事务和全路径预留。全部参与文档必须已保存、正文与磁盘一致、无其他保存／改名意图。预演全部审阅映射、检查点和预算后，在一次 SQLite 事务中记录意图并预留路径。按文档 ID 发起的 AI／审阅操作也必须检查预留，不能绕开文件 API。

正文改写保留 BOM、编码、原有换行及全部未修改字节。解码后无法精确重新编码的文件不自动修改。审阅身份、原稿、已保存检查点和不相交的撤销历史保留；与未审阅修改或不可安全映射历史相交时，提交前明确拒绝，不静默更改历史原稿。

## 文件发布和失败回滚

修改内容写入同目录 `create_new` 临时文件，写入、同步、身份读取共用原创建句柄；在第一次原件移动前持久化暂存身份。原件通过句柄移到本次意图独占的备份名，再以不覆盖移动发布暂存文件。目标名出现第三方文件时绝不覆盖。

文件与祖先目录必须具有受支持的身份、非重解析／大小写敏感别名及元数据状态。暂存文件和原件的受支持安全描述符、普通属性必须完全兼容；额外数据流、特殊属性或无法保持的 ACL 在移动前拒绝，不静默丢失或扩大权限。此处不是完整 SACL 保真认证。NTFS 名称隧道导致创建时间继承时，只允许在同一被持有的文件身份及字节完全一致的条件下校正该时间，再执行完整验证；校正间隔发生崩溃仍可能保守地停在待恢复。

全部文件验证成功后，在一次 SQLite 事务中提交正文、路径、磁盘修订、审阅映射和回执。相同请求 ID 只能重放相同意图；不同参数不得复用。审阅最终提交失败时不报告成功。数据库提交结果不确定时先核实持久状态，禁止把实际已提交事务回滚。

中途失败或进程重启后，根据已记录的强身份和原始字节摘要识别原件、暂存和备份。只移动确认属于本事务的对象，回滚同样禁止覆盖；能安全恢复的文件先恢复。第三方占位、修改、身份不符或不可读取时保留其内容及原件备份，状态为 `recovery_pending`，全部相关写入继续阻塞。终态成功后清理也只按确认身份的句柄执行。

进程可能在暂存创建与身份入库之间断电；这种未登记身份的残留不得按名称删除。保留恢复诊断，不声称所有断电场景都零临时文件。跨多文件可观察到短暂中间状态，不能承诺文件系统本身具有多路径原子事务；ReadMD 客户端通过预留与界面屏障避免读取、写入该中间状态。

## 前端和会话

复用重命名入口，确认前展示逐文件改动。所有受影响标签页必须先完成审阅队列和 AI 任务预留；任一脏文件、正在编辑或恢复中的参与者阻止提交。一次性验证所有实际文件和审阅回执，再同步更新全部标签页，避免半组收养。

发请求前保存原标签页上的持久组描述；成功后用现有 session CAS 保存新路径，收到准确 ACK 后才解除预留。丢失 ACK、切页、关闭及重启不得把事务转到新文档，也不得盲目生成新的请求 ID。文件事务已提交而会话保存失败时保留组描述与阻塞，不能回滚已提交文件。

正文、审阅及文件身份全部验证后一次收养；文件侧栏同时使用已验证路径更新，不切换用户所选目录。首次启动先串行消解组意图，再读取任何待恢复标签；恢复取消保留原会话及草稿，不发布仅包含部分标签的新会话。AI 任务恢复和普通载入同样遵守组屏障。

接口及尾斜杠别名要求本机来源与运行实例的 app token；严格令牌模式另外使用同一安全 meta 引导值，显式 LAN token 保持优先。生产 CSP 继续禁用内联脚本与普通 eval，不以注入 fetch 鉴权代替真实引导验收。

## 必测矩阵

- 普通、嵌套、带空格／Unicode／百分号、引用式、wiki、锚点及查询串；代码和外部链接不变。
- UTF-8 BOM、UTF-16、传统编码及混合换行，精确未改字节；无法往返和无法编码目标明确拒绝。
- 多文档及自引用、预览取消、计划过期、新增引用文件、目标碰撞、任一文件只读／锁定、容量不足。
- 多文件中途失败、第三方占位、重启回滚、同 ID 重放／异参拒绝、未知对象保留、清理失败。
- 审阅身份、保存后重开、检查点、撤销、AI／另一进程写入阻塞，非相交审阅映射与相交拒绝。
- UI 全组验证、会话 ACK 丢失、关闭／打开屏障及恢复；使用合成材料和正式 CSP，不使用个人文件或配置。

保留首次失败；当前二进制的基线已复现“源文件改名成功、两个引用文件仍保留旧链接”。构建仅使用共享离线缓存，禁止新增 target 目录；报告记录二进制与源码摘要，检查凭据脱敏和缓存体积后再更新账本。
