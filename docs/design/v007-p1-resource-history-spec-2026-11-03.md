# P1：图片编辑历史与跨目录另存

延续 V7-01 的资源暂存、SaveIntent、完整预算、原子文件写入和恢复投影；本项是 V7-01B，不重做保存/审阅服务。P1/P2 全部验收前不发布 V0.0.7，也不替换用户正在使用的 V0.0.6。

## 固定输入和独立预期

中文/emoji 路径、UTF-8 BOM/CRLF 文档，两个重复段落及两幅相同引用；图片 A/B/C 的字节彼此不同。先手工局部修改图片地址，再做多次正文/图片编辑，包含撤销后留在 redo 中的图片修改，以及 AI 待审被手改接管的情况。另存到第二、第三目录后，将旧目录移离原路径：当前、每次撤销和重做的正文及待审状态应与独立预期一致，所引用的图片从新目录实际读到原字节；原 Markdown/图片保持不变。

没有修改不产生副本；只有明确另存才搬迁。失败、取消、缺历史图片、未知占位、外改、编码拒绝、空间/恢复预算不足均不提交目标、不清原文或审阅，只回收本次创建且身份匹配的资源。文件已经提交而 SQLite 尚未完成时，新进程用持久意图完成相同投影；未知结果保持恢复依据。

## 设计边界

1. Rust 从实际 undo/redo 栈顺序重建每个可达状态。使用现有补偿逻辑及已知事务范围，不按字符串找第一次出现的位置。读取计划绑定 document_id/generation/review_revision，再次 prepare 时严格复核。
2. 对每个状态复用资源服务，搬迁可见图片及该状态必要的待审原图。资源按内容去重，历史资源计入同组预算；资源 guard 持有至文件提交，失败逆序回收，不枚举文档上级目录。
3. 已知历史修改的 UTF-16 源范围分别经过其前后两态的资源映射，得到新的补偿范围。映射扩大/重叠时合并对应范围；验证范围外文本逐字相同，才生成替换。语义不明、坏范围、缺原文均明确拒绝，不做跨未改段落的宽泛差分。
4. Action 的原始历史保留，另存附加补偿投影：预期完整正文修订、精确 inverse edits/expected slices、审阅补丁。投影只在相符状态使用；后来的手工输入仍先撤销，旧投影不能覆盖更新的修订。实际 undo/redo 继续记录新事件、递增 generation，并生成反向动作。
5. 投影随 SaveIntent 预存并预演完成峰值；提交、重复请求及新进程恢复使用同一份内容。改变此语义必须提升审阅存储版本，使已发布的格式 6 内核拒绝读写较新库。原 Markdown 编码、BOM、换行不因此改变。
6. 再次搬迁重新投影所有仍可达历史；普通原处同值保存不新增资源、不清 undo/redo。保存后未接受的 AI 修改仍 pending；旧隐藏元数据不能覆盖外部的新正文。
7. 手改接管或已撤回的完整图片原文单独保存资源投影，只作恢复资料，不授予向用户正文撤回 AI 的权限。受信的路径改写保持既有“保留手改并同意”决策；撤销生成的反向动作也附精确状态投影，不能退回不适用的旧范围映射。
8. SaveIntent 同时保留当前及历史资源的完整 SHA-256、长度和目标路径，计入原有持久预算。文件提交前、提交回执及新进程恢复分别复核；资源缺失、变动或命名空间不符时保留意图及原正文，继续 needs_recovery。显式修复后才重试完成，不能因 Markdown 摘要相符而假称完整恢复。
9. 规划阶段的展开表示也限于 64MiB，避免去重原文在多历史状态中反复展开后耗尽内存。回收新建资源同时复核文件身份和字节摘要；已观测到的原地外改同样保留。这些是时点复核及合作保护，不能冒充阻止任意外部写入的文件系统租约或多文件原子提交。

## 验收矩阵

- 手工整幅图片/局部 URL/多操作/重复图片、插入删除与 Unicode 前缀。
- 保存→关闭服务→重开→逐次撤销/重做→再保存→新进程恢复；撤销后 redo 分支也须迁移。
- 待审、同意、撤回、手改接管及元数据动作与普通正文交错；每个状态独立核对原文和决策。
- 再搬迁后旧两目录均不可读，所有必要图片仍可读取；原件和旧资源摘要不变。
- 缺历史资源、外部占位/目标锁定、预算不足、准备后新修订、取消、提交前失败及文件已提交后的受控中断；不把受控中断当真断电。
- Mac 本机 CLI/服务及最终原生 UI 分列；Windows/Linux 使用相同 Rust/HTTP/文件输入在各自 CI 验证。原生选择器、IME 或外部应用缺项继续明示。

当前是实施规格，尚非通过记录。禁止加载模型、打断用户 LLM 或个人桌面；原生交互需要单独协调桌面时段。共享一个 Rust target，锁定依赖离线编译，P1 本地新增构建/暂存预算先按 2GiB 监测，保留至少 10GiB 可用内存。保存/撤销/恢复实测后才更新完成状态。
