# V0.0.5 发布范围与 V0.0.6 接续

2026-10-25，用户明确要求先验收并发布现有成果，将第四批和第三批剩余深化放入 V0.0.6。此约定替代旧计划中“全部五批完成才可发布 V0.0.5”的版本安排，不改变任何功能的证据标准，也不将 75 项大范围需求标成完成。

## V0.0.5 的有限合同

第一、二批已有证据的体验与草稿恢复，以及第三批已实施的结构公式编辑、可读 DSL、学术／书籍／通用预设、共享元信息、引用与编号、科研图表、DOCX／PDF／EPUB 输出及上下文能力包交付，进入本次候选复验。各能力仍以现有规格中的实际支持范围为准；复杂组合不因进入版本而获得认证。

本轮必须修复 Windows 长路径安装失败、数学字体替换与格式修订损失提示、段落装饰影响整个阅读投影，以及新增提示的真实多语言覆盖。保留编辑工具栏、首屏刷新、4K 阅读宽度、保存／外改保护及所有既有通过基线。

发布候选必须绑定源文件、参与测试的观察器、binary／boot 摘要和原始日志；最终安装包实际二进制另作关键冒烟。保存重开、撤销、失败保护、转换导出、能力安装、MCP 与受影响集成须有可复算结果。构建成功不等于原生交互验收，受控 DOM 不等于原生视觉验收。

现有发布管线提供 Windows x64、Linux x64、macOS x64／ARM64 四个构建目标和 VS Code／MCP 集成包。Windows 是本机实测环境；其他平台保留各自证据状态，不把交叉构建或 CI 产物写成完整原生认证。未实际提供的架构不生成下载承诺。

## 发布前门槛

1. 冻结代码后顺序运行完整 Rust、前端／工具、仓库检查及离线锁定构建，保留首次失败和修复后的新候选；不边改产品边认证。
2. 使用隔离资料和 profile 验证长路径安装、真实引擎输出、保存重开及目标保护，不改真实用户资料，不录制私人目录。
3. 现有 Windows 故障矩阵重新执行；实害故障须修复。性能目标若未达到，原断言与失败仍保留并列入 V0.0.6，不能改阈值获得通过。
4. 手动 RC 默认只构建和验证；正式标签或显式发布才可进入发布 job，所有共享质量及构建门禁继续生效。
5. 核对源码提交、版本、完整资产和 SHA-256 后发布 V0.0.5；V0.0.4 标签及资产保留。官网和应用更新检查跟随真实正式发布，不把候选当作可下载正式版。
