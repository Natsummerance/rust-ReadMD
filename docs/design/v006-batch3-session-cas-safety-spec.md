# V0.0.6 第三批：会话并发与重命名恢复协议

状态：**已实现并通过限定的 Windows 进程与前端实测，整体仍未验收。** 曾在 Windows 隔离资料目录用真实进程复现旧会话覆盖重命名意图；新协议已对该流程、并发提交和重启恢复完成实测。首败、通过证据与未覆盖边界见[重命名增量记录](../reviews/readmd-v006-batch3-rename-2026-10-27.md)。

## 存储与接口

- 同资料目录的所有新内核和同一内核的多个页面对会话使用同一个、持久的 `session_version`：随机 epoch 和十进制字符串代数。不要用文件内容哈希当代数，避免内容重复时的 ABA；代数耗尽或元数据损坏时拒绝写入，不能重置。
- `GET /api/session` 在现有 settings 跨进程锁内从磁盘读取 session 与版本的同一快照。旧资料首次迁移在同一锁内保存 session 原文与新版本；未知或损坏的资料不能按空会话覆盖。读取失败或旧内存缓存不能授予写资格。
- `POST /api/session` 带完整 session、`expected_session_version` 和本次 `call_id`。锁内比较版本，session 与递增后的版本同一次同步替换；冲突拒绝且不返回可供盲目重试的新版本。通用 settings 写入在存储层拒绝 session 和保留元数据，其他偏好保持兼容。
- 以有界回执支持同一 call ID、相同预期版本和完全相同请求的幂等重放：只有原结果版本仍为当前版本时才返回原成功；随后会话已推进则拒绝，不能用旧确认让调用方误以为意图仍在当前会话中。回执只保存必要摘要；保留最近 256 条及总字节上限。回执之外的旧请求按版本冲突拒绝，不能假装成功或重复覆盖。不同内容重用已记录的 call ID 必须拒绝。
- 替换或同步结果不确定时，前端保留原请求和完整意图，不以更新后的代数重发旧状态；明确冲突后停止当前页面的会话写入，等待重新载入并恢复。已有旧内核、外部程序或人工覆盖 settings 文件不参加此协议，不能声称其受保护。

## 前端屏障

1. **启动：**必须完整解析并承接权威快照内的所有重命名意图，才获得该版本的写资格。用户抢先打开文档、恢复被打断、数据超限或意图被去重时不得把当前局部状态写回。localStorage 可保留恢复材料，不能授予原生写资格。
2. **重命名：**先完成审阅与恢复存储屏障，成功后才将意图暴露给会话自动保存；发送文件移动前，含全部预期修订与审阅身份的意图必须取得持久确认。结果未知时保留意图并用同一请求对账；若确认丢失后另一窗口推进会话导致重放冲突，当前窗口保留限制，不擅自移动或判定失败，需重启按权威快照恢复。服务端结果经身份及原始字节验证后，只有结算后的 session 获确认才能解除编辑限制。
3. **关闭：**单个、其他和全部标签都先形成不含关闭目标的候选会话并取得确认，再移除标签和清理对应草稿。失败保留标签与恢复材料；关闭期间阻止或检测并发的标签／正文变化，旧队列不得在确认关闭后重新写入它。
4. **写队列：**发送时使用前一笔确认版本；每笔待确认请求保留相同 ID 和内容。回执必须对应相同协议、调用 ID、内容、epoch 和下一代数。`flush` 只因目标会话得到确认而成功，普通偏好写成功不能冒充会话写成功；不因冲突自动读取新版本覆盖别人。关闭期间到达的文件打开与转换按顺序等待，嵌套的同一操作沿用队列身份，避免自等待。

## 验收

真实进程分别验证：迟到旧会话、带待审修改的重命名与强制退出、重启恢复、成功后的关闭和迟到写入、同 ID 重放及不同内容拒绝、普通偏好独立写入。边界测试覆盖相同服务的多个页面、首次迁移、缺版本旧客户端、损坏资料、版本上限、写入／同步前后故障和响应丢失。

前端验证恢复被用户操作打断、错误后未授予写资格、异步队列和关闭竞争、确认失败保留标签与草稿、单个及批量关闭、重命名前后持久化失败。最后用打包后的正式 CSP 页面与真实内核执行打开、审阅、改名、保存、关闭、重启及冲突；其他系统和旧内核混用仍单独列为未验或不受保护。
