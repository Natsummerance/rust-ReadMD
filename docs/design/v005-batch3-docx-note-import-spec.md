# Word 注释导入增量合同

第三批完整合同的内容完整性修复；不改变已冻结的 Windows MVP 验收范围。

1. 正文中的脚注、尾注按实际运行内的位置转成 Markdown 引用。重复引用共用定义；两类注释即使 Word ID 相同也不冲突。只导入正文实际引用的普通注释，不混入分隔线或已删除内容。
2. 遵循包内声明的关系定位注释及其图片、链接；支持非默认路径、包根绝对路径和命名空间别名，不访问外部注释部件或宿主文件。预览只暂存资源；保存才进入共享资源目录。
3. 注释复用正文的结构转换器，保留段落、列表、引用、表格、代码、链接、图片和可编辑 Office 公式，续段正确缩进在同一 Markdown 注释内。注释独有的数学样式和字体也参与上下文捕获。
4. 缺少定义或部件、重复 ID、无效关系、XML 损坏、命名空间伪装及不合规嵌套引用必须失败，不返回残缺的成功结果，不覆盖输入或既有输出。
   - 这些结构错误不能进入旧的有损转换回退；公共转换入口保留稳定错误码和本地化消息。
   - 字段和已接受移动内容中的引用保留，已删除／移出内容不导入；未知容器导致引用无法映射时明确失败，不输出孤立注释定义。
5. 验证实际原生入口：导入预览→编辑→显式保存→重开→再次导出 Word，并检查独立注释部件及资源。测试使用专用资料及正式 CSP。

Markdown 注释保存内容和稳定身份；Word 的自定义注释编号、混合脚注／尾注版式和任意节属性不在本增量中宣称无损，仍按完整出版模型和跨应用往返合同验收。再次导出遵循用户选定的现有脚注／尾注预设。ReadMD 自身的结构往返不能代替实际 Word／WPS／LibreOffice 认证。

依据：[Microsoft FootnoteReference](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.footnotereference?view=openxml-3.0.1)、锁定版本的 [quick-xml NsReader](https://docs.rs/quick-xml/0.42.0/quick_xml/reader/struct.NsReader.html)。不新增依赖，离线构建。
