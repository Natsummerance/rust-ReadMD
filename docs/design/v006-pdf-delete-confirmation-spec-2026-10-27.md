# V0.0.6 PDF：删页确认与关闭生命周期

## 范围和真实首败

合成的双页 PDF 经现有 PDFium 工作区打开。旧实现的删页确认在跨文档打开后仍保留；通过受控 DOM 事件触发该过期确认，会向新会话发送删除请求。打开新文档时新 PDF 层会挡住普通鼠标点击，因此这个复现不声称用户可以直接点击穿透遮挡层。首败报告保存在本机 `.cache/v006-pdf-delete-target/first-failure-controlled/report.json`。

另一个首败无需穿透遮挡：暂缓旧 PDF 的关闭请求期间，用户仍能点击旧页面上的删页按钮并确认，导致关闭在途时另发删除请求。正式 CSP 的真实浏览器按钮与本机 PDFium 工作进程复现，报告保存在 `.cache/v006-pdf-delete-target/closing-first-failure/report.json`。两份报告不包含用户文档或私人配置。

## 行为约定

- 删除确认绑定当前 PDF 会话、修订及页码；关闭工作区或开始其他操作时取消确认。取消后旧按钮回调不再生效，不能删除新文档或其他页。
- 关闭从第一个异步等待之前进入独占状态，普通编辑、页导航、图片选择、历史读取及重复关闭不能启动新操作。
- 对有修改的 PDF，取消关闭继续保留草稿；选择保存并关闭时仅由内部关闭流程启动保存。保存失败或关闭请求失败，保留会话和可见草稿，退出关闭状态以便重试。
- 再次点击关闭仍可取消当前工作任务；同一个取消请求在途时重复点击复用请求，不重复发起取消。任务取消和完成仍由既有工作进程协议决定。
- 对话框的可选取消信号只影响该次确认；预先取消的信号不会关闭其他确认，取消后移除监听器，默认无信号的调用保持原行为。

## 验证边界

单元测试覆盖会话、页面、修订和关闭中的确认过期，以及保存并关闭、重复关闭、取消信号和监听器清理。正式 CSP、无界面的 Edge 与真实 PDFium 使用隔离配置和合成 PDF，分别在 1160×820 和 1024×680 验证关闭请求挂起时的真实删页按钮、过期确认受控触发、正常删除／撤销、取消关闭、保存并关闭及新进程重开。测试通过不等于全部 PDF 对象、字体、签名、扫描材料和原生可见窗口已完成验收。
