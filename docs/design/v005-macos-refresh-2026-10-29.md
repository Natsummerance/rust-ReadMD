# V0.0.5 macOS 修复边界与发布约束

本轮从正式 V0.0.5 的 `3cbb7a39ad889a2a485105acb4950a6cee995649` 分出修复线。V0.0.6 迁移分支继续保留；不把尚在开发的业务功能作为 V0.0.5 替换包发布，也不移动原 V0.0.5 标签。

## 输入、成功条件与失败行为

- 输入为对应芯片的完整 `.app`、ZIP 和 DMG，使用锁定、离线编译的正式主程序、已核对的 V0.0.5 桌宠资源和固定版本的 Mac SVG 引擎。
- `.app` 必须先签内层 Mach-O，再更新受管引擎的字节清单，最后封装并签外层资源。压缩的桌宠可执行文件必须在清单重算前签署。复制安装或压缩往返后，真实 `codesign --verify --deep --strict` 仍须通过。
- 用户选择免费 ad-hoc 签名。默认 Gatekeeper 首次拒绝是明确的分发限制；安装说明只使用 Apple 的逐应用“仍要打开”流程。不能把该签名称为 Developer ID、Apple 公证或默认免提示安装。
- 原生工作流检查真实 Cocoa WKWebView 中的中文路径、编码/BOM/换行、可见编辑首屏、修改/撤销/重做、保存、关闭、重开、会话恢复、空会话主页，以及真实外部修订冲突后的取消、保留正文和草稿检查点。
- 原生工作流驱动仅在 `native-qa` 加 `debug_assertions` 下编译，不进入正式构建。正式 ZIP/DMG 另做签名、完整资源、受管引擎最小输出和实际原生冷启动；两类候选分别记录摘要。
- 保留正式 CSP 和真实 token 鉴权。启动就绪不能仅凭空页 `readyState=complete`；必须等生产正文脚本和宿主桥接就绪。测试不得以浏览器/headless 结果代替原生窗口。

## 依赖与平台边界

SVG 引擎继续使用已审查的 resvg 0.48.1。Mac 原版资产、源码归档、可执行架构、SHA-256、许可证和依赖通知分别固定，随程序离线提供；不用用户 PATH 上的程序代替。签名会改变字节，运行时清单必须绑定签名后的实际内容。

Apple Silicon 原生与 Intel/Rosetta 分开记录。Rosetta 通过不宣称实体 Intel Mac 通过；最低系统版本声明不宣称所有旧系统实测。实体 Intel、旧系统、实际键盘/输入法、首次人工 Gatekeeper 放行、文件关联、菜单栏/托盘和 AI 配置仍各自需要证据。V0.0.6 的非 Windows 多文件重命名保护继续保留，本轮不删除平台保护或加入不安全的普通 rename 替代。

## 仅替换 Mac 下载

`tools/refresh-macos-release.mjs` 只处理现有 V0.0.5 的四个 Mac 文件与合并后的 SHA256SUMS。发布前核对原标签、发布 ID、全部旧资产身份及摘要，要求修复源码已推送，并绑定实际验证过的四个包。

先完整上传并认证五个候选，才逐项更换正式名称。变更期间写持久回执；中途失败尝试恢复整组原名称，不删除未知对象或原下载。恢复无法确认时保留 `recovery_pending`，禁止盲目重放。最终下载、其他平台身份、原标签和说明全部复核后，才清理本轮已知的旧资产。GitHub 资产名称切换不是跨文件原子事务。

Windows/Linux/VS Code/MCP 文件与原标签不在替换范围。Mac 修复源码提交必须在发布说明中单独标明。GitHub 连接缺失时只能准备本地候选，不能声称推送、发布或删分支已经成功。

## 验证与清理

必须保留首次失败、修复原因、不同候选的源码/主程序/boot/安装包摘要，以及真实测试边界。既有原始字节断言不改预期摘要来适配平台。缺固定材料、缺生成物、既有基线失败和产品代码失败分别登记。

Rust 始终 `--locked --offline`；架构依赖在独立准备阶段取得。共用一个有预算的 Mac target，关闭 incremental。测试资料、用户配置、原始日志和凭据不入 Git。生成的临时目录显式放在当前工作区，结束后清理；离线输入和失败证据不按 cache 名称一并删除。
