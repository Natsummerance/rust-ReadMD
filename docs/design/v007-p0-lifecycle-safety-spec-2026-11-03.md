# V7-00：决策目标与恢复保护

本规格补充生命周期矩阵 LC08／10／11，先于资源另存、容量和安装扩展。开发已获本次用户授权，版本发布仍需另行指令。

输入是两个不同身份的文档、已保存正文、未保存修改，以及可控制返回时机的真实服务请求。独立预期同时检查正文原件字节、当前编辑内容、恢复正文和新进程页面集合；按钮状态不能代替持久结果。

关闭、编辑退出、主页、批量关闭、切页和真正退出使用单一前端操作所有者。等待确认或后端回执时，第二个破坏性操作明确取消，系统打开与导入依序排队。操作所有者直至整个流程结束才释放，不能在确认框隐藏时提前解除。内部保存冲突重载等必要子操作持有明确的本地所有者令牌，不与外部导航混排；令牌不参与后端授权。

确认绑定具体页面对象、路径、修订、编辑 generation 与 Rust 审阅身份／generation。修改后撤销到同样文字也使旧确认失效。保留精确字节的既有编辑器实现，通过入口适配器接入操作边界；不改变受保护源码摘要。后台保存仍走现有 Rust 保存服务，不复制业务写入。

丢弃前先持久保留原修改；每次异步等待后复核目标与 generation，Rust 审阅丢弃也使用预期审阅头。清理通用草稿必须带原正文和时间界限，不能无条件删除另一个写入者新增的草稿。清理等待期间出现新输入时保留编辑状态和新正文。

缺失未保存正文时保留可见的恢复失败页面，禁止空编辑、空另存和空导出。权威会话保留原 descriptor，不能由缺失后的局部视图改写。重试使用原身份和已有会话版本约束；恢复正文出现后，新进程能继续恢复。放弃丢失恢复记录必须有明确的用户决定和持久回执，不能把普通关闭当作隐式放弃。

旧实现把缺失草稿后的整个会话设为不可写。新实现只有在 Rust 明确声明 `recovery_guards` 能力时，才允许带 `preserved_tabs` 的受限 CAS：旧持久状态与拟提交状态必须各有且仅有一个完全相同的原始 descriptor。缺失页面不可普通关闭；其他页面可保存、关闭，应用可真正退出，原记录继续完整保留。保护约束参加幂等指纹；同一 call_id 不能换约束重放。旧后端没有该能力时继续拒绝写入，不进行兼容性降级。

测试保留正式 CSP、真实鉴权与实际文件。服务延迟只阻挡原请求，不伪造成功响应。Native QA 仅用专用数据目录，不修改日常 App 或现有用户文档，不加载模型。先保留旧代码首次失败，再绑定新源码／boot／二进制与原生结果。
