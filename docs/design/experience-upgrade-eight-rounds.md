# ReadMD 八轮修订方案实施记录

本文件配合 `capability-upgrade-acceptance.json` 使用。R001–R057 保留，新增 R058–R072 承接八轮讨论确定的要求。用户后续已确认集成到 V0.0.5 并正式发布；目前尚未发布。以下是实施记录，不是全量验收声明。最新剩余清单与执行顺序见 [V0.0.5 未完成清单](v005-remaining-work.md)。

## 固定约定

- 数学标准语义使用可读 DSL，默认在渲染结果中填槽。原始 XML、编译缓存进入后端状态；未知扩展的保留不计为可编辑支持。
- AI 修改直接进入当前工作正文；保存、审阅和任务运行分别管理。保存不会接受修改，未审阅原文不能按普通缓存淘汰。
- 导出有待审修改时询问“全部同意并导出”；绑定本次快照，失败或取消保留待审状态。
- 首次 AI 请求优先选区，否则全文；追问沿用目标，新选区、切页和新对话更新后续目标。读取工作区和修改文档的权限分别管理。
- 多轮任务绑定原文档。切页、关闭侧栏、收到托盘继续；关闭任务文档和真正退出保留检查点并停止；重启等待用户继续。连续段默认 64 轮、30 分钟。
- 外部文档先阅读原排版，再明确选择提取或 PDF 编辑。论文按需启用实际引擎分页，不能用 PDF 预览认证 Word 排版。
- 图片简单操作就地完成，复杂操作进入临时专注画布。默认仅修改当前引用，本地手工、AI 和 MCP 共用 Rust 图像工具。
- 默认界面不新增场景工作台。顶栏左侧全局操作、阅读设置及禅模式；文档栏“更多”紧邻 AI。统一控件、44px、46 语言、RTL 和高 DPI。

## 第一工作段：资源与保存

发现的真实问题：EPUB 预览提前在源文件旁创建 `<文档名>.assets`；图片插入和粘贴也会提前写入相邻 `images` 目录。保存资源时原实现使用字符串全局替换，并会跳过缺失资源继续写入正文。

当前改动：

1. `document_assets` 为同步格式适配器提供请求隔离的暂存作用域，图片进入集中 `resource-staging`；桌面、批量和 MCP 转换复用。
2. 转换响应携带 `AssetHandle`，虚拟文档、图片插入、粘贴和保存快照传递这些依赖。过期粘贴结果不能写入另一文档。
3. 明确保存时仅物化实际 Markdown 图片引用，写入资料夹共享 `readmd-assets`。名称保留用途和内容摘要，相同内容跨文档复用，已有文件不覆盖。
4. 图片路径只在解析出的图片节点中改写；同样的字符串出现在正文或代码示例中不会被全局替换。
5. 资源失败阻止正文提交；正文保存失败或冲突时清理本次新建资源，已有共享资源保持原样。
6. 另存为成功后明确登记后续保存授权，不依赖偶然的文件重载。

资源路径回写同时提供精确的 UTF-16 编辑，不破坏保存前的撤销历史；引用式图片的可选标题已保留，资源索引按目录建立，避免逐图片重复遍历。

保留的兼容边界：底层旧转换函数及旧 `/api/image/save` 非暂存调用仍保留旧合同；新版桌面流程使用暂存调用。未知 HTML 图片、移动/打包依赖、集中资源清理和容量策略尚未完整验收，R058 保持进行中。

## 第二工作段：日常交互

已调整全局操作位置、阅读设置和禅模式入口，移除重复字号按钮，修正禅模式正文预留高度。PDF 页等待实际图片解码；导出分页请求清除旧页面并显示统一加载状态。演讲读取当前编辑稿，加载期间隐藏旧 iframe，等待演讲引擎、字体、图片和布局就绪后显示；关闭和后续请求使迟到结果失效。

已增加窄窗口、RTL、44px 目标的自动验证和 Windows 原生画面检查。阅读统计、默认提示标题随语言切换更新，作者自己的标题保持原文。演讲加载失败与超时有重试入口，生成标识阻止旧 iframe 的迟到事件替换新请求。

原生复测发现并修复启动语言竞态：交互式窗口先于偏好加载就绪，迟到的中文初始化可能覆盖用户新选择的词库。初始化及手动切换现在检查语言请求代次，旧请求不能更新词库、方向、存储或派发变更；启动偏好提供独立就绪 Promise，原生验收不再把壳层可见当成全部偏好就绪。

这一段仍需完成全部触控/高 DPI/长文本组合、演讲长内容分页与备注、打印解码完整故障矩阵。

## 第三工作段：可读公式链路

`math_dsl` 接入统一 `MathDocument`、HTTP 和 MCP，支持自然运算、19 类核心结构、标准命名属性与可读 `office.*`/`word.*` 形式。新公式默认 DSL；旧 LaTeX 保留原解释。编辑源范围使用 UTF-16，重复公式和分子、分母分别定位。常见属性修改保留源码注释及排版，复杂结构可能规范化，详见 `math-dsl-v1.md`。

正文与预览渲染 DSL，单击打开原位槽位编辑；源码中补全数学符号与常用结构。大量公式按视口排版，单个界面的后台公式编译请求并发上限为 4，相同请求合并。增量刷新按公式自身源码判断渲染是否过期，修改其他段落不再导致未完成公式空白。

后台排版队列在开始网络请求前检查公式是否仍存在；重复公式共享请求时保留仍在使用的对象。测试中的 40 个排版任务保留 4 个已启动请求，36 个过期排队任务没有发送。原生千公式材料触发 15 页智能分页，再切换全卷模式，验证首/中/尾公式、精确编辑、一次撤销、保存和重开；初次显示约 5 秒，后台同时请求不超过 4，槽位交互另有至多 1 个解析请求。该测试不是八小时稳定性或输入 P95 认证。

Windows 原生测试实际完成重复公式第二处分母修改、属性更新、撤销/重做、原子保存、重开以及 DOCX/EPUB/PDF 文件输出。还修复了两个视觉检查发现的问题：MathML 扫描重复排版读屏树导致 SVG 互相拦截点击；PDF 行内对象未向后续文字保留宽度导致重叠。新的 PDF 输出已重新打开并视觉检查。

这些流程不等于全 OMML 认证：所有标准属性/枚举和任意嵌套的完整可编辑覆盖、Word 关联信息验证、保真扩展、旧文档迁移、独立公式草稿的持久恢复、离开自动提交和辅助技术仍列在 R059 的剩余工作中。

PDF 原生画面确认行内公式和后续文字已不再重叠。另发现 GFM 提示块在该导出链路仍显示原始 `[!NOTE]` 标记；提示块类型和版式的一致输出继续列为跨预览/导出差距，不能计为 GFM 完整覆盖。

2026-10-08 后续快速优化：上述提示块原始标记问题已修复，真实 PDF 和原生 PDFium 画面已确认中文类型标题、边线及正文。同步完成 AI 自动选区与有效公式离开应用，详见 [本批实施记录](../reviews/readmd-v005-quick-ux-2026-10-08.md)。复杂嵌套 GFM、无效公式草稿持久恢复及完整正文审阅继续保留为未完成项。

## 实测边界

本机只有 Windows。已使用用户授权的哲学 EPUB/PDF 副本在正式 CSP 的原生 WebView 中验证，原始书籍只读并在结束后核对摘要。私有路径、书名和正文不写入测试报告。

其他平台原生运行、实际 Word 往返、全 OMML DSL 语义、共享正文审阅、多轮 Harness、专业图像/绘画以及剩余八类生产场景继续按账本推进。八小时压力、百万字等目标材料以及 P95/内存退化指标必须以实际运行证据登记，不能由当前通过的局部测试推断。
