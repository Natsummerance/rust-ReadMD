# 第三批：原生公式默认属性与真实分页墨迹

2026-10-24 实施与验收规格。接续 C68 的有限字符样式来源及既有出版参数。**实现、纯控制和实际验收分开记录；本文件不提前认证 M07、P04 或第三批完成。**

## 公式默认属性

既有 Word 公式包含原生段落／字符链时，只有来源与实际目标模板相容，才能保留继承。不能通过写入更多 direct 属性、改动 Normal 或修改全局模板宣称原生无损。

- 显式 `rPrDefault` 比较完整、命名空间规范化的树，包含 wrapper、稀疏属性及省略／显式默认值。四轴 b/i/sz/RGB 相同不足以证明完整字体、语言或复杂文字字号相同。
- 在真实源与目标级联中比较有效属性；保留原来的稀疏 direct 声明，不能把值相同视为原本就是继承。
- 只复用目标已经存在且完整相容的默认字符链，不捏造 default=true 或新的 rStyle。Missing／Empty 保持已有四轴准入合同，不扩大成任意全局属性支持。
- 无法证明的主题、未知依赖及相冲突全局值准确物化并警告；保留原来源，不能删除检查以凑通过。
- 实际矩阵使用应用真实支持的正文预设 Arial。源中原有 direct STIX Two Math 仍保留，首式删除真实 direct rFonts 后继承实际 Arial；原本缺省的语言／szCs 不伪称已删除。
- 后两式为测试显式添加的语言／szCs 遮盖要逐操作记录，不能冒充原始输入。当前 DOCX 默认属性修改仅改 styles 成员，再重新导入、保存、导出；校验继承者变化、direct 遮盖不变。

验收包括六种真实输入、四个相容家族的两代导出与新进程重开、三项当前默认值修改、两种旧 Missing 来源回归及普通正文／裸公式隔离。独立 ZIP/XML 检查器核完整默认树、数学结构、链路、direct 稀疏及实际有效值；三式 SVG 与完整 Rust／Typst PDF 对比真实 direct-effective 控制。当前默认修改与旧 Missing 组只在第三进程保存／导出，不声称额外新进程重开。

C69 首次实际失败必须保留：测试预设选 STIX 正文字体，但当前导出字体集合将其回退为 Microsoft YaHei，因此完整源／目标默认值不同，拒绝原生保留正确。修正材料使用合法字体，不修改原失败、不放宽检查、不把预设回显当作已被导出消费。

## Typst 普通正文非零基线

沿现有局部格式和导出控件开放 Typst，新增来源与实际墨迹资格；不加常驻界面。普通顶层段落支持全局和局部的正、负、小数基线、零复位及删除覆盖；标题和保护对象不随普通正文移动。

1. 来源 wrapper 与真实 PDF 的 MCID／OBJR／ParentTree、页对象逐一绑定。跨页私有 witness 可能附着于后代真实 Link；规范 wrapper 必须是实际有 witness、且包含全部 attachment 的共同祖先，不能凭 URI、矩形或未被见证的公共祖先猜测。普通链接包含普通文字，重复 URI、跨行跨页及内部跳转按真实源身份核对。
2. 逐可见字体程序、CID/GID、轮廓、字号、advance、文字矩阵、CTM、透明度和实际路径检查。当前正向资格为水平、未旋转的 Type0／Identity-H／CIDFontType2／FontFile2 TrueType glyf；不把 CFF、Type3、未知过滤器／操作符或非矩形裁剪默认为安全。
3. Code／Math 使用独立、可清理的保护 witness。零 alpha 的数学命中区域没有墨迹；一旦可见，必须参与裁剪、纸边与碰撞检查，不能依据对象名称忽略。
4. 移动后的可见墨迹须在纸面与裁剪内，且不侵入相邻行、段和保护对象。测量框、链接 Rect 与 leading 不能代替实际墨迹。
5. 完整证明后清理所有内部映射，重新读取并核绘制内容，再只修改已经证明归属的真实链接矩形。每个可见链接 glyph 恰好由一个分片覆盖，拒绝重复、重叠分片及侵入非链接墨迹的矩形。无轮廓字符仍验证字体、CID/GID、advance 和源 MCID，但其逻辑宽度不当作可见点击墨迹；每个真实分片仍须有可见 glyph／path，空白分片不得据此放行。
6. 越界／碰撞返回有类型的 `pdfBaselineInk` 定位，含 block、页、真实页对象和 ink；失败不提交最终文件，已有输出逐字节保持。

正向材料覆盖 0、+3、−2.5、+3.25pt，默认／Multiple／Exact／AtLeast 行距，Strong、真实 Oblique、17／23pt 作者字号、保护对象及重复跨页链接。Consolas 组必须选择独立的实际斜体字体程序；不将默认 SC 的 Em 标签当作物理斜体证据。

独立验证器比较完整 PDF 的每个 glyph、字体程序、轮廓、所有路径与 4 倍渲染的全部像素。保留无轮廓空白字符的边界，不能据空白逻辑坐标宣称有可见墨迹。输出对象、对象流及 UTF-16 私有标记也须检查。

## 可见分页预览

真实 HTTP 预览必须与独立 MCP 导出的固定源码、资源、参数一致；检查来源修订、所有页的源映射及墨迹覆盖。首次 PNG 和后续 `{key,page}` 图片路由也要验证，不能仅校验 PNG 头或返回的 PDF。

来源定位必须包含实际字形的负侧承及保护对象。有限严格路径从已经验证的源身份和真实墨迹，按来源／实际页面聚合补充点击包络；不能靠固定 padding 或增大测试容差掩盖遗漏。保留已有命中顺序和真实链接矩形，不跨页合并，不发布 artifact 或私有 witness 身份。块级包络只表示定位范围，不冒充逐字精确选区。

Windows 当前页面位图来自 Windows.Data.Pdf；独立 PyMuPDF 比较须明确固定分辨率、尺寸和抗锯齿容差，且以空白、陈旧、错页和移位图片作负控制。不能把两渲染器差异变成任意放宽阈值，也不能把该 Windows 位图路径称为 PDFium 跨平台验收。

保留的 C72 原始响应在同一个9.6pt代码字形出现1个几何及2个颜色的局部栅格差异。有限校准保持1px主包络、2px fringe、8／32／192对比及64／128 RGB阈值；只允许每向至多0.1%的strong像素在2px内取得同样严格的匹配。几何和RGB主包络失败取并集计数，全部像素仍须匹配，不配准、不平均丢失墨迹。固定真实PDF／PNG与±2px整体移动、缺字、下伸部分、句点、细线、变亮、错色、超配额反控同步归档。该模型只认证实际有限材料，不证明任意相接微小符号的栅格完整性；完整字体、GID、轮廓和绘制内容检查仍独立保留。

WinRT的[DestinationWidth](https://learn.microsoft.com/en-us/uwp/api/windows.data.pdf.pdfpagerenderoptions.destinationwidth?view=winrt-26100)／[DestinationHeight](https://learn.microsoft.com/en-us/uwp/api/windows.data.pdf.pdfpagerenderoptions.destinationheight?view=winrt-26100)采用DIP。本机1600DIP请求得到2240物理像素与140%缩放相容，这只是本机观测；不把图像尺寸改为统一同比例缩放或搜索偏移来迁就比较。

## 完成与保留边界

同一最终候选须绑定离线锁定构建、完整 Rust 库测试、前端／工具测试、六项仓库门槛、真实通信和独立文件检查。保留首次失败、精确失败源码、正常 EOF、预设恢复及有界证据归档读回；不复制运行库，不清空共享缓存。

本单元不认证任意 Word 主题／样式包、自动默认字符链的真实外部应用、所有 OMML、完整 CSL 或全部出版参数。Word／WPS／LibreOffice／独立阅读器、其它系统原生证据、正式 TeX 材料、受控冷态、完整故障与八小时压力仍独立在账。后续优先 Windows 可执行的资源竞争／崩溃／取消矩阵，再推进有界复杂 CSL 与剩余实际参数；缺环境的认证不阻塞这些实现。
