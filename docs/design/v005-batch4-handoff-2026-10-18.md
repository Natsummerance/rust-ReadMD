# 第四批执行交接（2026-10-18）

这是实施路径，不是功能完成或发布证明。继承[第四批执行规格](v005-batch4-execution-spec.md)与[首条流程规格](v005-batch4-first-workflow-spec.md)；第三批完整验收及非 Windows 原生缺口保持独立，不用第四批覆盖掉旧账。

## 先交付一条完整流程

真实 AI 修改两个相同段落 A/B → 用户手改第三处 C → 同意 A → 保存 → 正常退出并重开 → 只撤回 B → 再保存重开，A 和 C 保留。正文、审阅决定与任务状态分别持久化，普通 Markdown 不混入审阅记录。

该流程先接最小真实 AI 工具桥：`read_document → propose_review`，固定授权范围、持久 call ID 和执行回执、退出暂停。现有 provider 的文本／用量事件不等于工具调用协议；先扩展适配事件和工具结果回传，不能用测试注入代替真实模型修改。该流程通过后才接固定导出快照和完整自动多轮任务。后续界面仍采用现有正文、侧栏、菜单和上下文操作，不增加独立场景工作台。

## 从第三批带入的四条约束

1. **继承不等于零。** 快照保存用户原始稀疏选项和解析后的有效选项，注明来源；不得把空输入转成零，也不得把显式零回退为默认值。重启和跨格式切换仍保留该区别。
2. **范围必须随修订证明。** 公式节点 ID、源码 hash 和 UTF-16 范围只证明当前公式；不能直接充当持久 ReviewChange 身份。正文改回同样文字也要推进 generation。
3. **保真数据是输入，不是权限。** 未知扩展、资源描述和外部修订必须有语法与预算检查，不能改写标准正文或绕过固定目标。直接 Rust API、HTTP、MCP 和桌面入口使用相同检查。
4. **输出能力逐路径声明。** 不支持的字段在资源加载和目标替换前返回可本地化错误；错误原文与恢复依据保留。字体、CSL、公式、图像及前置信息不能因普通正文样式而被扁平化处理。

## 先写的故障用例

保存和审阅：同 hash 不同 generation、surrogate 中点、重复段落、重叠手改、存储额度不足、迁移失败、人工队列未确认、文件外改、原子替换前后崩溃。

保存源码改写：资源物化与公式迁移各自返回精确、可组合的 edits；不能直接拿 `saved_edits` 的首尾大区间替换映射全部审阅块。每次系统改写记录前后 generation、UTF-16 范围及操作来源，并在回执中告诉前端只映射一次。专门验证 pending B 两侧各发生一次资源／公式改写，保存重开后撤回 B，A/C 和两侧新资源路径完整保留；不把夹在中间的未变块误判为人工接管。复用 `Materialized.edits`、`Migration.edits` 与 CRLF→CodeMirror LF 映射，冲突时保留原始依据。

导出和资源：prepare 后新增不相交 C、修改或撤回 D、图片字节被替换、资源缺失、目标锁、取消、输出已提交但决定未提交。只接受绑定快照中仍有效的修改；不能用 UI Promise 代替文件回执。

任务和协作：回执丢失后相同 call ID 重发、同 ID 不同参数、权限撤销、附件越界、断线重连、服务重启、个人撤销及预算耗尽。任务范围固定在原文档，关闭侧栏不取消，关闭任务文档停止并保留检查点。

每个失败用例同时检查旧目标字节、正文、审阅原文、事件数及临时产物。合成故障测试与真实 provider/native 成功路径分开报告。压力门槛和其他平台原生要求沿主规格，不提前标记通过。

## 复用项目的本轮复核

- 继续复用仓库已锁定的 SQLite/rusqlite。事务默认回滚、显式 commit 的边界适合持久审阅日志；文件原子替换仍须单独记录意图与回执，不能当成同一数据库事务。[官方 Transaction 文档](https://docs.rs/rusqlite/0.40.2/rusqlite/struct.Transaction.html)
- 继续复用已锁定 Yrs 0.28.0；StickyIndex 用于协作相对位置，UndoManager 按 origin 与 capture 窗口组织个人撤销。它不能代替 ReadMD 的持久审阅决定和文件回执。[UndoManager 文档](https://docs.rs/yrs/latest/yrs/undo/struct.UndoManager.html)、[StickyIndex 源码](https://docs.rs/crate/yrs/0.28.0/source/src/sticky_index.rs)
- Continue 仅作为工具注册与权限适配的设计参考。2026-10-18 重新读取其官方仓库，README 已明确不再积极维护并只读；因此不新增对它运行时或服务的依赖。未来若取源码，仍须固定 commit、逐文件许可与 NOTICE。[官方仓库](https://github.com/continuedev/continue)、[工具权限文档](https://github.com/continuedev/continue/blob/main/docs/cli/tool-permissions.mdx)
- CodeMirror 继续使用已有版本和事务能力；本次官网返回 403，未据此作新 API 兼容性断言。新实现以锁定依赖的实际类型／源码和测试为准。
- PDFium、FFmpeg、whisper.cpp 的资源路径、许可与包锁沿既有规格。当前交接没有下载组件、引入新依赖或冒充这些模块已经完成。

第四批首个可交付物是 B4.1–B4.3 的 A/B/C 可恢复审阅闭环。第三批完整 OMML、Word／阅读器互操作、复杂排版与跨平台未验项仍在独立清单，不能因开始第四批而销账。
