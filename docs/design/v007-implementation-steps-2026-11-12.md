## 11 月 19 日发布前联测范围

- **文件改名**。Mac、Linux 保留跨文件更新链接的保护。验证操作前解释限制，取消或拒绝后核对所有原件。普通文件操作单独回归。
- **实时共写**。从桌面分享一份 Markdown，编辑者通过邀请链接直接输入。两人在同一段的同一位置改动后应各自看见完整结果；断线重连保留双方输入，个人撤销只撤自己的输入，主持者显式保存才更改磁盘。角色降级必须阻止越权写入。
- **PDF**。覆盖现有入口的阅读、页面操作、批注和已支持表单的保存、撤销与重开。复杂表单编辑和更深的 PDF 对象编辑留作后续升级。
- **离线转写**。共用 FFmpeg、Whisper 和字幕输出逻辑。Mac ARM64 已有实际音频证据；Windows、Linux 集中验平台包、引擎启动和同一段短音频到字幕的结果。缺包的平台保留实际能力状态。

11 月 19 日在开发候选 `3c51fc55` 的真实 Rust 服务和无头 Chrome 桌面编辑页、来宾页重跑协作。7 组通过，包含同一位置并发输入中文、断线合并、个人撤销、磁盘保存和来宾页重开。离线媒体组包工具 11 项通过。三平台最终安装包仍待统一联测。

### 本轮验证

- 在 Mac ARM64 的真实编辑器页面和带鉴权的 Rust 服务中完成四个流程。最后一行删空后可从表头重新插行；在第二张重复表里移动、插入、删除后保存，重启服务，逐步撤销和重做三笔操作。复核 UTF-8 BOM、CRLF、行内格式、待审原文与位置。手上还有未应用的单元格输入时，结构操作按钮会等用户先处理输入。
- PPTX 定制排版现可设置 50%–100% 的表宽和表头加粗。布局阶段先应用字重再换行，预览与可编辑对象共用每一行的内容。三种宽度的原生表格回归通过；浏览器实际操作 50% 并关闭表头加粗，手写加粗仍保留。ibisOffice 排版后的两列文字起点间距从 426 pt 变成 213 pt。
- 毕业论文目录标题从正文样式派生，沿用一级标题字号、颜色和段距。原样张在 ibisOffice 目录页多出“目录 2”，只设置段落大纲级别的对照仍复现。修复后保留目录域和两条真实标题，页码均为 3，无自身条目。
- 本机 ibisOffice 0.8.6 分别排版三份 DOCX（实验报告 2 页、毕业论文 3 页、期刊稿 1 页）和四份 PPTX（各 2 页），核对测试表格文字、实际使用字体及字重。另取已发布的实验汇报样张，在原生界面另存、关闭、重开、全屏放映并翻页，副本与原件摘要一致。带实际编辑的再次保存、动画时长及其他 Office 应用仍待验。
- 同一开发候选的 Rust 定向回归共 76 项，前端定向回归 77 项，真实文件与表格导出安全检查 96 项。46 份语言文件通过结构检查。当前证据来自 Mac，Windows、Linux 继续按同候选复跑。75 项合同仍为 63 进行中、12 待办。

### 矩形表格与导出预览

- 在编辑栏打开表格并选中单元格，可以在右侧插列、删除当前列，或按这一列升降序排列正文行。数值按实际大小排列，文本按当前界面语言排列，空值始终在末尾；同值保持原序。排序保留原行的链接、强调、代码和转义。最后一列受保护。结构操作和应用、取消分行排列，在 390 和 1024 像素宽度保留 44 像素操作区域。
- 用两张同内容表格和独立待审段落走真实编辑器及 Rust 服务。连续七次修改后保存，重新启动进程逐步撤销、重做，核对每一步的正文、待审位置及 BOM/CRLF。审阅重叠和外部写入均阻止冲突操作。
- PPTX 网格表的表头色、文字色和隔行色同时作用于预览与可编辑表格。续页重复表头，拆行保持原行底色。三线表使用透明底。ibisOffice 0.8.6 排版的半宽样张两列文字相距 213 pt，表头及隔行填色分别为 `#164354` 和 `#26446C`，均为白字；手写加粗独立保留。
- 打开同一 EPUB 的全屏预览时复用已经载入的书页。用 48 章样稿实测，关闭并重开后停在同一处（640 px），切到 PPTX 时移除两处旧书页。预览命中还会比对标签页、文档身份、正文及审阅版本。

### 演示备注与本批验收

- 修复前，长备注经过自动分页，末尾段落会进入 PPTX 与 HTML 放映正文。用真实 HTTP 导出同一份输入，修复后在 PPTX 备注占位符找到了该段，ibisOffice 输出的放映页只呈现公开内容。离线打开导出的 Reveal 演示，备注保留在演讲者区域，代码示例中的尖括号和 & 按原文显示。
- 作者备注从单独一行的 `<!-- note -->` 开始。后面的自动标题和长段落都属于备注。需要继续投影正文时应使用明确的下一页或子页分隔。PPTX 的自动续页沿用作者备注，每个公式的源码只随含该公式图的页保存。
- 本批在 macOS 27.2 ARM64 上通过 98 项 Rust 定向测试、176 项前端测试、96 项真实文件与导出安全检查。八份测试产物通过 ibisOffice 0.8.6 排版检查。表格编辑和 EPUB 使用正式前端、严格 CSP、鉴权 Rust 服务和独立浏览器配置。Windows、Linux 实际运行，以及 ibisOffice 界面中编辑表格后另存再开，仍待验收。

### 合并、拆分与单元格属性

- 候选 `1b0b6818`。编辑表格时，选择左上格，再按住 Shift 选右下格，也可直接填跨行数和跨列数。可以从合并范围内任一格拆分。富文本格保留原始 Markdown，合并时按行展示各格内容。拆分保留每格原有的对齐设置，支持继续排序、增删行列。
- Mac 原生 ReadMD 用两张相同表格验证定位、磁盘保存、退出重开、菜单撤销和重做。Windows、Linux 各用本机 Rust 进程及浏览器操作编辑器并核对磁盘。三平台的同一流程覆盖六次撤销、六次重做和 BOM/CRLF 恢复。[跨平台运行](https://github.com/Natsummerance/rust-ReadMD/actions/runs/44297063820)
- 在 Mac 的 ibisOffice 0.8.6 中分别修改 DOCX、PPTX 合并格内的一段，另存、关闭并重开。两份样张均为一页，四段顺序、右下对齐、原格线和独立的右列均保留。DOCX 英文样张声明微软雅黑，ibisOffice 使用 Times New Roman；PPTX 使用 Arial。
- HTML、EPUB 和 PPTX 预览使用真实跨度。ReadMD 生成的 Typst 源经 0.15.1 编译，网格、三线表各生成一页 PDF，并用 PDFKit 核对文字位置。在该候选中，默认 Rust PDF 及其 PNG 路径、TeX 和 HTML 演示遇到合并或单格属性时会返回明确错误并保护目标文件。合同 R019 继续进行中。[本轮验收记录](../reviews/readmd-v007-table-geometry-2026-11-18.json)

### 默认 PDF 与 PNG 的跨页表格

- 候选 `7f6ae01f` 在 macOS ARM64、Windows x64 和 Linux x64 通过。用两组模拟实验共 42 条浓度记录及置信区间导出 A5 科研三线表，三平台都排成 3 页，每页分别有 10、17、15 条数据。两组合并说明各跨两页，续页重复表头，脚注链接指向定义。三线和单元格文字位置均已逐页测量。[科研样张](../../tests/fixtures/table-geometry/research.md)
- 用 32 行纵向合并格核对 64 行文字只出现一次且保持顺序，短行高 26.85 pt，多行格高 115.95 pt。另对普通长表和双轴合并网格检查页底收线及内外边线。在每个平台独立解码 PNG，核对分图中的字迹与线条位置，逐像素比对长图与分图各页的裁切区域。[定向验收记录](../reviews/readmd-v007-pdf-table-geometry-2026-11-18.json)
- 三种格式均验证取消快照、目标文件已有内容、表头非法跨入正文时的写入保护；两种 PNG 另验真实 129 页布局超预算后的清理。Linux 以锁定的 PDFium 包实装、重启服务，再执行预览和导出。三个系统均完成编辑后保存、重开和撤销重做的浏览器回归。R019 仍在进行中。[Windows 与 Linux 运行](https://github.com/Natsummerance/rust-ReadMD/actions/runs/44303233653)
