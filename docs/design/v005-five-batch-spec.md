## 第二批可执行合同

### 用户流程

1. 打开 Markdown 并编辑渲染公式；记录当前文档身份、正文摘要及公式精确 UTF-16 范围。
2. 有效输入按第一批规则应用为一次正文事务。尚未完成或无效输入单独保存，不标记正文被修改。
3. 切页、退出编辑、预览重建前保留当前草稿；回到同一文档的编辑预览时，精确恢复原公式、属性及尚未应用的槽位输入。
4. 正常退出前等待集中恢复写入；重新启动可恢复草稿。异常退出只承诺已收到持久化确认的输入，测试必须等待确认后终止自有测试进程。
5. Ctrl+S 先尝试应用有效公式。无效输入保留为独立草稿，保存当前已应用正文，并在现有状态位置显示草稿仍保留；保存不等于应用或删除无效公式。
6. Esc/公式取消为明确放弃该公式草稿；成功应用后清理对应记录。其他公式及正文历史不受影响。
7. 外部编辑或正文修订不匹配时不自动恢复到正文；通过现有“恢复与版本历史”打开可读的公式恢复副本，保留原稿，不把内部 JSON/XML 展示给用户。

### 数据与服务合同

复用 `/api/documents/history` 和 Rust 压缩原子写入，增加内部 `math_draft` 记录类型。普通正文仍只保存为 `.md`，不写入公式草稿、机器状态或新旁文件。

草稿格式 `schema: 1`：文档正文 SHA-256、公式起止位置及原始公式、DSL/LaTeX 类型、最后有效源码/必要内部模型、选中节点、未应用输入及选择位置。不能保存整个正文副本。最大单条 512 KiB、每文档最多 32 条；受集中存储总额约束。未应用公式不按普通 30 天历史自动淘汰；配额不足拒绝新增并保留旧记录。

记录写入与删除通过同一串行队列，旧异步写入不能在成功应用或明确取消后复活草稿。保存正文的 `clear_draft` 不能删除 `math_draft`。恢复前必须同时核对正文摘要、公式范围和原公式；不按全文第一次字符串匹配恢复。

前端沿用现有状态、恢复历史和公式上下文，不新增常驻工具栏。复用已有翻译词条；新文案如不可避免，必须通过现有翻译维护流程同步所有语言，不能补英文冒充翻译。
