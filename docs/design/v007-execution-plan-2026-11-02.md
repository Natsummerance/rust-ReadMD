## 验收方法与资源纪律

每条先写输入、行为、失败方式、保存结果及独立预期，再调查现有模块与成熟组件；完成入口→真实后端→持久结果→重开→撤销/失败。一次可回退提交对应一个边界清楚的结果，保留首次失败。测试通过后才更新清单；计划排期不改变合同状态。

生命周期必须按三个时点核对完整页面身份集合：退出前、进程真正退出后、下一进程启动并稳定后。不能只看到最后页面减少，就断言恢复失败；要区分恢复读取、后续显式关闭、外部文件变化和测试环境输入。关闭回执允许记录有限的按钮／键盘／菜单／程序入口类别，不能记录正文、实际目录、密钥或任意按键，更不能把客户端的原因标签作为授权依据。

原生键鼠测试同一时刻只能有一个操作者。与其他会话、真人或模拟器操作并行时，先取得明确的桌面操作时段；发生焦点变化先停止并重查，不继续向未知窗口发送键盘事件。CLI、服务和纯计算验证可以继续。锁屏、焦点变化、缺少固定输入及真正代码失败分别记录，不降低鉴权、CSP、修订或原生验证要求来消除失败。

每个最终候选都绑定源码提交、index、boot、二进制和安装包摘要。前端补丁、资源 URL 或签名变化之后必须重新核对对应候选；旧包的成功不挪给新包。受保护源文件的精确字节保持原样，新增保护优先放在现有状态、审阅和业务边界，不能修改测试摘要把失败改成通过。

V7-00 的退出门槛是：没有静默丢失页面或正文、没有空正文假保存、没有被覆盖后永不完成的确认请求、没有旧候选冒充新候选的证据。矩阵中缺少原生或故障证据的项继续明确待验，不概括为“全部功能可用”。

性能目标继续待实测：输入 P95≤50ms、取消≤200ms、worker 停止≤2s、正常绘画 60fps、阅读启动/内存退化≤15%。先记录基线与测量条件，未选入本版的绘画目标不冒充已达标。

Rust 继续 `--locked --offline`、`CARGO_INCREMENTAL=0` 和单一共享 target。重型引擎/模型显式调用；至少保留用户要求的 10GiB 可用内存，不强停用户 LLM。资源不足就暂停本任务的重操作，先做不依赖模型的项目。工作区内暂存有归属和预算，用后清理，不按 cache 名称整树删除。
