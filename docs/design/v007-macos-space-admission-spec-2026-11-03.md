# Mac 安装容量准入切片

本切片只改变受管资源包的安装和旧包迁移，不调用 OCR、语音或 AI 模型，也不修改已有文档。沿用安装事务、资源锁和回滚实现。

## 输入与独立预期

- 已存在的真实安装父目录及经过现有锁文件校验的文件清单。以打开的目录调用 `fstatfs`，记录调用用户可用字节、分配单位、设备与文件系统身份；失败拒绝安装，不能回退为无检查。
- 按每个文件向上取整，计入目录、双份清单/事务日志、每文件元数据和 32 MiB 余量。已有下载与旧包已计入系统占用，不再次从可用字节扣除；新暂存必须完整计入额外峰值。32 MiB 是保守预算，不是所有文件系统的上界证明。
- Mac 的所有当前客户端，在各自 profile 资源锁之外共用一个每用户安装写入门。APFS 不同卷可能共享容器空间，因此保守串行同一用户的全部受管安装，而不是只按卷号分组。普通阅读和资源使用不持有此门。争用立即返回原有 busy 回执，取消不需要等待一个长阻塞锁。
- 协调文件位于用户应用支持目录的固定私有子目录；不依赖 `READMD_DATA_DIR`。专用测试通过 Mac 原生测试使用的 `CFFIXED_USER_HOME` 选择工作区内的同一用户命名空间，两个 profile 仍使用同一门。空锁文件保持稳定且不删除，进程退出释放锁。
- 安装提交前复核目录与卷身份、协调门的文件及目录身份。符号链接、被替换的目录、非空/多链接/他人所有的协调文件都拒绝，不修理或删除不明对象。

## 故障验证

1. 实际 Mac 查询与独立 `statfs`/系统容量结果一致，分配单位采用 `f_bsize`，不能把 `f_iosize` 当作分配单位。
2. 两个独立进程、不同 profile 争用同一协调根：第二个在创建 payload 前拒绝；首进程终止后再次安装可取得门。资源读租约保持独立。
3. 更换安装目录、链接替换及更换协调文件后，旧回执不能继续提交；原目录、旧包、外部占位保持原样。
4. 容量不足、查询失败、取消与受控小卷 ENOSPC 分别验证。容量是时点观察，外部程序仍可消耗空间；最终写入失败必须沿用现有事务的原件保护，不声称排除了全部外部竞态或真实断电。

Apple 的 [statfs 文档](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/statfs.2.html)区分基本块、最优传输大小和普通用户可用块；[APFS 文档](https://support.apple.com/en-asia/guide/security/seca6147599e/web)说明容器内共享空间。[flock 文档](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/flock.2.html)只保证配合该协议的进程互斥，不能用于声称多文件重命名已能抵挡任意外部写入。
