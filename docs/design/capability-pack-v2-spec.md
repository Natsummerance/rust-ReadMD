# 大型离线能力包：实施合同

状态：流式格式已接入统一安装、真实引擎探测、取消和原子提交；原生离线导入、在用保护及浏览器 141 MB 分块安装已完成 Windows 实测。现有 JSON v1 四包保持兼容。TeX 大包目录、极限容量及完整故障矩阵仍待完成。本合同属于 R003/R030/R075 的交付链路，不能据此标记整体功能已交付。

## 用户流程

继续复用功能内的安装提示及插件管理，不新增工作台。用户看到用途、下载大小、安装大小、峰值临时空间和许可证，选择安装并继续，或导入离线包。安装不写输入文档目录，不执行第三方安装脚本，不把宿主 PATH 上的工具当成管理资源。

准备、下载、安装、最小真实操作和提交分别记录状态。下载／解包阶段可取消；原子提交开始后明确显示正在完成。失败、损坏、空间不足或进程退出不得破坏旧版本或误报就绪。取消成功后不得稍后自动提交。安装器使用同一服务与目录，离线完整发行可直接携带同样的包。

## 格式与内存合同

新增二进制 v2，沿用 `.readmd-pack` 扩展。固定 magic `RMDPKG2\n`，后接小端 u32 清单长度、UTF-8 JSON 清单，再依清单顺序连接各文件的单成员 gzip 数据。每项固定相对路径、未压缩长度、压缩长度和 SHA-256；可选 `executable` 明确 Unix 可执行权限。路径只来自与应用锁逐值相等的清单，不从归档中的自由路径头提取。包内路径使用固定 ASCII 名称，不限制用户文档及资源的 Unicode 文件名。

应用内目录固定包版本、平台、整个包长度／摘要及清单摘要。清单至多 8 MiB、40,000 文件；下载至多 2 GiB，展开至多 4 GiB，单文件至多 256 MiB。文件数预算根据完整中文输入的 34,822 文件调整，清单／内存和空间上限不变；大清单保存为紧凑 JSON，避免格式化缩进使相同内容越过大小限制。实际清单必须满足更小的固定包预算。校验拒绝重复名称、大小写冲突、Windows 保留名、绝对路径、目录穿越、ADS、符号链接、重解析点及不属于清单的额外字节。

Rust 逐块处理下载、整体摘要、解压和逐文件摘要，工作缓冲不随整个包大小增长。每个压缩段必须精确结束，不接受拼接成员、压缩尾部或解压炸弹。不能把 500 MiB 运行库先读成 JSON/base64，或一次放进 HTTP 请求正文。v1 既有小包保持原上限。

原生离线选择直接读取选定文件；浏览器使用有界分块传输到集中暂存区。上传会话绑定配置身份和包 ID，检查 offset、长度、摘要和容量；重复块幂等，不允许重排拼接、跨会话读取或任意目标路径。会话取消、过期或退出恢复规则明确；临时内容不能被当作已安装文件执行。

## 生命周期与独立运行库

全部提取在应用能力目录下新建的临时根。只有所有文件核对、许可证材料存在、平台匹配及最小实际操作通过，才切换版本。失败保留旧版，未知用户文件不被递归删除。安装／修复／卸载与使用租约共用互斥规则，不能校验后被另一线程移除正在使用的引擎。

TeX 先完成中文宏包、对应源码及许可证，固定配置和字体，去掉更新器及任何自动下载行为。运行库在安装时完成公共只读 ACL 准备；每任务使用独立 OS 隔离、目录和截止时间。Windows 采用已实测 AppContainer／Job 入口；其他平台没有原生隔离及证据时不启用对应目录项。主程序不内置大型 TeX 树。

核心 Markdown、DOCX 生成、公式模型和必要小型运行库仍随应用提供。Office、WPS、LibreOffice 用于输出互操作验收，不是 DOCX 生成前提。已交付的小型资源包和核心能力不等待大型包才能使用。

## B3-52 工作暂存回收合同（部分实现，完整矩阵待验）

进程停止不等于工作暂存已回收。真实 Typst/OCR 崩溃矩阵已发现拥有者退出后留下任务文件和短目录引用；不能据此按 `readmd-*` 前缀递归清理。

MCP 渲染暂存集中管理，原目录仅用于最终原子提交。持久化任务身份、配置身份、已声明的工作根、创建时文件身份、资源/恢复引用及生命周期；不得从任意请求提供清理路径。活动任务以 OS 句柄租约保护，只有确认拥有者与工作进程停止、任务无恢复引用后才进入回收。使用期、取消后清理期与可恢复检查点分别记录；完整审阅与 TaskRecord 仍须接入同一合同。

回收逐项核对归属，不跟随符号链接或重解析点。短目录引用须匹配任务声明及实际目标，只移除引用本身；已替换、未知或混入用户文件的项保留并报告。没有可验证所有权的旧暂存保留，不能以兼容迁移之名删除。空间不足时停止创建新任务，必要原文和恢复依据不得作为普通缓存淘汰。

验收覆盖创建/启动/运行/停止/回收各边界的真实拥有者异常退出、独立任务保护、重启幂等、未知文件、长路径、文件锁、磁盘满和恢复引用。Windows Typst/OCR操作和安装探测、MCP单文件暂存现已接入持久归属、继承租约与下一启动回收；23项真实故障/恢复检查及完整内核回归通过，见[实现证据](../reviews/readmd-v005-batch3-task-workspaces-2026-10-11.md)。本合同的创建/启动边界、磁盘满/配额、TeX及全传输/平台仍未整体验收。

## 当前实现和复现

`rust/readmd-kernel/src/capability_archive.rs` 接受应用可信锁、输入流及集中暂存父目录，返回独立 `TempDir`，不返回已安装状态。64 KiB 缓冲处理正文、CRC 和逐文件 SHA-256，拒绝单成员后的尾部和重复 gzip；取消删除本次暂存，旧安装不受影响。五条专门测试覆盖 97 文件、37 字节碎片输入、危险路径／重名、截断／损坏／尾部／拼接成员、解压超额、预算及取消。

`node tools/build-stream-capability-pack.mjs MANIFEST RUNTIME OUTPUT` 只离线装配，先逐文件压缩计算长度，再逐文件重压缩写入完整包；两遍均核对输入长度和摘要。输出通过独占同目录硬链接提交，不替换已有归档。显式 `--write-lock` 用于维护者准备压缩长度，更新锁后还须完成独立审查。四条工具测试检查可复现性、锁不匹配、输入损坏、旧输出和路径保护。

真实跨语言探测使用已审查 Typst 原文件，`cargo run --manifest-path rust/Cargo.toml -p readmd-kernel --example capability_archive_probe --offline --locked --target-dir .cache/community-upgrade/build -- MANIFEST PACK EVIDENCE_PARENT`。它只用于格式证据，不能代替安装服务及 UI 验收。

统一服务现在直接读取文件流，解包后核对字节并执行真实引擎探测，才进入提交；下载不再把完整包重新读入内存。原生 `import` 与下载复用任务状态，解包／探测可取消，取消与提交共用同一锁。重复启动同一配置下同一引擎的任务返回原任务。状态区分 installed、ready、busy，避免把正在使用的资源当成缺失资源重复安装。

主清单为 v2 时，整个包长度、摘要及紧凑 JSON 清单摘要必须符合应用固定目录。已交付的 v1 资源也可以换成流式编码，但除压缩长度和受限的可执行标记外，身份、平台、版本、文件路径、长度、摘要及审查内容必须与 v1 锁逐值一致。这保持了 v1 原本允许 raw/gzip 重编码的信任边界，不允许借换格式引入新字节。自有仓库当前仍分发原来的四个 v1 包，未启用新的 v2 目录项。

PDF 会话持有整个会话生命周期的资源租约，Typst／OCR 持有实际操作期租约；取得租约与安装／卸载使用同一互斥锁。卸载先核对完整移除计划，暂移已知文件，遇到文件锁恢复此前移动的文件；未知嵌套文件保留原位置。准备目录检查符号链接和 Windows 重解析点；没有因此递归删除用户文件。

设置 `READMD_BIN` 后执行 `node ui-tests/capability-stream-native.cjs`，并用 `READMD_TYPST_STREAM_PACK` 指定真实流式 Typst 包，其他三包可通过 `READMD_PDF_PACK`、`READMD_OCR_PACK`、`READMD_FONTS_PACK` 指定。脚本使用真实 Windows 宿主、正式 CSP、隔离配置、System32-only PATH 和专用文档，验证安装继续、异步导入、取消、重复请求、坏包、修复、在用保护、junction 拒绝及重启。历史范围见[安装接线记录](../reviews/readmd-v005-batch3-stream-install-2026-10-10.md)，当前程序再次通过该 10 流程回归。

浏览器分块由 `capability_delivery/upload.rs` 管理，复用上述校验／探测／提交，不另建安装器。`POST /api/capabilities/packs` 的 `upload_start` 接收引擎、格式、总量及 UUID 请求标识，返回会话和私有令牌；`POST /api/capabilities/upload/chunk` 接收 job、offset、令牌、SHA-256 和最多 4 MiB 的二进制正文；`upload_finish` 验证完整接收后返回同一安装任务。原有状态和取消操作继续适用。私有令牌不出现在状态查询中。

会话绑定配置与引擎。重复块只确认，不追加；乱序、错长、错摘要、越权和不完整结束均拒绝。同配置最多四个上传安装任务、总压缩传输预留最多 2 GiB，解包／探测继续占用预留。它不是包含原有资源、解包及备份在内的完整磁盘上限。15 分钟无活动的上传过期；重启通过活跃文件锁和精确标记识别孤立暂存，只清理已知文件，不自动安装或复用未验证的包。用户重启后重新选择文件。

`ui-tests/prepare-capability-chunk-fixture.mjs` 离线制作保持原引擎字节的 141,000,444 字节合成容量包，`ui-tests/capability-chunk-native.cjs` 在正式 CSP 下通过六条真实流程，包括功能入口的大包上传、取消、整体摘要错误及重试、实际 PDF、重复结束和真实进程退出／重启清理。旧通用 JSON 单请求接口仍限 128 MiB；新 v2 通用导入及已知引擎功能导入使用分块。完整证据和测试工具限制见[分块记录](../reviews/readmd-v005-batch3-chunk-upload-2026-10-10.md)。测试用 v2 目录未发布，不能将其描述为 TeX 可安装、2 GiB 极限或全平台认证。


## B3-52 预留预算与公平恢复增量
