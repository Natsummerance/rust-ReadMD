# V0.0.7 P1 代码运行生命周期

本切片承接 V7-05，复用现有 `/api/code/run`、任务取消、文档修订和补偿历史，不重新建设代码工作台。未通过下述完整链路前，不标记 V7-05 或全部 P1 完成，不发布 V0.0.7。

## 输入、行为与独立预期

1. 运行前已取消：有效 SQL 和真实子进程命令均返回 `execution_cancelled`，不创建脚本或启动运行资源，不返回成功输出。
2. 运行中取消：固定的长递归聚合 SQL，以及仅等待后输出 `LATE` 的专用子进程。取消信号应在 200ms 内被观察，返回前完成该请求执行资源的回收；worker 停止目标为 2 秒。不得清理其他进程、用户模型或其他请求。
3. 超时：使用相同固定输入和独立期限。返回 `execution_timeout`，SQLite 不再留下后台查询；子进程及它持有管道的子孙不能继续运行。取消、超时、执行错误和成功保持不同状态。
4. HTTP/MCP：正式鉴权、已有确认闸门和请求预算保留；可取消请求使用现有 task ID，MCP 的外部取消传到同一执行实现。取消后不插入正文。重复 ID 不能让旧 worker 成为不可取消的执行者。
5. 固定目标：开始运行时绑定文档身份、内容修订、generation、代码围栏的 UTF-16 范围及预期原文。切页、编辑、移动围栏或切换编辑器后，旧结果不能写到当前文档或按重复字符串误匹配。
6. 成功结果：结果写入由 Rust 文档事务处理，显式插入构成一次撤销；保存、关闭、新进程重开、撤销及重做都保留正确内容与待审状态。运行成功不等于结果已插入或保存成功。
7. 环境：内置 SQLite 可实际就绪。其他语言检查真实最小操作，宿主 PATH 能找到程序不能作为受管就绪证据；未有锁定运行资源时明确限制，不宣称自包含。不得静默下载、加载模型或替用户安装解释器。

## 实施顺序与证据边界

先固定取消/超时首次失败，再修复执行生命周期，随后接入目标修订与结果事务。保留现有正常 SQL 渲染和语言兼容回归。Mac 本地共享 target 离线构建；Windows/Linux 使用各自原生 CI 的进程和 SQLite，不能用交叉编译结果代替。

SQL 优先复用锁定 rusqlite 对 SQLite 的 progress handler，直接在当前请求中运行和中断，避免超时返回后遗留脱离生命周期的线程。参考：[SQLite 查询进度回调](https://sqlite.org/c3ref/progress_handler.html)、[SQLite 中断语义](https://sqlite.org/c3ref/interrupt.html)。子进程以请求持有的专用进程组或系统对象管理，不能向宿主进程组发送信号。

内存 SQL 的 ATTACH/VACUUM INTO、目录 PRAGMA 与动态扩展不能成为读写外部文件的旁路；显式内存数据库仍可使用。MCP 的取消通知按已有协议不再回复原请求，使用后续请求和正常 EOF 等待 worker 的真实停止，不能把“没有响应”误判为运行故障。Mac 进程组只剩已退出成员时的 EPERM 必须由原生组成员状态确认，不得一概忽略。Unix 保留可等待的根进程至发出组信号，避免先回收 PID 后误伤复用同号的进程。

真实原生 UI、完整语言矩阵、受管运行资源和跨进程结果历史均须另取证；本规格不代表它们已经完成。

## 固定代码目标与正文提交

Rust 的现有审阅服务提供 `code_target` 与 `code_output`。前者按 Markdown 解析树的源行定位完整根级围栏，校验原代码，返回文档身份、generation、审阅修订、内容修订、节点标识及 UTF-16 范围。后者重算并核对全部目标字段，仅插入或替换该围栏紧邻的完整输出标记块，沿用持久编辑事务、幂等回执及撤销历史。取消在提交边界前生效；重放已提交调用只报告原回执，不重复执行代码或插入。正文保存仍由既有保存事务完成，保留编码、BOM、换行和外部修订保护。

固定输入包含两个完全相同的代码围栏、emoji、BOM/CRLF、独立待审原文和另一份相同正文的文档。独立预期是仅第二个围栏得到输出；一次撤销只移除这次输出；保存后实际新 HTTP/MCP 进程重开、撤销、重做仍保持独立待审原文。改后再撤销虽得到相同文本，旧 generation 的结果仍须拒绝。运行中切页只允许向原目标的持久草稿提交，不能自动保存另一页。

界面每张代码卡片归属一个文档，跨文档复用 DOM 时必须重新绑定，旧任务仅可更新其已分离的卡片。退出确认期间先保留代码输出写入，取消退出则释放；确认退出后取消执行并等待停止，再返回退出就绪。确认关闭标签时，持久关闭回执与移除界面之间同步标记取消，避免延迟输出重新写回已关闭页面。

本切片不放宽复杂容器围栏、损坏输出标记的保护，不将宿主 PATH 解释器当成受管运行资源。全部运行的预算与顺序、原生强制退出及宿主崩溃时的 Unix 子孙回收、完整语言矩阵继续单列验收，不能据单代码块链路通过标记 V7-05 完成。

浏览器历史验收使用物理 `KeyZ` / `KeyY` 并核对真实 Rust undo/redo 请求。Playwright 的字面字符区分大小写，物理按键和带 Shift 的小写字符不能混用，见[官方键盘规则](https://playwright.dev/docs/api/class-keyboard#keyboard-press)。保留远端首败的事件、页面及回执，修正测试输入后重新运行实际 Linux CI；本机用 `navigator.platform` 选择键位的测试必须写明模拟，不能计为 Windows/Linux 原生证据。

Mac 原生脚本可使用工作区内校验过的冻结资源目录，记录其 boot 和脚本摘要，再通过正常 LaunchServices 启动相同签名二进制。这样等待人工桌面时段期间，后续开发不会改变待验候选的资源。该目录仍通过既有工作区所有权和非符号链接检查，不绕过正式 CSP、鉴权或原生宿主。

## 原生内核正常退出

固定输入为实际 HTTP 启动的 Node 定时器（60 秒后才输出），仅使用专用 profile 和临时目录。观察到该请求的直接子进程及其独立进程组后，正常向专用内核发送 SIGTERM；独立预期是在退出返回前停止所拥有的代码执行，且两秒后该 worker 不再运行。首轮 Mac 实测违反此预期，已保留失败并按 PID、启动时间、精确命令及专用脚本字节核实后清理；初次测试误以为脚本直接位于临时目录的夹具失败也单独保留。

内核为代码请求及底层 SQL/子进程执行登记当前进程持有的取消状态。桌面/HTTP 宿主正常关闭的尾声同步关闭新增准入，取消现有执行，再有界等待它们完成资源回收；同时保留调用者原来的取消检查。这里只操作自身登记的执行，不扫描或停止宿主其他程序。停止未获确认时返回退出失败，不报告正常完成。真实宿主强杀或崩溃时的 Unix 子孙保护和持久任务恢复仍需独立实现、验证。MCP stdin EOF 的既有排空行为继续单列研究和验收，不把本次 HTTP 信号退出结果扩大到全部传输关闭情形。
