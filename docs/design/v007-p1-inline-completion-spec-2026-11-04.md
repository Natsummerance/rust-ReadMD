# V7-11：灰字补全的流、身份与停止

复用现有补全设置、Rust 模型路由、CodeMirror、正文事务和历史，不引入另一套编辑器。独立模型选择与速度优先路由保持；使用用户指定的当前远端连接做实际验证，不公开连接、模型偏好或凭据，不加载本机模型。本文件是输入与验收规格，不是整项通过记录。

## 输入与独立预期

1. 真实鉴权内核接收有 Unicode 的前后文；SSE 的每个建议和终帧绑定 task ID 及完整原始上下文摘要。旧 JSON 客户端可以不传这两个字段；传入的身份不能错误。非法请求与匿名尾斜杠别名不得到达提供商。
2. 使用真实延迟 socket 输入，灰字在提供商真正返回后渐进显示。累计快照替换而非拼接；收到本请求完整终帧才缓存成功。截断、坏 UTF-8、无效 JSON、错误身份、额度耗尽和未知结束原因都不能变成完成或缓存。
3. 灰字只在接受后进入正文。Tab 接受当时仍有效的可见建议，形成一次真实正文事务；保存、撤销、重做和新进程恢复核对实际文件。未接受部分、失败与取消不进入正文。选区、页面、编辑器、generation 或仅审阅 revision 变化后，旧请求都失效。IME 期间不显示或接受过期候选；浏览器合成 composition 事件和系统输入法分别记账。
4. Tab 接受流中已有的部分、Esc 取消、关闭下游、替换 task ID 及配置切换只取消该请求；两个取消请求不能在后台继续占用两个请求槽。取消响应目标 200ms，拥有的 socket／worker 停止目标两秒，分别实测。读不到的系统 DNS 结果不得在取消后发起晚连接。
5. 原有当前／固定模型单次尝试 20 秒，自动探索的非当前模型 8 秒，全程 30 秒且包括模型发现。兼容 JSON 重试共用原尝试期限；写下游和写缓存前后都检查期限。发现模型最多两秒。固定模型不得悄悄换成其他模型；自动失败最多尝试两个模型。

## 聊天模型的生成额度

实际远端首败中，128 token 上限在一条有用的补全结束前耗尽。只记录受控的额度、结束原因和字符数；真实响应正文及连接信息不进入公开证据。诊断用本机转发只改变额度，不构成新产品二进制直连通过。

聊天补全的 token 上限调整为 512，给计入输出额度的内部推理保留空间；真正 FIM／completion 协议保持 128。仍在第一个完整可用单元处停止，保留原有六行／1000 字符、传输／原始文本大小、两请求及时间限制。额度耗尽继续失败，不能把截断候选标成正常完成。请求预算有实际线上协议检查；额外推理字段不能进入灰字。

## 验证边界

先保留真实失败和 keyless 故障输入，再分别验证 HTTP、生产浏览器、指定远端及 Mac Cocoa；源文件、boot、内核与生成物绑定各自摘要。三平台 CI 与原生宿主分列；headless、DOM IME 或单一供应商不代替原生输入法、所有供应商或完整 V7-11 认证。P1/P2 全部完成前仍不发布 V0.0.7。
